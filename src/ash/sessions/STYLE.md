# Sessions 设计与样式

本文是 Sessions 的设计规范，适用于 `src/ash/sessions/**` 及其他目录中专供 Sessions 使用的界面；不继承 Workbench 的视觉规则。

修改 UI 时落实受影响的要求；本文不代表现有界面已全部符合规范，状态、权限和生命周期仍遵守所属模块契约。

## 样式边界

| 层级                     | 适用范围                                       | 样式依据                           |
| ------------------------ | ---------------------------------------------- | ---------------------------------- |
| IDE                      | 常规 Workbench 窗口、导航、编辑与工具界面      | IDE 规范与所属组件                 |
| Agent Window（Sessions） | 窗口框架、标题栏、页面导航、账户入口和通用界面 | 本文与 Sessions 所属组件           |
| 独立页面                 | Design 等页面的内容、工具和页面所属浮层        | 页面专属规则；未规定的部分采用本文 |

- 三层分别定义外观，共用控件或主题服务不要求共用样式。
- 页面规则只作用于页面拥有的组件，不能影响窗口框架、其他页面或 IDE。
- 样式归属按组件用途与拥有方判断，页面菜单挂在窗口根节点下仍属于页面。
- 切换页面不改变窗口皮肤，也不能残留上一页面的样式。
- 共享控件拥有结构、交互状态和生命周期，调用方通过外观变体、主题变量或专属样式标识选择外观。
- 单个页面的设计不得修改共享控件默认值或 IDE、Sessions 全局主题值。
- 窗口 CSS 限定到 `.ash-sessions-window`，页面 CSS 限定到页面组件或专属浮层。
- `browser/media/style.css` 拥有窗口字号、图标和共享控件外观；`browser/media/workbench.css` 拥有窗口及共享 Part 在 Sessions 中的布局。页面与组件 CSS 随所属组件放置。
- Workbench 及更低层 CSS 不引用 Sessions 的 class 或变量；共享控件提供通用外观入口，Sessions 在自身作用域选择取值。此依赖方向由 stylelint 检查。
- 只有多个页面确实需要的规则才进入 Sessions 通用样式；保留已有的页面差异。
- 页面专属外观仍须满足可访问性、键盘操作和生命周期要求。

## 工作与状态

- 当前会话内容与下一步操作占据主要注意力，导航、设置和执行细节降低强调程度。
- 待回应请求持续可见并说明要决定什么，后台进度保持克制，完成与失败保留明确结果。
- 新建会话、发送和当前状态位置稳定，条目整理动作可在悬停或键盘聚焦时出现。
- 等待、无内容、无搜索结果和加载失败分别说明原因与下一步，未提供的能力不显示可点击入口。
- 选中、键盘焦点、执行、待回应和禁用分别表达，状态不能只依赖颜色或透明度。
- 禁用控件说明不可用原因，状态徽标只表示真实待处理事项，不用装饰性圆点或持续闪烁。

## Session 与 Chat

Session 是工作上下文，Chat 是其中一段对话。

- 侧栏选择 Session，主区域呈现当前 Chat，Session 名称只在识别上下文的位置强调。
- 单 Chat 避免相邻标题重名，多 Chat 保留各自标题与关闭入口，Session 标题表达共同上下文。
- Chat 数量仅用于理解或切换多段对话，时间、模型和目录不得与标题争夺注意力。
- 关闭 Chat、归档 Session 和停止执行分别命名与反馈。

## 导航

Activity Bar 用于产品页面导航，顺序与入口位置稳定，页面内工具放在对应内容附近。

- 所有一级页面都保留可展开的全局侧栏。默认导航在展开的侧栏上部显示图标与名称，账户位于底部；收起时一起隐藏，标题栏始终保留展开入口。
- 侧栏开关只改变展开状态，不切换页面。展开状态与宽度由窗口统一记忆，切换页面继续沿用；页面内导航或资料区不能禁用全局导航。
- 窗口统一使用一套尺寸，不提供紧凑模式。默认使用贴边布局，侧栏与内容以细分隔线区分；显式选择的布局外观继续生效。

| 项目     | 尺寸      |
| -------- | --------- |
| 图标     | 16px      |
| 点击区域 | 36 × 36px |
| 按钮间距 | 8px       |
| 高亮圆角 | 8px       |

- 侧栏与横向导航均使用 16px 主图标。高亮覆盖点击区域，窄窗口调整布局而不单独缩小侧栏图标。
- 图标与文字在默认、悬停和选中时使用同一前景色；未选中背景透明，悬停轻量反馈，选中持续高亮且与悬停可区分。
- 单色线性图标在 16px 下统一使用 1.25px 设计线宽；品牌标志和图标中的必要实心细节保留其造型。
- 同一入口使用同一图形，图标按钮提供可翻译的名称、tooltip 和可访问名称。
- 页面选择使用 `aria-current="page"`，账户入口表达菜单展开状态。
- 账户与窗口操作单独分组，位置稳定。
- 标题栏的侧栏开关、后退、前进为同组操作，按钮之间的间距为 2px。
- 模式切换的外圈与图标保持静止，使用同一个选中滑块横向移动表示 Chat 与 Code 的切换；开启减少动态效果时立即定位，键盘焦点独立于选中状态。
- 模式切换复用 Base UI 的 `SegmentedControl`，采用 `icon` presentation；通用交互与样式边界遵循[分段切换规范](../../../docs/ui-styling-ownership.md#分段切换)，业务适配层只绑定当前模式与命令。

## 会话列表

| 项目           | 尺寸                 |
| -------------- | -------------------- |
| 单行条目高度   | 36px，与页面导航一致 |
| 两行条目高度   | 至少 64px            |
| 搜索与新建控件 | 至少 36px 高         |

- 标题是首要信息，第二行只放工作摘要、来源或状态，时间与计数降低强调程度。
- 内容增长时条目增高，保留状态、操作与文字可读性。
- 头像用于识别人、Agent 或工作来源，没有识别用途时省略。
- 顶部全局导航的“＋ New”新建会话并打开输入区，下方列表按 Pinned、Projects、Chats（Code 为 Recents）分组。大组的 chevron 紧跟标题文字之后，点击展开收起；没有内容的大组不显示。Chat 只保留大组，Code 的小组使用标题前的 folder / folder-open 表达展开状态，会话标题前显示图标。
- 选中使用连续轻量背景，错误与待回应有文字或形状辅助。
- 悬停辅助操作采用共享的[悬停叠层与渐变规范](../../../.agents/skills/design-philosophy/SKILL.md#hover-overlays)。
- 保留选择与滚动位置，后台更新不自动重排用户正在操作的条目。

## 对话与输入区

- 对话按消息、进展、待决定事项和结果组织，长工具输出提供摘要与展开，失败和待回应内容直接可见。
- 正文保持适合阅读的行宽，代码、表格和差异可加宽并处理溢出。
- 输入区使用独立表面、12px 圆角、浅灰边框和浅阴影，聚焦只强调输入区。
- Chat 与 Code 输入卡片在悬停或内部聚焦时使用灰色边框与加深的柔和阴影，两者都结束后回落。
- 输入卡片不叠加蓝色边框或外圈，输入光标与按钮键盘焦点保持清晰。
- Sessions 通过显式外观变体定义输入框的悬停、聚焦、阴影与过渡，Workbench 保留自己的外观。
- 输入区随内容增高，达到可用空间限制后内部滚动，空会话与已有对话保持一致的控件关系。
- 输入区不预留固定的大块空白。
- 附件与上下文靠近编辑内容，模型与模式为辅助操作，发送与执行中的停止明确可见，未发送草稿保留。
- 自动滚动只跟随正在查看末尾的用户，向上阅读时保留位置并提示新内容。
- 权限请求紧邻对应操作，写清对象、影响和选项。
- 窄窗口优先保留对话与输入区，侧栏有明确开关，多 Chat 保留活动上下文与切换方式。

## 图标与点击区域

| 角色                                                     | 图形尺寸                            |
| -------------------------------------------------------- | ----------------------------------- |
| 主图标：侧栏与横向导航、标题栏、模式切换、输入区主要操作 | 16px                                |
| 菜单、列表行内操作、正文操作、附件与资源条目             | 16px                                |
| 行内元数据、状态与辅助标识                               | 12px；有 Compact 图形时使用对应版本 |

| 操作         | 最小点击区域        |
| ------------ | ------------------- |
| 普通工具动作 | 28 × 28px           |
| 触屏操作     | 44 × 44px，包含留白 |

图形与点击区域分别设置，头像与内容插图按内容角色设计。

`browser/media/style.css` 在 `.ash-sessions-window` 中定义 16px 默认图标尺寸；组件显式声明的 12px 辅助图标继续生效。尺寸变更仅作用于 Agent Window，不修改共享默认值或 IDE 图标尺寸。

IDE 与 Agent Window 共用图标注册、主题解析和 WOFF2 渲染机制，各自拥有视觉样式。IDE 保持原 SVG 的字形、字重与线宽；字体格式迁移不改变其外观。Agent Window 的可变字重、线宽及选中态调整只在 Sessions 作用域内生效，不修改共享默认值或影响 IDE。Agent Window 中的 Code 页面仍遵循 Sessions 样式，独立 IDE 窗口遵循 Workbench 样式。

## 字体与留白

| 角色                                           | 字号 | 字重                |
| ---------------------------------------------- | ---- | ------------------- |
| 页面标题                                       | 18px | 600                 |
| 空状态主标题，仅独立引导时使用                 | 26px | 600                 |
| 普通文字、会话标题、正文、输入、导航与控件标签 | 14px | 400；强调标题用 600 |
| 元数据                                         | 11px | 400                 |
| 徽标计数                                       | 10px | 400                 |

- Sessions 在窗口根节点集中定义自己的字号角色，共享控件继承所在窗口的字号；IDE 使用独立的 Workbench 字号，Sessions 中的 Code 页面仍使用 Sessions 尺度。
- 输入文字在 Sessions 中默认为 14px，用户显式设置的输入字号继续生效；代码、终端和画布内容遵守所属内容的字号设置。
- 正文行高至少 1.4，长段落用 1.5，放大与缩放保留内容和操作。
- 间距使用 0、2、4、6、8、10、12、16、20、24、28、32、36、40px。
- 控件内部常用 4–8px，相关内容之间 8–12px，区块之间 16–24px，窗口布局与测量尺寸按实际约束计算。
- 使用已注册且符合本文尺度的 token，缺少时在所属位置注册。

## 圆角与边界

| 表面                                                                                   | 圆角 |
| -------------------------------------------------------------------------------------- | ---- |
| 标签                                                                                   | 4px  |
| 小型输入控件                                                                           | 6px  |
| 普通按钮（含文字、图标和标题栏操作）、普通导航、搜索框、项目表单输入控件、普通会话条目 | 8px  |
| 对话输入区、独立浮层                                                                   | 12px |
| 圆形发送／录音按钮、有身份含义的头像、胶囊                                             | 全圆 |

- 圆角按组件角色与大小选择，同类组件一致，不按浮起程度推导。
- 弹窗标题与关闭按钮放在同一个 28px 高的 header 中垂直居中；长标题省略并保留完整 tooltip 与可访问名称。
- 普通按钮使用 `--ash-cornerRadius-large`；Sessions 通过 `--ash-button-border-radius` 设置共享按钮的默认圆角，页面自有按钮遵循同一尺度。
- 通用按钮外观集中在 `browser/media/style.css`，仅作用于 Sessions 内的共享 `Button`。主按钮使用中性实心，次按钮使用透明背景与描边，低强调动作保持无底色；页面选择变体并拥有布局，独立页面可保留专属外观。
- 标准主、次按钮内边距为上下 4px、左右 8px；普通图标按钮至少 28px 宽。导航、标题栏、发送和页面专用工具保留所属组件的尺寸规则。
- 紧凑文字动作使用共享按钮的 `small` 尺寸，在 Sessions 内至少 28px 高，内边距为 2px / 8px；不在各页面重复定义尺寸、圆角、悬停、焦点和禁用样式。保留自定义内容的原生按钮复用共享按钮的样式变体。
- 普通边框与分隔线为 1px，焦点与状态标记以清晰可辨为准。
- 内部区块优先用留白分组，独立滚动或调整大小的区域可使用边界。

## 键帽与快捷键提示

- 复用共享 [`KeybindingLabel`](../base/browser/ui/keybindinglabel/keybindinglabel.ts) 的 `keycap` presentation，由共享组件拥有按键标签、DOM、可访问名称与释放链，不在页面内另造键帽组件。
- Agent Window 使用独立的轻量键帽外观，集中在 [`browser/media/style.css`](browser/media/style.css)，通过 `.ash-sessions-window` 内的主题变量和样式生效；不为匹配 Agent Window 修改共享组件默认外观或 IDE 主题值，不影响独立 IDE 窗口。

| 项目           | Agent Window 要求                                     |
| -------------- | ----------------------------------------------------- |
| 高度／最小宽度 | 20px／20px                                            |
| 内边距         | 上下 0、左右 4px                                      |
| 圆角           | 4px                                                   |
| 边框           | 四边统一 1px，使用 `--ash-border`                     |
| 背景           | 透明                                                  |
| 文字           | 继承控件标签字号，使用 `--ash-description-foreground` |
| 阴影           | 无阴影，不加深或加厚底边                              |

- 快捷键提示使用对应按键文字或符号，如 `Esc`、`↑`、`↓`、`↵`；独立按键分开显示，避免与操作图标混淆。紧凑符号的可访问名称保留完整键名。
- 浅色、深色与高对比度主题沿用各自的语义颜色，保持键名和边框可辨；页面只负责提示的文案、组合与布局。

## 颜色与动效

- 颜色使用所属层或页面的语义 token，区分页面、辅助区域、输入表面、选中、悬停与状态。
- 选中使用轻量背景，不能直接套用强调按钮背景。
- 浅色、深色与高对比度主题下状态清晰，高对比度使用明确轮廓。
- 卡片静置时轻，悬停或聚焦时柔和浮起，持续操作时稳定，离开后回落。
- 浮起只改变边框与阴影，尺寸、内容位置和点击区域保持稳定。
- 过渡短暂、连续且可中断，快速交互从当前外观继续，尊重减少动态效果设置。
- 动效用于说明变化或维持位置感，不用循环明暗、缩放或位移模拟呼吸。
- 悬停与聚焦可共用表面反馈，键盘焦点仍须清晰，进度结束后保留最终状态。

## 文案与可访问性

- 文案使用用户理解的动作与状态，英文用 sentence case，保留专有名称，文案、提示、错误和可访问名称接入所属端 NLS。
- 页面图标配名称提示，有空间的业务动作优先显示文字，删除、归档、关闭与停止使用明确动词。
- 所有操作可通过键盘完成，列表与导航按语义支持方向键，Tab 按逻辑顺序进入区域。
- 菜单与浮层关闭后恢复焦点，键盘焦点始终可见且与选中区分，鼠标交互不留下无意义的焦点装饰。
- 标题截断用省略号并提供完整 tooltip 与可访问名称，正文、权限请求和错误原因保留完整文本。
- 状态变化按紧急程度播报，流式输出不逐字打断用户。
- 新交互区域提供无障碍帮助，复杂内容提供可访问文本视图，并允许控制帮助提示播报。

## 修改与验证

- 规则随明确的产品设计决定更新，不为迁就现有实现反向改写，不记录逐次问题处理过程。
- 改动与评审写清所属层、目标组件、需要保留的页面差异及相关规则。
- UI 使用 Playwright 验证 Browser 与 Electron，通过 DOM、计算样式、焦点和可访问属性断言行为。
