# ash-call

通话控制、成员与状态类型由 [`ash-call-contract`](../call-contract/src/lib.rs) 定义。协议直接依赖该契约；本 crate 使用并导出同一份类型，负责授权、持久化与运行时。

- 持久化通话、成员角色和媒体房间代次。
- 频道通话使用稳定身份，由 `ash-collab` 的空间成员授权；owner/editor/viewer 映射为 owner/speaker/listener。并发发起共用同一通话，viewer 只能加入已有通话。独立通话继续使用自己的邀请和成员。
- 频道通话快照中的成员记录已经授予的媒体权限；每次授权和后台恢复重新读取频道成员，撤权或角色变化先更换媒体房间。频道通话禁止独立邀请及成员修改，删除频道会关闭关联通话。
- 使用房间成员凭据授权；SQLite 只保存凭据哈希。
- 处理邀请、移除、角色变更、结束和幂等重试。
- 权限变更先记录待执行状态，再由宿主更换 LiveKit 房间。
- 不依赖 UI、LiveKit SDK、设备驱动或模型执行。
- 持久化成员的发言设备；其他设备只听，切换设备会更换房间。
- `runtime` feature 提供协作服务客户端、本地进程管理、通话控制与权限换代后重入。
- 成员变化按修订号等待；通话状态通过宿主通知界面。
- 控制服务短暂失败时暂停音频并有界重试，重新授权后恢复；权限拒绝直接结束通话。
- 仅所有者和发言者可主动共享屏幕；停止、采集失败、重连和离开会清除共享状态，重连不自动恢复录屏。
- 离开可取消等待中的重入和授权重试，随后等待媒体与设备清理。
- 所有者可在通话的 `documents` 列表中关联或移除结构化文档，成员通过既有修订号通知接收列表变化。引用包含协作服务地址、房间、schema、content type 和标题，不包含正文或凭据。
- 文档访问仍由文档房间授权。打开共享文档会新建未命名工作副本，并要求单独的文档邀请令牌；取消关联或离开通话不撤销文档权限、不关闭正在编辑的文档，也不更换媒体房间。
- 旧通话记录默认没有文档引用。单人 AI 语音由 App Server 的 `voice` 路径装配并接入原 Chat 任务链；向任意多人通话邀请 AI 仍待实现，任务执行不归本 crate。

设计与验收范围见[协作媒体方案](../docs/design/collaboration-media.md)。

```sh
just test ash-call --features runtime
```
