# `ash-immutable-generation-store`

1. The store publishes immutable base generations and change-layer snapshots under a cross-process write lock. Publication uses compare-and-set against the expected snapshot, records a content digest for exact retries, and distinguishes pre-commit failure from a committed manifest whose directory durability is unknown.
2. `PublishedSnapshot` retains shared generation leases and exposes full reads or positioned `read_exact_at` access. This crate contains no mmap, shared file cursor, or unsafe code; a format-specific consumer may map an opened immutable file while retaining its lease.
3. A pre-commit write failure removes and syncs that attempt's unpublished data while preserving the current generation. Stale cleanup removes manifests and syncs that directory before deleting unreferenced layer/base data, treats missing paths as success, and reports errors to its caller. Process-abort tests cover process-crash recovery; they do not simulate machine power loss.

4. `GenerationFile::from_file` publishes from an open file using bounded buffers and positioned reads; it preserves the caller’s file cursor. File-backed and byte-backed inputs produce the same publication digest. The staged files are rehashed before commit to reject input changes between digesting and copying. Read or verification failure preserves the current publication; callers should keep input files stable until publication returns.
