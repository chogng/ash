# `ash-tgrep`

公共 [`grep`](../grep/README.md) 的 tgrep 进程与协议适配器，用于 Agent 和 Codebase 的 Indexed 内容搜索，以及共享目录的模糊文件查询。编辑器 Current 内容搜索由公共 grep 直接交给 rg。有提交的 Git worktree 共用仓库服务和不可变基础索引，各 Directory 持有独立租约；普通目录、未提交的新仓库和目录子范围使用单目录服务。索引、文件监听和差异核对由包内 tgrep 负责。

## 安装与生命周期

- 固定正式版 1.2.3 上游提交 `58629d208fcb508614b0ce6824bd78197647148f`，Ash 包内版本为 `1.2.3-ash.58629d2.1`。沿用上游的原生 watcher 修复、周期内容校验、引用感知回收、请求行上限和查询统计／批量读取；Ash 保留文件名、取消、宿主所有权和旧协议增量提示等仍有消费者的适配。源码和接入补丁的校验值见 [`runtime-lock.json`](../../third_party/tgrep/runtime-lock.json)。构建时编译，查询时不下载或编译。
- 开发准备、发布构建与 Remote runtime 都包含 `ash-resources/tgrep/tgrep[.exe]`。查询不联网下载，不搜索系统 `PATH`。显式 `ASH_TGREP_PATH` 可指定开发 executable；覆盖路径无效时直接报错。
- `just test` / `scripts/cargo.py run` 对依赖本 crate 的开发目标准备锁定的 executable；普通产品从安装目录解析。
- 进程池按 executable 与仓库存储键协调首次启动，全局表锁只做查找；同键等待检查取消，不同仓库可并行启动。池仅保存进程弱引用，最后一个 Session 释放后不会留住进程。
- Git worktree 首次查询懒启动 `tgrep serve --shared --shared-storage <目录> --shared-policy <策略> --ash-parent`，默认使用 managed v2。从 Git common directory 的 `tgrep-daemon-v2.json` 发现服务，包内凭据辅助命令复用上游私有文件权限校验读取认证信息。每个请求携带 namespace、instance、repository 和认证，每个成功响应及 worktree 查询分别校验服务身份、root、view、version 和精确 generation。
- 每个 Session 持有独立 owner、OS guard 和 lease；owner 准备明确绑定宿主管道，宿主异常退出时也能释放未完成的 bootstrap，等待已接收工作排空后退出服务；先持久化操作 token 与请求，再提交操作，持久化终态 receipt 后才 acknowledge。丢失响应使用同一 token 查询或重放，不用新 token 猜测是否提交。关闭先 fence owner，等待已接收工作终止和目录读取排空，再释放 guard 与宿主租约。
- 默认在线回收目标为 2 GiB，分批检查和删除，活动 generation、checkpoint、引用与宽限期对象受保护，因此这是软目标。构建工作、队列、游标与 receipt 另有预算；这些预算不是进程 RSS 上限。固定基线策略关闭 adaptive advancement；显式 `Session::rebuild` / 公共 `rebuild_index` 捕获当前 HEAD 并版本化推进，同一提交则刷新 checkpoint。v1 存储不自动导入或回收，原协议仍保留回归测试。
- 单目录服务的内容就绪还要求当前进程完成首次磁盘核对，避免重新启用索引时把旧索引的完整覆盖误当作已处理停机期间的修改；文件名查询仍不等待内容就绪。
- 注册固定起始提交，已有活动 view 则显式接受其精确版本。先安装目录 observer，再由有界 worker 在后台构建内容；文件名查询不等待内容完成。注册中断仍保留原操作意图；`open_with_lifetime` 让宿主的目录占用和存储租约覆盖后台清理，确认排空或结束所属服务后才释放。无法确认清理时停止所属服务，其他查询显式收到服务退出错误。普通目录、未提交的新仓库与目录子范围继续使用单目录服务。
- 单个租约释放不影响其他使用者。删除 worktree 前，App Server 通过公共 grep 等待已开始的搜索并确认释放索引租约；引擎最后一个目录租约在仓库注册锁外等待该目录读取结束，随后重新核对并释放租约，包括取消连接后仍在执行的发现和内容核对任务。最后一个 Session 释放时回收子进程。`close` 失败时保留注册和存储租约用于重试；引擎确认重复 detach，不会重新打开已删除的 checkout。State Runtime 的索引租约和临时存储由同一仓库的活动目录注册共同持有，最后一个注册释放后回收；正常宿主退出统一清理服务；单目录服务也绑定宿主 stdin 生命周期，避免 Windows 进程退出绕过析构时留下服务。
- 注册和文件名查询各有 30 秒截止时间；首次内容搜索另允许 10 分钟准备基础索引和 worktree 核对，再开始 30 秒查询。内容初始化等待操作 receipt 或核对状态返回构建错误，不等待后台重试耗尽期限；观察到首次内容发布后，后续核对与查询共用原来的 30 秒截止时间。取消关闭连接或终止扫描子进程。v2 文件名操作自动启用连接断开检查：排队请求在读取目录前跳过，目录修复与评分协作停止，未完成的修复不发布。Git 或系统调用中的读取需等该调用返回；注册、内容核对和释放继续完成资源清理。服务退出、协议错误和超时显式返回错误。内容索引暂未就绪或查询期间被失效时，在原截止时间内核对后重试；不按错误文案判断是否重试。

## 查询与新鲜度

`Session::file_fuzzy` 在引擎自己的路径清单上评分，只传回前 N 项、分数、字符高亮和截断前的数量。
排序与高亮共用 [`file-search/src/ranking.rs`](../file-search/src/ranking.rs)，目录排除规则共用
[`discovery.rs`](../file-search/src/discovery.rs)；两份源码都按锁中的哈希注入引擎。评分不承担准入策略。
查询最多 1 KiB，结果上限 1–5,000，并检查取消、30 秒期限、目录身份和返回路径范围。
开始查询前确认 Ash 通知的写入；元数据、ignore 和路径清单只有引擎一个所有者，Ash 不缓存完整候选列表。
显式 glob 继续查询当前磁盘路径。

批量 `files/page` 只保留为引擎内部诊断和测试协议，每页最多 1,024 条，游标绑定目录和成员版本。
Rust 公共适配器只提供有界模糊查询；游标收集移至测试辅助模块，不向产品导出。
成员变化使旧游标显式失败，纯内容修改保留版本。
文件名视图包含符合 ignore 规则的隐藏、二进制和大文件，不等待内容索引或文件大小准入。
普通文件变化只检查提示路径和祖先；目录变化核对子树，规则变化、提示溢出和轮询到期完整修复。
`files_ready` 与内容 `ready` 独立；文件名清单仍只驻留内存。

基础索引按 Git tree、索引格式和大小上限区分，由提交中的完整文件构建。每个 worktree 的新增、修改、删除和 ignore 变化只写入自己的 overlay；提交分支修改不会清空这些差异。overlay checkpoint 绑定精确基础索引和 worktree root，重启后先核对当前磁盘内容。managed 内容核对沿用上游受预算约束的发现与内容证据复用，仍需元数据遍历；文件名提示则保留路径和子树增量修复。v1 的细粒度内容发现优化保留在兼容路径，不能据此假设 v2 每次核对的元数据开销相同。基础索引和 checkpoint 的在线回收由引擎引用模型决定，Ash 不自行删除对象。

索引查询由服务一次完成候选筛选、按路径排序和全局匹配行上限。正向 glob 筛选遵守 ignore 规则的非隐藏文件，显式隐藏目录 scope 可查询可见子文件。公共 grep 将 Current、单文件或含未保存文档的内容查询交给 rg，不进入本适配器；Current glob 可以主动包含被忽略文件。本适配器仍保留直接扫描接口用于引擎兼容性测试。匹配文本保持完整。返回的 `index_stats` 统计本次查询的候选和总文件数，包含已处理的 Ash 写入；扫描没有索引统计。

Ash 文件工具写入后记录一份带版本的待确认路径，文件名和内容各保留自己的确认位置，只有两者都确认后才移除记录。提示最多 1,024 条、64 KiB 路径字节；任一限额溢出后改为带版本的全量核对标记，两个消费者独立确认该版本，未使用内容搜索时也不会无限累积路径。managed 单次内容提示超过工作队列上限时转为全量失效。下一次内容索引查询向所属 worktree 发送 `views.invalidate(changed, full)`，收到 `input_epoch` 并确认该 epoch 的内容就绪后推进内容确认位置；就绪重试等待核对，不重复施加变化提示；单目录服务使用 `reload`。文件名查询通过 `files/refresh(changed)` 独立确认目录元数据，不使已就绪的内容视图失效。刷新前在短锁内取得待确认版本和路径，RPC 在锁外执行；成功后只推进已捕获的版本，不误确认执行期间新增的写入。内容重建不阻塞文件名查询和写入通知。Ash 不自行扫描这些文件并拼接索引结果。共享服务监听每个 worktree；managed v2 的健康系统 watcher 按事件核对，并默认每 120 秒完整验证内容；完整验证期间继续服务已有视图，发现差异后关闭就绪并修复。显式轮询和 watcher 失败后的轮询回退按相同周期完整核对；关闭 watcher 时也关闭周期验证。旧 v1 继续在完整核对结束 120 秒后再次核对；文件名查询按引擎轮询周期核对元数据。内容索引在失效和 checkpoint 发布期间关闭内容查询。刷新确认表示指定修改已处理，不表示整个文件系统的瞬时快照。外部修改仍受异步通知时机影响，Current 明确要求读取当前内容。遍历、存储或内容读取失败返回错误。

旧 `fastRegex` 配置由 Config 迁移为 `tgrep`。旧 FRS 索引不读取；关闭并删除由 App Server 经 State Runtime 租约删除公共 grep 索引目录。

just test ash-tgrep
