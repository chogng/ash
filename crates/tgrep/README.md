# `ash-tgrep`

公共 [`grep`](../grep/README.md) 的 tgrep 进程与协议适配器。有提交的 Git worktree 共用仓库服务和不可变基础索引，各 Directory 持有独立租约；普通目录、未提交的新仓库和目录子范围使用单目录服务。索引、文件监听和差异核对由包内 tgrep 负责。

## 安装与生命周期

- 固定上游源码提交 `b614b8c51e76607abffaf73239c42365f0e3c1ff`，源码版本为 1.1.0，Ash 包内版本为 `1.1.0-ash.b614b8c.4`。包含上一次固定提交之后的 7 个更新，包括索引读取边界、源文件大小限制和搜索兼容性修复。源码和接入补丁的校验值见 [`runtime-lock.json`](../../third_party/tgrep/runtime-lock.json)。构建时编译，查询时不下载或编译。
- 开发准备、发布构建与 Remote runtime 都包含 `ash-resources/tgrep/tgrep[.exe]`。查询不联网下载，不搜索系统 `PATH`。显式 `ASH_TGREP_PATH` 可指定开发 executable；覆盖路径无效时直接报错。
- `just test` / `scripts/cargo.py run` 对依赖本 crate 的开发目标准备锁定的 executable；普通产品从安装目录解析。
- 进程池按 executable 与仓库存储键协调首次启动，全局表锁只做查找；同键等待检查取消，不同仓库可并行启动。池仅保存进程弱引用，最后一个 Session 释放后不会留住进程。
- 首次查询懒启动 `tgrep serve --shared --shared-storage <目录>`，从 Git common directory 的 `tgrep-daemon-v1.json` 读取发现信息，通过 `hello` 校验协议、能力和索引 profile。每个请求与成功响应校验服务实例和仓库身份；worktree 请求另校验 root、view 和精确 generation。
- 注册使用明确的起始提交和调用方预先分配的唯一 lease，路径模式先确认目录、租约和精确 generation，内容索引由两个有界 worker 在后台构建，每个 worktree 的核对串行，不同 worktree 可并行。注册中断后用同一 token 完成恢复与释放；`open_with_lifetime` 让宿主的目录占用和存储租约覆盖后台清理，确认 detach 或结束所属服务进程后才释放。无法确认清理时停止所属服务，其他查询显式收到服务退出错误；已退出服务的注册可正常释放。服务重启后分配新租约。普通目录与未提交的新仓库启动 `serve --index-path <目录> --no-require-git`，按自身目录隔离存储；目录子范围也使用单目录服务。
- 单个租约释放不影响其他使用者。删除 worktree 前，App Server 通过公共 grep 等待已开始的搜索并确认释放索引租约；引擎最后一个目录租约在仓库注册锁外等待该目录读取结束，随后重新核对并释放租约，包括取消连接后仍在执行的发现和内容核对任务。最后一个 Session 释放时回收子进程。`close` 失败时保留注册和存储租约用于重试；引擎确认重复 detach，不会重新打开已删除的 checkout。State Runtime 的索引租约和临时存储由同一仓库的活动目录注册共同持有，最后一个注册释放后回收；正常宿主退出统一清理服务。
- 注册和文件名查询各有 30 秒截止时间；首次内容搜索另允许 10 分钟准备基础索引和 worktree 核对，再开始 30 秒查询。内容初始化通过同步准备请求返回构建错误，不等待后台重试耗尽期限；观察到首次内容发布后，后续核对与查询共用原来的 30 秒截止时间。取消关闭连接或终止扫描子进程。文件名操作显式启用连接断开检查：排队请求在读取目录前跳过，目录修复与评分协作停止，未完成的修复不发布。Git 或系统调用中的读取需等该调用返回；注册、内容核对和释放继续完成资源清理。服务退出、协议错误和超时显式返回错误。内容索引暂未就绪或查询期间被失效时，在原截止时间内核对后重试；不按错误文案判断是否重试。

## 查询与新鲜度

`Session::file_fuzzy` 在引擎自己的路径清单上评分，只传回前 N 项、分数、字符高亮和截断前的数量。
排序与高亮共用 [`file-search/src/ranking.rs`](../file-search/src/ranking.rs)，目录排除规则共用
[`discovery.rs`](../file-search/src/discovery.rs)；两份源码都按锁中的哈希注入引擎。评分不承担准入策略。
查询最多 1 KiB，结果上限 1–5,000，并检查取消、30 秒期限、目录身份和返回路径范围。
开始查询前确认 Ash 通知的写入；元数据、ignore 和路径清单只有引擎一个所有者，Ash 不缓存完整候选列表。
显式 glob 继续查询当前磁盘路径。

批量 `files/page` 只保留为引擎内部诊断和测试协议，每页最多 1,024 条，游标绑定目录和成员版本。
Rust 公共适配器只提供有界模糊查询；游标收集移至测试辅助模块，不向产品导出。
成员变化使旧游标显式失败，纯内容修改保留版本。
文件名视图包含符合 ignore 规则的隐藏、二进制和大文件，不等待内容索引或文件大小准入。
普通文件变化只检查提示路径和祖先；目录变化核对子树，规则变化、提示溢出和轮询到期完整修复。
`files_ready` 与内容 `ready` 独立；文件名清单仍只驻留内存。

基础索引按 Git tree、索引格式和大小上限区分，由提交中的完整文件构建。每个 worktree 的新增、修改、删除和 ignore 变化只写入自己的 overlay；提交分支修改不会清空这些差异。overlay checkpoint 绑定精确基础索引和 worktree root，重启后先核对当前磁盘内容。首次注册仍需遍历和校验文件；后续文件提示只核对相应文件，目录提示只发现对应子树，未变化文件保留已确认的内容证据和可见性。新增或变动的 ignore 源、Git 已跟踪路径豁免变化、歧义提示和溢出退回完整核对；完整核对仍读取文件内容。路径证据、准入规则和 overlay 在同一版本发布，Ash 不维护第二份内容路径缓存。基础索引和 checkpoint 由上游保留，不进行在线回收。

索引查询由服务一次完成候选筛选、按路径排序和全局匹配行上限。正向 glob 筛选遵守 ignore 规则的非隐藏文件，显式隐藏目录 scope 可查询可见子文件。Current、单文件或含未保存文档的查询仍读取当前内容；Current glob 可以主动包含被忽略文件。匹配文本保持完整。返回的 `index_stats` 统计本次查询的候选和总文件数，包含已处理的 Ash 写入；扫描没有索引统计。

Ash 文件工具写入后记录一份带版本的待确认路径，文件名和内容各保留自己的确认位置，只有两者都确认后才移除记录。提示最多 1,024 条、64 KiB 路径字节；任一限额溢出后改为带版本的全量核对标记，两个消费者独立确认该版本，未使用内容搜索时也不会无限累积路径。下一次内容索引查询向所属 worktree 发送 `refresh(changed, full)`，收到 `processed_epoch` 并确认内容就绪后推进内容确认位置；就绪重试使用 `refresh/reconcile`，不重复施加变化提示；单目录服务使用 `reload`。文件名查询通过 `files/refresh(changed)` 独立确认目录元数据，不使已就绪的内容视图失效。刷新前在短锁内取得待确认版本和路径，RPC 在锁外执行；成功后只推进已捕获的版本，不误确认执行期间新增的写入。内容重建不阻塞文件名查询和写入通知。Ash 不自行扫描这些文件并拼接索引结果。共享服务监听每个 worktree，并在每次完整核对结束 120 秒后再次完整核对；文件名查询也按引擎轮询周期核对元数据。内容索引在失效和 checkpoint 发布期间关闭内容查询。刷新确认表示指定修改已处理，不表示整个文件系统的瞬时快照。外部修改仍受异步通知时机影响，Current 明确要求读取当前内容。遍历、存储或内容读取失败返回错误。

旧 `fastRegex` 配置由 Config 迁移为 `tgrep`。旧 FRS 索引不读取；关闭并删除由 App Server 经 State Runtime 租约删除公共 grep 索引目录。
