# Design Editor 设计与实施方案

Ash Design 的目标是贯穿构思、设计、生成、编辑和交付的创作编辑器。同一项设计工作可以包含白板、海报、演示、网站、应用和视频，共享品牌、素材、版本与生成记录；每种内容保留适合自己的编辑规则。

本文定义目标设计和实施顺序，不表示这些能力已经完成。当前二维编辑器的目录、状态、文件和生命周期约定以 [README](README.md) 为准；窗口装配和依赖方向遵守 [Sessions README](../../README.md) 与 [LAYERS](../../LAYERS.md)。未来能力按本文确定职责，完成实现与验证后再同步更新当前能力说明。

## 产品定位与参考依据

Design 结合精确编辑、Agent 创作协作和可重复执行的媒体工作流。用户能够直接调整对象，也能够让 Agent 围绕选区生成候选结果；一次创作积累的素材和设计决定可以用于多种成果。

### 七项工作区的 Part 分工

以下是 Ash 的目标布局约定。窗口复用现有 `SidebarPart`、`EditorPart`、`AuxiliaryBarPart` 和 `SessionsPart`，各工作区贡献自己的内容和显示要求。共享宿主与生命周期契约以 [Sessions 布局](../../LAYOUT.md#creator-conversation-and-editor-composition) 为准。

| 入口 | `SidebarPart` | `EditorPart` | `AuxiliaryBarPart` | `SessionsPart` |
| --- | --- | --- | --- | --- |
| Design | 图层、组件与资源 | 设计画布 | 设计属性 | 按需显示设计对话 |
| Whiteboard | 页面、区域与模板 | 白板与对象工具 | 按需显示对象设置 | 按需讨论与整理白板 |
| Slides | 幻灯片列表与模板 | 当前页、讲稿与演示 | 属性与转场 | 按需处理大纲、当前页或整套内容 |
| Brand | 品牌模板与素材 | 单张、整批素材与批量内容表 | 模板允许修改的内容、尺寸与导出 | 完整创作对话有需要时显示 |
| Sites | 网页、图层与 CMS 等任务导航 | 网页设计、断点、CMS 编辑与预览 | 布局、样式与交互 | 按需修改代码功能 |
| Make | 项目与页面导航 | 运行预览与代码编辑 | 选中元素的编辑属性 | 默认显示 Agent 对话 |
| Prototype | Design 的图层与流程列表 | 交互连接与原型播放 | 触发、目标、条件与动画 | 复用 Design 的对话与内容上下文 |

完整 Agent 对话只由 `SessionsPart` 承载，`SidebarPart` 保留导航、图层、模板和资源职责。图片生成提示词、文案调整等单项 AI 控件可以随对应编辑内容出现；需要持续对话时打开同一个 `SessionsPart`，不在侧栏或编辑器内再创建一套聊天状态。

Make 默认从左到右组合 `SidebarPart` 导航、`SessionsPart` 对话和 `EditorPart` 运行预览或代码，选中元素时再显示 `AuxiliaryBarPart`。其他工作区以 `EditorPart` 为主，导航和属性按当前任务显示，打开 Agent 时保留编辑器并显示 `SessionsPart`。打开对话后仍维持 Creator 入口选中；侧栏和属性区遵守现有显示偏好与窄窗口规则，不要求四个区域长期同时展开。Creator 首页保留导航侧栏，中央显示工作区入口。

`PanelPart` 按需承载终端、构建输出等底部工具。讲稿、批量内容表、CMS 编辑与运行预览属于对应的 `EditorPane`，不因位于页面下方就迁入 `PanelPart`。`ActivityBarPart` 保留 Creator 产品入口，七项工作区通过 Creator 导航选择；`TitlebarPart` 保留窗口导航和窗口操作。

工作区通过布局入口描述导航、编辑器、属性和对话的组合，不自行创建窗口 Grid 或新的 Part。对话身份、草稿、附件和执行状态由现有 Sessions 与 Agent / Thread 契约持有，设计文档、历史与保存由 Creator 编辑器和工作副本持有；两者按文档与对话身份关联。切换工作区、收起对话或进入播放只改变显示与焦点，不重建内容、不丢弃草稿，也不隐式停止运行任务或归档对话。

### Ash 的工作区与验收要求

以下是目标要求，不能作为当前实现已完成的说明。七个入口按自己的创作任务选择结构、工具和内容，不能因为共享编辑器或布局宿主，就全部固定为“图层—画布—形状属性”。布局由所属工作区提供给现有 Sessions 宿主，编辑内容与对话分别沿既有持有者管理。

| 入口 | 工作区的主要内容与辅助区域 | 判断能力完成的实际任务 |
| --- | --- | --- |
| Design | 画布为主，图层与资源、设计属性辅助；Agent 按需打开 | 编辑界面和组件，应用共享样式，保存重开；采用一次选区修改并撤销 |
| Whiteboard | 大白板与对象工具为主，页面或区域导航按需显示；不强制常驻形状属性栏 | 梳理想法、连接对象并整理为图；移动对象后连线保持对象关系 |
| Slides | 页面列表、当前幻灯片、属性与转场；讲稿和演示属于演示文稿本身 | 排序页面、调整内容、编写讲稿并完整演示；退出播放恢复编辑位置 |
| Brand | 模板与品牌素材、单张或整批素材、允许修改的内容及批量导出 | 发布有编辑约束的模板，替换批量内容并生成多尺寸素材，保持品牌要求 |
| Sites | 页面与图层、响应式设计、属性与交互；CMS、代码功能和发布各有任务入口 | 验证多断点布局、页面导航和内容更新，预览后发布并更新网站 |
| Make | Agent 对话与运行预览同时可见；代码可切换查看，视觉选区提供修改上下文 | 描述需求、生成可运行内容，在同一工作区继续修改并验证结果；保留代码与版本记录 |
| Prototype | Design 内容上的流程与交互编辑，辅助区显示触发、目标和动画；播放以原型为主 | 设置点击目标与分支，验证触发、条件和转场；退出播放继续修改同一设计 |

实现涉及 `contrib/<mode>` 的工作区、Creator 页面与视图装配、设计文档和文件契约，以及 Agent / Thread 接入；各项成果的内容规则由所属能力定义，共享空间几何、素材引用和文件设施不能代替这些规则。实现时同步覆盖对应真实任务、内容保存、撤销及视图生命周期；用 Playwright 验证 Browser、Electron UI 和 Electron 的编辑、对话、预览切换与键盘操作。Part 组合验收还需覆盖 Make 默认同时显示对话与预览、其他工作区按需打开对话、Creator 入口保持选中、导航和属性的独立显示、尺寸与焦点恢复，以及切换后草稿、附件、任务和未保存设计仍保留。当前具备的操作和限制见 [README](README.md#creator-工作空间)，通过验收后再更新能力说明。

## 用户如何开始和继续工作

新建入口允许描述目标，或选择海报、演示、网站、视频等起点。起点决定初始内容和工具，不限制后续成果。例如完成品牌海报后，可以引用它的产品图、字体与色彩制作短片。

普通用户围绕内容操作，专业用户可以深入调整图层、关键帧和流程节点。按当前成果显示工具，不把所有能力长期放在同一工具栏中；未实现的能力不提供可点击入口。下表描述可用区域的职责，不要求全部同时显示；各入口的组合以[工作区要求](#ash-的工作区与验收要求)为准，Make 的对话默认可见。

| 界面区域 | 职责 | 随当前内容变化 |
| --- | --- | --- |
| 左侧导航（`SidebarPart`） | 管理成果、结构和共享素材 | 海报显示图层，演示显示页面，视频显示镜头 |
| 中央编辑区（`EditorPart`） | 完成当前内容的编辑与预览 | 空间画布、分镜、时间线或工作流 |
| 右侧属性区（`AuxiliaryBarPart`） | 编辑选中内容的参数 | 排版、图片处理、镜头设置或节点输入 |
| Agent 协作区（`SessionsPart`） | 表达目标、处理候选与继续创作 | 携带当前文档、选区、引用素材与版本；Make 默认显示，其他入口按任务展开 |

画布负责空间组织和排版；分镜负责镜头目的与顺序；时间线负责片段、声音和动画的时间安排；工作流负责生成与处理的依赖。只有当前成果需要的视图才出现，切换视图不复制文档内容。

Agent 输入必须能明确表达修改范围。选择对象、标记图片区域或选择镜头时间段后，输入区显示对应上下文。Agent 返回的候选应说明改了哪些内容、影响哪些成果，用户可以比较和采用。直接编辑文字、几何或属性仍使用编辑器命令，不需要启动生成任务。

视觉和交互遵守 Sessions 的设计规范：作品占据主要注意力，辅助区域克制；状态有文字含义，所有操作可通过键盘完成。复杂画布、时间线和工作流提供无障碍帮助、文本内容视图及播报偏好，界面文案接入所属 NLS。

## 文档、成果与素材

设计文档组织一项创作中的成果、品牌资源、素材引用和流程定义。成果包括白板、排版作品、演示、视频序列、网站和应用；各自拥有明确的内容结构，共享稳定身份和引用。

媒体素材保存独立版本与元数据，设计内容保存引用和使用方式。相同素材可以同时用于海报、演示和视频参考，不因切换视图或增加成果而产生另一份内容副本。

设计文档、素材、对象、生成任务和对话使用各自的身份。设计文档可以关联 Project、Workspace 和 Thread，但不能用这些身份代替文档或素材身份。成果独立于对话存活；删除或归档对话不应删除已被设计引用的素材。

### Library 与编辑器的归属

Library 是收集和复用素材的地方，Design 是将素材组织成作品的地方。同一产品图可以从 Library 用到海报、网站和视频，各处保存自己的裁切、尺寸和时间安排。Library 更新了图片之后，已有作品仍读取采用时的确切版本，由用户决定哪些使用处升级。

| 内容 | 所属位置与职责 | 当前状态 |
| --- | --- | --- |
| Design 文档、对象、画板、图片使用方式与撤销历史 | `sessions/contrib/creator/common`；属于设计编辑器，不属于 Session 对话 | 已实现二维排版及图片引用 |
| Library 素材目录、集合、标签与检索 | Library 管理界面消费跨产品素材领域契约 | 已实现图片目录、导入、搜索、收藏、集合与预览 |
| 素材原件、不可变版本、来源与正式元数据 | Rust `assets` 领域；State 提供事务存储，通过现有 app-server 链路提供能力 | 已接入 Design 图片入库与确切版本读取 |
| 缩略图、音视频处理与素材删除回收 | 所属 Rust 素材与媒体领域 | 尚未实现 |
| 标签页、文件访问、保存与关闭检查 | 既有 Workbench、Platform 编辑器和工作副本设施 | Design 已复用 |
| 图片解码、尺寸读取及预览资源 | Platform 图片模块提供共享能力；Workbench 与 Design 各自拥有查看状态 | 已接入 PNG、JPEG、WebP |
| 对话与生成过程 | 既有 Agent / Thread 能力；关联文档和素材身份 | 候选采用尚未接入 Design |

当前 Design 的模型保留在 Sessions 所属贡献目录，因为编辑器目前只有 Sessions 使用。Workbench 是编辑器宿主，不集中持有所有产品的内容模型。将来出现明确的第二个编辑器消费者，再按实际归属提取共享能力；素材目录契约从一开始属于跨产品素材领域，不能要求 Library 导入 Sessions 的设计编辑模型。

采用 Library 或生成候选的素材时，作品保存确切版本并取得独立保留关系；目录删除、对话归档和编辑器关闭不删除已采用内容。可移动的设计包保留所用媒体字节，重开不依赖原 Library 路径或生成 Thread。来源与目录关联后续用于追溯和再次查找，不代替设计包中的永久引用。

### 媒体加载与预览基座

VS Code 的图片、音频和视频查看来自内置 `media-preview` 扩展，通过只读自定义编辑器与 Webview 承载。它提供查看与播放行为，不提供 Design 文档、Library 素材目录或视频剪辑模型。Ash 复用已有文件服务、编辑器宿主和生命周期设施，参考上游公开行为独立实现；不为图片查看引入整套扩展编辑器运行机制。

当前 [共享图片模块](../../../platform/media/browser/image.ts) 为普通文件查看识别 PNG、JPEG、WebP，交给浏览器解码并取得显示尺寸；解码结果及时释放。这些结果用于当前视图，正式素材元数据由 Rust 入库产生。`ImageResource` 提供由消费视图持有的预览 URL，关闭或替换时释放，不持有 Library 目录、设计模型或撤销历史。

[Workbench 图片预览](../../../workbench/contrib/mediaPreview/browser/imagePreview.ts) 负责普通文件打开、适应窗口、原尺寸、缩放、键盘操作和文本元数据视图；它收到文件服务的变化通知后重新加载。Design 的画布资源使用共享 `ImageResource`；导入通过 [素材服务](../../../platform/assets/common/assetService.ts) 上传原件，采用 Rust 返回的确切版本、类型、显示尺寸和内容摘要，保留自身的裁切和编辑规则。每个视图分别拥有短期预览资源，共用原始文件与既有文件访问契约，不建立第二份全局素材库。

[Rust 素材领域](../../../../../../ash-rs/assets/src/lib.rs) 校验原件、产生 SHA-256 摘要与包含图片方向的显示尺寸，保留原始字节，不套用模型输入的缩放或转码策略。[State 存储](../../../../../../ash-rs/state/src/assets.rs) 将版本和原件在同一事务中发布，相同摘要的内容只存一份，素材身份与版本身份保持独立。已发布版本不可改写；相同身份及相同内容重试返回相同结果，内容或来源冲突则拒绝。追加版本不改变已有作品采用的版本。

上传分块暂存，单图上限 16 MiB；取消和连接关闭清理未发布的数据；超过十分钟未活动的上传在下一次上传操作时清理。完整上传完成后进行不可取消的原子入库；响应丢失时按调用前确定的素材与版本身份读取确认，不自动重放修改。已入库内容独立于连接、窗口与 Thread 存活，当前不提供删除回收接口。Design 保存、脏状态与文件冲突仍由原工作副本负责，媒体字节随设计包保存，移动后重开无需连接素材库。

图片导入需要连接支持素材契约的 Rust 后端；普通图片文件查看仍通过既有文件服务工作。Library 已提供图片目录与采用入口，消费同一素材服务取得确切版本，并用前端媒体能力展示内容；Design 内的 Library 选择器尚未实现。音视频的共享播放和媒体处理仍待实现，普通播放器不会承担分镜、时间线或生成流程的状态。

### 文档内的关系与编辑方式

| 关系 | 表达什么 | 不能代替的职责 |
| --- | --- | --- |
| 对象层级与布局 | 包含关系、空间位置、排列与样式 | 媒体任务执行 |
| 页面与镜头顺序 | 演示顺序或叙事顺序 | 片段的精确时间安排 |
| 时间线 | 片段区间、音轨、文字图层和关键帧 | 生成步骤之间的依赖 |
| 工作流依赖 | 输入、处理步骤、输出与受影响范围 | 对象的空间排列 |

这些关系引用同一批对象和素材，但分别维护自己的规则。工作流节点在界面中的位置只用于阅读流程，不影响执行；时间线位置决定成片时间，不取决于节点在画布上的坐标。

| 内容性质 | 编辑方式 | 修改结果 |
| --- | --- | --- |
| 文字、矢量、布局、组件与关键帧 | 确定性的编辑命令 | 立即预览，进入文档撤销历史 |
| 生成图片和视频 | 使用模型支持的输入与控制 | 新的素材候选版本，明确选择后更新引用 |
| 可运行网站和应用 | 修改代码或有明确映射的组件 | 更新运行预览，并保留代码变更记录 |

生成视频中的人物动作不能按矢量对象逐项编辑，必须通过模型支持的控制或重新生成来调整。图层提取产生新的可编辑内容，保留原图和来源；不把提取结果当成原始结构。任意应用代码也不能承诺与设计对象无损双向转换。

## 第一阶段：文档与编辑契约

第一阶段交付品牌海报：导入产品图，放入画板，调整位置、尺寸、裁切和文字，保存后重开，再采用一次 Agent 局部修改并撤销、导出。先实现这个闭环，再增加视频和流程编辑。版本 2 结构、画板、图片引用及素材包读写已实现；以下完整契约还包含待实现的品牌资源、来源记录、素材替换和 Agent 候选采用，不能将基础编辑完成视为第一阶段全部交付。

### 文档结构与身份

新文档格式使用 `schemaVersion: 2`。格式版本表示如何解析文件，不表示用户编辑了多少次，也不作为生成候选或磁盘写入的冲突依据。

| 内容 | 保存字段与含义 | 约束 |
| --- | --- | --- |
| 文档 | `documentId`、`schemaVersion`、名称、成果顺序、成果表、素材表、品牌资源 | 文档身份不取决于文件路径、窗口、项目或对话 |
| 排版成果 | `artifactId`、`kind: composition`、名称、根对象顺序、对象表 | 第一阶段只实现排版成果；不创建尚不可编辑的视频或网站空壳 |
| 对象 | `objectId`、种类、名称、几何、可见性及种类专属属性 | 每个对象只属于一个成果；复制对象创建新身份 |
| 容器 | 画板或分组的有序子对象引用 | 根对象和子对象顺序共同决定层级与绘制顺序；父关系从它们推导，不再保存第二份父对象字段 |
| 素材 | `assetId`、名称、有序版本记录 | 一项素材有稳定身份，更新图片不会改变它的身份 |
| 素材版本 | `assetVersionId`、内容摘要、包内相对路径、媒体类型、原始尺寸和来源记录 | 已登记版本的内容与元数据不可改写；新内容建立新版本 |
| 品牌资源 | 稳定样式身份、名称、颜色或文字样式值 | 对象明确选择引用样式或使用局部值；修改共享样式一次更新所有引用对象 |

文档、成果、对象、素材与素材版本的身份使用 UUID。成果、对象和素材身份在文档内解析；跨文档引用必须带 `documentId`，不能仅凭同名对象或文件名建立关系。对象表按身份索引，有序引用表达包含关系；一个对象不能同时出现在两个容器，包含关系不能形成环，图像引用必须能解析到已登记的确切素材版本。文件解析在替换当前文档之前检查完整结构。

移动或重命名设计包保留文档身份；“另存为”创建独立文档，分配新的 `documentId`，包内身份可以保留，因为它们由文档身份限定。另存后的修改不更新原文档。多个编辑器分组打开同一个资源时共享一份模型和工作副本，通过已有资源身份服务判断是否为同一资源。

画板拥有固定宽高、背景和裁切开关，子对象使用画板局部坐标。调整画板尺寸改变交付范围，不隐式缩放子对象；缩放整套内容是独立命令。分组用于一起操作对象，保留现有组内坐标及等比缩放约定。两者不能使用同一个种类再靠 UI 推断用途。

### 图片引用与素材版本

图片对象保存确切的 `assetId` 和 `assetVersionId`，以及目标几何与源图裁切区域。裁切区域以原图宽高的比例保存，源图保持完整；显示和导出从同一个区域计算结果。改变裁切不创建新的图片文件。移动、旋转、缩放和裁切通过文档命令完成，拖动过程中只显示预览，完成时提交一次。

素材版本的内容摘要使用原始媒体字节的 SHA-256，用于校验内容及复用包内相同文件；摘要不能代替素材或版本身份。两个独立素材可以引用相同字节，仍保留各自的来源和版本记录。来源路径、Thread 和任务身份只用于追溯，作品显示不能依赖这些来源仍存在。

例如同一产品图用于主海报和横幅：两处图片对象引用同一个素材版本，分别保存自己的尺寸和裁切。采用新图片时由用户选择只替换当前对象，或替换指定的其它使用处；一次命令更新选定引用。不通过“永远读取最新版本”自动改变已有作品。

导入图片先读取原始字节、确认媒体类型与尺寸，并准备可保留的素材文件，再一次性登记素材、版本与图片对象。导入失败或取消不创建半个图片对象，也不进入撤销历史。生成结果先作为候选存在；采用时才登记到设计素材并替换对象引用。取消或删除对话不能删除已经采用的素材。

撤销替换恢复旧引用，重做恢复新引用；两者不重新生成、不改写媒体字节。删除最后一个图片对象也不立即删除素材文件，因为撤销、恢复备份、已保存文档或运行快照仍可能引用它。素材清理必须检查这些保留关系。

### 文件包与保存

可编辑成果使用目录形式的 `.ash-design` 包：`manifest.json` 保存版本 2 结构，`assets/` 保存原始媒体，媒体文件按内容摘要命名。文件内仅保存包内相对路径，移动整个包后引用继续成立；不把图片写成大段 Base64，不把用户导入位置或 Thread 产物位置作为永久引用。压缩交付属于导出，编辑器直接读写目录包。

未命名文档已导入的媒体由 Design 工作副本保留，并与结构化内容一起进入恢复备份。保存前拥有可解析的素材，不依赖仅存在于某个 Widget 的对象 URL；预览 URL 和解码资源由各编辑器实例按需创建与释放。尚未命名文档的素材保留能力需要随第一阶段实现，不能把关闭恢复只做成保存一段 JSON。

当前实现支持一个排版成果，运行时以不可变对象树持有内容，版本 2 清单用对象表及有序身份引用表达层级。解析先检查完整清单，再读取并校验素材字节。当前图片导入支持 PNG、JPEG 和 WebP；恢复备份包含原始字节，预览 URL 由 Widget 释放。这些边界不限制后续成果类型，新增字段和行为仍须完成对应解析、编辑与保存验证。

保存顺序是固定当前文档快照，写入它需要的全部不可变素材，最后用已读取的磁盘版本条件写入 `manifest.json`。清单是保存完成的判据；素材写入失败不能提交引用它们的清单。清单写入失败时，旧清单和原有素材继续有效，当前文档仍未保存；新增但未被清单引用的文件不被视为作品已保存。

保存期间继续编辑时，成功写入的快照成为保存基准，后续修改继续保持脏状态。脏状态比较文档内容与保存基准，不比较编辑次数；撤销到已保存内容时应恢复为未修改状态。保存不清空撤销历史，也不把选区、视口、拖动预览或播放位置写入文件。

现有 [文件服务](../../../platform/files/common/files.ts) 已有二进制读写、目录操作和条件文本写入。Design 的文件控制器组合这些能力，素材包读写仍经过文件服务；不在 Widget、Agent adapter 或 Main 内新增直接文件访问。文件服务的写入冲突与文件变化通知仍是磁盘变化依据，包内媒体损坏或丢失必须明确指出对应素材，不能替换成空白图片再保存。

版本 1 的 `.ash-design.json` 作为导入来源：完整解析后转换成一个排版成果，保留对象身份、顺序、分组、几何、文字、路径和已有动画，不凭空推断画板。第一次保存由用户选定版本 2 包位置；不改写原版本 1 文件，不双写两种格式。不能识别的格式版本在打开边界说明问题，保留当前文档。

### 编辑提交与异步候选

[DesignModel](common/model/designModel.ts) 继续拥有唯一已提交文档和撤销历史；[DocumentCommands](common/commands/documentCommands.ts) 负责操作语义；[文件控制器](browser/designDocumentController.ts) 拥有资源、磁盘版本、保存基准与工作副本生命周期。把素材登记与引用纳入文档快照，不另建一套图片编辑历史。

| 修改 | 提交范围 | 撤销结果 |
| --- | --- | --- |
| 新建画板或导入图片 | 对象、包含关系及必要的素材记录一起提交 | 移除此次新增内容，媒体保留仍遵守引用生命周期 |
| 移动、缩放、裁切或文字修改 | 一次用户操作产生一份文档快照 | 恢复操作前内容 |
| 替换图片或采用 Agent 候选 | 素材版本登记与所有选定引用一起提交 | 恢复旧版本及原引用范围 |
| 修改品牌样式 | 修改共享样式定义，不逐个复制对象值 | 恢复定义及全部引用对象的显示 |
| 打开另一份文件或恢复备份 | 完整替换已提交内容，重置历史与视图选区 | 不把替换混入前一份文档的撤销历史 |

编辑事务全部成功才提交；一次操作不能先更新素材面板，再单独更新画布。无内容变化的操作不进入历史。普通编辑和候选采用都经过同一个模型入口，一次提交发布一次内容变化通知。保存操作只更新文件基准，不作为编辑事务。

区分三种版本：`schemaVersion` 是格式版本，模型的 `editRevision` 是当前模型生命周期内的编辑序号，文件服务的 `diskRevision` 是磁盘内容的读取版本。编辑、撤销和重做都递增 `editRevision`，它不写入设计文件；模型新建或内容整体替换时产生新的 `modelEpoch`。版本令牌使用 `documentId + modelEpoch + editRevision`，避免重开同一文件后把旧结果误判为当前结果。

Agent 请求固定版本令牌、目标对象身份、选区或裁切范围、输入素材版本与必要的文档快照。后台任务保存这些确切输入，不读取正在变化的模型。候选只描述预期修改与结果，不直接调用模型写入；预览候选也不改变文档、脏状态或撤销历史。

采用候选时要求版本令牌一致、目标仍存在、引用素材与请求一致，再将全部修改提交为一次操作。期间即使只修改了其它对象，也不能自动采用旧候选；显示版本已变化，允许查看结果或基于当前内容重新发起修改。打开或恢复文件后的旧结果仍可查看，但需要重新明确目标和修改范围后才能作为新的编辑采用。第一阶段不实现自动合并。

### 第一阶段的落地顺序与验收

| 顺序 | 改动面 | 必须验证的行为 |
| --- | --- | --- |
| 1 | 文档类型、解析与模型提交 | 身份、包含关系、素材版本、版本 1 导入、编辑令牌与统一撤销 |
| 2 | 画板与图片渲染、命中、命令和属性 | 导入、放置、移动、缩放、裁切；画板调整不改变子对象；两处引用独立编辑 |
| 3 | 素材包与工作副本 | 保存、重开、另存、移动包、未命名恢复、保存期间编辑和外部修改冲突 |
| 4 | 海报排版与共享品牌样式 | 文字、对齐、层级和样式引用在同一历史中操作 |
| 5 | Agent 选区候选与导出 | 版本匹配才能采用、采用可撤销、过期候选保留可查看、采用素材脱离 Thread 保留、导出不改变保存状态 |

第一阶段验收只要求完成海报闭环：同一素材放到两个画板，独立裁切，修改品牌颜色，保存并移动包后重开；让 Agent 修改一处图片，另一处保留原版本，采用后撤销、重做并导出。还必须验证未保存文档恢复、缺失素材提示、磁盘冲突，以及请求发出后继续编辑时不能直接采用旧结果。通过后再开始三镜头视频，不能用视频或工作流演示代替这些基础行为。

## 视频与时间线

视频同时需要生成素材与编辑成片。完整路径为：创作说明 → 分镜 → 参考图与角色设定 → 镜头生成 → 时间线剪辑 → 字幕、声音与图形合成 → 导出。

分镜保存每个镜头的目的、参考素材、提示词、目标时长和候选版本。角色与产品参考跨镜头共享，具体模型只暴露其实际支持的参考帧、时长、比例和运动控制；不能把不同模型的能力假定为一致。

时间线拥有统一时间基准、片段入出点、顺序、音轨、文字图层和关键帧。对象动画与视频片段在同一成片时间下预览。播放时钟属于编辑器实例，片段安排和关键帧属于文档内容，离线渲染属于后台媒体处理。

字幕、标志和品牌文字优先保留为独立图层，避免把后续需要精确修改的内容固定在生成画面中。只改字幕时更新文字与合成；替换一个镜头时保留其它镜头和声音，再更新受影响的成片输出。

预览使用按需加载的缩略图与适合播放的媒体资源，避免在空间画布同时解码所有视频。导出读取固定的文档与素材版本，不能在导出过程中读取不断变化的编辑状态。

## 媒体工作流与执行记录

媒体工作流由有类型的输入、生成、处理、排版、合成和导出步骤组成。节点端口明确接受和输出的内容，执行前校验类型、缺失输入和依赖环；视觉连线对应实际数据依赖。

运行时固定流程版本、输入素材版本、参数和模型配置，记录节点执行状态、输出及失败原因。流程定义保存在设计文档中；运行记录和长时间任务由后端持有。相同提示词不保证相同生成画面，可重复使用的是确切输入和已保存结果。

输入变化后沿依赖标记需要更新的结果，保留已有输出供比较。局部重跑只执行用户指定且受影响的步骤，复用仍有效的结果。收费生成由用户明确启动，不因输入变化自动执行，也不隐式重试可能重复计费的请求。

常用流程可以提供简单输入表单，让用户作为创作工具使用；需要调整过程时展开同一份流程。参数表单与节点编辑共享定义，不能分别维护两套执行逻辑。批量任务固定每个输入项与输出的关联，局部失败可以定位到具体项。

任务区分等待、运行、成功、失败和取消，并保留已完成结果。停止必须到达真实任务或供应方取消接口；供应方不支持取消时明确显示实际状态，不把停止等待当作生成已停止。关闭编辑器释放界面订阅和预览资源，不隐式取消已提交的后台任务。

## 前后端职责与文件生命周期

| 能力 | 最终持有者 | 边界 |
| --- | --- | --- |
| 编辑内容、未保存修改、撤销与候选提交 | TypeScript 文档模型及工作副本 | 一次编辑只有一个提交入口 |
| 选区、视口、拖拽、播放时钟、布局与焦点 | TypeScript 编辑器实例 | 不进入后台持久状态 |
| 设计文件打开、保存和外部修改冲突 | 现有文件服务与工作副本 | 不新增第二套文件状态 |
| 模型调用、生成任务与取消 | 对应 Rust 领域能力 | UI 消费领域接口，不消费供应方协议 |
| 媒体处理、成片渲染与输出 | Rust 媒体处理能力 | 使用固定输入版本，拥有任务和资源生命周期 |
| 流程运行记录、恢复与任务产物 | Rust 执行与存储能力 | 与编辑器视图的存活时间分开 |
| 对话、Turn 与工具执行记录 | 现有 Agent / Thread 能力 | 关联设计上下文，不持有设计编辑模型 |

前端通过领域 service 和机械 adapter 使用 app-server，沿现有 renderer protocol client 与连接链路通信。Main 负责进程和连接装配，不成为媒体业务后端；app-server 负责协议调度，领域实现保留明确归属。只有出现真实跨模块消费者时才提取共享能力，不为目录对称建立空模块。

生成和导出读取不可变输入快照，结果返回素材或修改候选。采用候选时核对它所依据的文档版本和修改对象；文档已变化时展示冲突与候选，不覆盖用户后续编辑。文档内容的提交、撤销和脏状态仍由前端工作副本统一处理。

后端修改磁盘文件时，由现有文件监听和文件服务发现变化。未保存内容与磁盘变化发生冲突时使用工作副本的冲突处理，不让 adapter 维护另一份文档或保存基准。

当前图片生成产物存放在 Thread 范围内。接入 Design 时，需要让采用的素材具有独立的设计引用与保留生命周期，使设计文件重开、移动或对话归档后仍能解析素材。已实现的本地图片导入按[第一阶段的文件包契约](#文件包与保存)分开保存媒体和结构化内容；生成候选与 Library 的素材保留关系仍待接入。

## 实施顺序与验收

各阶段沿同一份设计文档、素材身份和执行边界增加能力，不建立需要替换的临时编辑模型。每阶段交付一个能够完成实际任务的闭环，尚未交付的能力保持不可用。

| 阶段 | 实现范围 | 验收结果 |
| --- | --- | --- |
| 设计与素材基础 | 画板、图片引用、文字排版、品牌样式、素材版本和选区修改 | 一套品牌海报可以保存、重开和继续编辑；局部修改可撤销 |
| 视频生产 | 分镜、镜头生成、时间线、声音、文字合成与 MP4 导出 | 三个镜头组成 15 秒短片，替换一个镜头不会重生成其它镜头 |
| 可编辑媒体工作流 | 有类型的节点、分支比较、结果复用、局部重跑与批量输入 | 一个生产流程可用于新输入，失败和受影响范围可定位 |
| 演示、网站与应用 | 页面顺序、演示播放、响应式布局、组件映射、运行预览与发布 | 共用设计素材完成交付，同时验证各自的内容和运行规则 |

第一阶段先完成[品牌海报验收](#第一阶段的落地顺序与验收)。跨成果验收在视频阶段完成：用同一套品牌与产品素材完成海报和短片，修改一个共享标题、替换一个镜头，再分别导出。标题修改更新海报和短片文字图层；镜头替换只影响对应片段与合成。它检验共享内容是否减少重复工作，以及编辑、素材、版本和执行是否真正连通。

实现验证需要覆盖：

- 文档解析、素材引用、版本升级、保存重开、移动后的引用解析、撤销重做和外部修改冲突。
- 生成任务输入版本、候选采用、重复提交、取消、失败恢复与已完成结果保留；对话归档后设计引用仍有效。
- 工作流端口类型、依赖环、结果复用、更新范围、局部重跑和批量项失败；避免重复计费的真实执行路径。
- 时间基准、片段入出点、声音与文字同步、对象动画、预览和实际导出的内容一致性。
- 使用 Playwright 驱动 Browser、Electron UI 和 Electron 的真实场景，检查视图切换、选区上下文、键盘焦点、窄窗口、主题、非默认语言与任务状态；通过 DOM、可访问属性和计算样式定位问题，不以截图代替行为验证。
- 对受影响模块运行所属测试与正常构建，检查新增 warning。当前验证入口见 [README](README.md#当前能力与验证入口)。

以上为待实现能力的验收要求，不是已完成测试的声明。
