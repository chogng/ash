# Creator 网站模式与 contrib 拆分

Creator 是 Sessions 的创作入口和工作区组合，Sites 是其中的网站创作模式。Creator、公共画布、七个模式和独立编辑能力在 `sessions/contrib/` 下平级归属。作品编辑复用 Workbench Editor 基座，图层和属性等工具面板复用 View 基座。各个 contrib 操作对应资源的文档和编辑上下文，文档修改、撤销重做与保存保持唯一入口。

本文是网站模式的开工设计，说明目标职责、当前基础、实施顺序与验收要求。以下目标尚未实现；源码定位只证明已有基础，不代表网站能力已交付。当前优先启动网站编辑闭环，其他 Creator 模式按各自需要推进。

## 产品关系

```text
Sessions
└─ Creator 创作工作台
   ├─ Design、Whiteboard、Slides、Brand 等创作模式
   └─ Sites 网站模式
      ├─ 页面管理
      ├─ 图层与选择
      ├─ 画布编辑
      ├─ 布局与响应式
      ├─ 外观编辑
      ├─ 交互编辑
      ├─ CMS 内容管理
      └─ 预览与发布
```

上图表达产品里的组合关系，源码按能力平级归属。公共画布由独立 canvas contrib 拥有，七个模式使用其公共契约；Sites 组合网站所需的页面、布局、外观和交互能力。

这里按完整能力拆 contrib，按钮和属性字段属于对应能力。例如 Flow、Fill、Hug、Gap、Padding 一起归布局编辑；它们共享规则、计算和编辑行为，分开会让一次布局修改跨越多个状态持有者。

Creator 模式决定用户正在创作什么，以及可用工具和面板的组合。某个模式内部的工具选择、动画播放或代码查看属于该模式的编辑操作。切换模式不能把现有文档自动解释成另一种成果，也不能隐式创建转换后的副本。

## 基座选择：作品用 Editor，工具面板用 View

复用 Workbench 的 `EditorInput`、`IEditorPane`、编辑器注册、编辑组及工作副本生命周期。Creator 负责创作入口和工作区组合，各模式注册能打开对应资源的编辑器，具体画布与工具作为编辑器的组件。图层树、属性、素材等面板使用 `ViewPane` 和 `ViewPaneContainer`，消费对应编辑器上下文。

七个创作模式在无需 Agent 对话时，统一采用 `SidebarPart | EditorPart | AuxiliaryBarPart`。这是窗口现有 Parts 的组合：中间直接使用共享 EditorPart，Creator 贡献负责模式入口、编辑器和工具面板的组合，不另建承载作品的 CreatorPart。左右 Part 的内容随当前文档模式切换，选中对象变化只更新适用的面板内容；EditorPart 内部呈现对应资源的空间画布、演示页面或运行预览。

```text
SidebarPart | EditorPart | AuxiliaryBarPart
页面/图层/素材 | 当前资源的编辑器 | 布局/外观/交互
```

左右面板可以编辑文档属性，仍然属于工具 View；中间的文件编辑器负责文档编辑上下文。所有面板命令绑定其所属编辑实例。Creator 与 Code 使用窗口共享的 EditorPart 及编辑服务，创作资源和会话 Code 工作集的恢复规则由窗口装配明确区分，不能因切换会话而替换正在编辑的创作资源。

用户需要与 Agent 讨论时，窗口布局额外显示已有 SessionsPart。对话的显隐不更换文档模型、不销毁编辑器，也不将画布搬进 Chat 或 AuxiliaryBarPart；右侧仍承担编辑工具的职责。具体对话位置由窗口布局契约决定，各创作模式不自行实现另一套对话容器。左右工具 Part 可由用户收起，编辑器保留当前资源和状态。

| 现有基座                                                                                                               | 适用职责                                         | 复用边界                                                              |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------- |
| [EditorInput](../workbench/services/editor/common/editorService.ts)                                                    | 指定打开哪个资源、使用哪个编辑器                 | 资源身份与编辑器类型分别表达；模式不是文档身份                        |
| [IEditorPane](../workbench/browser/parts/editor/editorPane.ts) 与 [EditorPaneRegistry](../workbench/browser/editor.ts) | 自定义编辑器的创建、加载、显示、布局、焦点与释放 | Design、Sites 等使用自己的内容模型和组件实现此契约                    |
| [EditorPart](../workbench/browser/parts/editor/editorPart.ts) 与编辑组                                                 | 标签、活动编辑器、分屏、打开取消、保存和关闭协调 | 复用现有实现与服务，Creator 不另建标签和文件关闭机制                  |
| [IWorkingCopy](../workbench/services/workingCopy/common/workingCopyService.ts)                                         | 未保存状态、备份、保存、另存、回退与外部修改     | 内容领域拥有序列化与模型；注册服务负责索引与协调                      |
| [ViewPaneContainer](../workbench/browser/parts/views/viewPaneContainer.ts)                                             | 面板显隐、顺序、折叠、尺寸及焦点                 | 承载图层、属性等工具；文档和撤销记录由编辑模型拥有                    |
| [Stanza](../editor/README.md)                                                                                          | 文本和富文档内容编辑                             | 在需要文字编辑的组件中使用；其 TextModel 不承担空间画布和网站布局模型 |

一个文件或文件包是一个持久资源，拥有一份已提交内容、撤销历史与保存基准。默认打开一个编辑器实例；同一资源可以打开多个编辑视图，它们可以分别编辑，但提交到同一个模型。独立的是各视图的选区、当前页面、断点和视口，内容及保存状态彼此同步。不同资源分别拥有自己的内容、历史与未保存状态。

例如同一网站可以同时打开电脑布局和手机布局。电脑视图修改共享标题时，手机视图也显示新的标题；手机视图修改手机断点的尺寸覆盖时，电脑布局保持自己的有效规则。关闭其中一个视图释放该视图的引用与资源，其他视图继续编辑。最后一个编辑引用关闭时处理未保存内容，再释放文档。保存、另存和恢复按文档执行，各视图不能持有竞争的保存基准。

网站包里的多个页面仍然属于这个网站文档，页面切换不产生新的工作副本。图层树和属性面板也是同一编辑器的辅助界面，可以发起编辑命令；它们不因“能编辑”就各自成为文件编辑器。命令必须携带发起操作的编辑实例上下文，避免多个视图存在时修改另一份选区。

`IWorkingCopyService` 只登记工作副本，不自动合并同一 URI 的内容，也不提供共享撤销。内容领域需要按资源取得和释放模型引用；同一资源的多个编辑器使用同一模型及保存状态。现有文本模型引用服务绑定 TextModel，空间文档不能直接冒用该类型。

当前 CreatorEditorPane 已在共享 EditorPart 的保留产品编辑组中承载 CreatorPage，各模式工作空间与其文档保持原有独立生命周期。图层与属性使用左右 ViewContainer；会话工作集恢复保留产品编辑组。按网站文件身份打开多个编辑器、共享同一网站文档模型和资源恢复仍属于 Sites 的目标能力。涉及的窗口契约见 [LAYOUT.md](LAYOUT.md) 和 [LAYOUT_CONTROLLER.md](LAYOUT_CONTROLLER.md)。

## 职责与数据归属

| 层                           | 拥有的职责                                                           | 与其他层的关系                                                              |
| ---------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Sessions 窗口                | Parts、窗口布局、导航、焦点与窗口生命周期                            | 组合 SidebarPart、EditorPart、AuxiliaryBarPart，按对话需要显示 SessionsPart |
| Creator 贡献                 | 创作入口、模式选择与能力组合                                         | 作品在共享 EditorPart 编辑，工具 View 分别注册到左右 Part                   |
| Sites 模式                   | 网站工作区组合、默认工具与面板、网站编辑上下文                       | 组合所需 contrib，定义网站特有的内容和运行要求                              |
| 网站文档与编辑模型           | 页面、元素、布局规则、断点差异、样式、链接和内容绑定，以及提交和历史 | 所有编辑能力通过同一编辑入口修改                                            |
| 文档工作副本及模型引用拥有方 | 资源身份、模型引用、读取版本、保存基准、未保存状态、备份和关闭处理   | 按资源共享内容，使用现有文件服务与工作副本设施                              |
| contrib                      | 自己的命令、控件、面板、手势及订阅                                   | 借用文档和编辑上下文，拥有自己的界面与资源                                  |
| 后端领域能力                 | 发布任务、站点版本与长期运行的任务状态                               | 前端使用领域服务；连接适配层负责传输转换                                    |

“同一份文档”指同一个网站的编辑过程。不同创作模式可以拥有各自的内容类型；公共契约围绕工作区和文件生命周期建立，不要求所有成果都塞进现有图形对象类型。

网站编辑上下文包含文档、当前页面、当前断点和选区。画布、图层树、布局面板与外观面板读取同一上下文。选区及视口属于编辑器实例，页面内容及规则属于文档；多个视图打开同一文档时，共享内容与历史，分别保留自己的选择和视口。

可变状态使用 observable；事件用于通知。命令携带发起操作的文档与编辑上下文，不能默认操作窗口里另一个活动编辑器。Context key 只表达命令和菜单的启用条件，业务逻辑读取状态持有者。

## contrib 的拆分边界

以下名称用于说明目标职责，创建目录与公开接口时仍需有实际消费者。已有能力能够承担职责时扩展其契约，不按表格预建空模块。

| 能力         | 对应截图操作                                          | 完整职责与边界                                                                       |
| ------------ | ----------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 页面管理     | Webpages、Home、/journal、/article                    | 页面创建、删除、顺序、名称与路由；页面切换更新编辑上下文                             |
| 图层与选择   | Layers、元素层级、显隐                                | 显示文档层级，选择、重排与包含关系编辑；与画布共享选区                               |
| 画布编辑     | 点击、拖动、缩放、测量、工具栏                        | 视口、命中、手势和编辑辅助显示；通过编辑命令提交内容                                 |
| 布局与响应式 | Desktop/Tablet/Mobile、Primary、Position、Auto layout | 断点、继承与覆盖、排列、尺寸、间距、内边距和定位；拥有网站布局规则的求值             |
| 外观编辑     | Fill、Stroke、Effects、Opacity、圆角                  | 编辑颜色、边框、阴影、透明度及可复用样式；按元素类型提供适用控件                     |
| 交互编辑     | Link、Interaction                                     | 页面跳转、外链、触发条件和交互定义；预览消费这些定义                                 |
| CMS          | 内容集合、文章字段、列表绑定                          | 内容结构、条目、模板与绑定；内容和页面模板具有不同身份                               |
| 预览与发布   | 预览按钮、Publish                                     | 预览贡献负责运行网站；发布贡献负责固定版本、启动任务和显示结果，两者生命周期分别管理 |

页面路由、断点和 CMS 是网站领域规则。图层操作、选区、颜色编辑等能力只有在多个模式的实际契约一致时才共享；网站尺寸规则不能通过给自由画布的宽高字段附加含义来表达。

布局计算归布局能力，画布负责呈现计算结果。属性面板编辑规则，预览和发布使用同一套网站布局与运行语义，避免编辑器里看起来正常、实际网站排列却不同。

## 网站文档的关键约定

### 页面、元素与断点

页面与元素拥有稳定身份。路由属于页面，导航与链接引用目标页面身份；页面重命名和路由修改不会让内部链接丢失目标。删除被引用页面时，由同一次编辑处理引用并明确展示结果。

一个页面保存一份元素结构，断点保存明确的属性差异。Primary 是主要编辑版本，次要断点继承没有覆盖的属性；在次要断点修改只形成该断点的差异。主版本修改不能覆盖已有的次要断点差异。切换 Primary 必须保持各断点原本的有效内容，变更作为一次可撤销操作。

断点中的显隐与元素的全局删除分别表达。新增和删除元素的适用范围必须在编辑入口明确，不能把多个断点做成互不关联的完整页面副本。

### 布局规则与计算结果

文档保存固定尺寸、Fill、Hug、排列方向、对齐、Gap、Padding、定位及必要的尺寸限制。计算后的坐标和尺寸用于显示、命中和测量，属于可重算结果。

例如截图中的 `800 Fill × 3976.55 Hug`，800 和 3976.55 是当前结果，Fill 和 Hug 才是文档规则。手工改变规则与浏览器宽度变化导致重新排版，是两种不同操作；重新排版不产生文档修改或撤销记录。

Relative、Absolute、Fixed、Sticky 保存各自的定位语义。图层树可以按滚动行为分组显示，但分组不能成为另一份页面结构。图层名称与网页结构角色分别保存，例如名字为 Header 的元素仍然可以承担 main 角色。

### 编辑、预览与保存

面板修改、画布操作和 Agent 采用结果经过同一编辑事务。一次拖动先显示预览，结束时提交一次；取消丢弃预览。撤销恢复该次操作的全部内容，包括断点差异及受影响的引用。

模式切换、页面隐藏与界面释放遵守明确生命周期：隐藏时停止手势和视图播放，保留未保存文档；释放视图清理其订阅、DOM 和预览资源；文档由工作副本持有并参与窗口关闭处理。已启动的发布任务不依赖某个面板继续存在。

预览消费网站文档的明确版本；实时更新时切换到新的完整版本。发布固定内容、素材与运行配置版本，编辑中的后续修改不会混入已经启动的发布。发布与文件保存是不同结果，发布成功不能消除尚未保存的编辑。

网站格式需要在第一轮内容实现时完成解析、序列化与版本约定。元素层级、断点差异、样式与页面引用使用网站内容类型，不能借用任意 metadata 字段规避模型定义。媒体通过已有素材服务取得确切版本，采用到网站后的引用随网站保存与恢复。

## 代码归属与装配

目标源码采用平级 contrib：

```text
sessions/contrib/
├─ creator/       # 创作入口与工作区组合
├─ canvas/        # 公共空间画布、坐标转换与手势机制
├─ design/
├─ whiteboard/
├─ slides/
├─ brand/
├─ sites/
├─ make/
└─ prototype/
```

布局、外观、交互等完整编辑能力也按职责平级归属。Sessions 已有 `contrib/layout` 拥有窗口布局；网站内容布局与它职责不同，实施时需使用明确的领域名称。能力自己的公共契约跟随拥有方，只有窗口核心或共享服务也需要消费的契约才放进相应共享层。

公共画布已拆至平级 [`contrib/canvas`](contrib/canvas/README.md)，七个模式通过编辑器使用它。当前 Creator 及模式仍在 [`contrib/creator/`](contrib/creator/README.md) 内部。上图是目标归属；调整目录时需同步迁移全部生产调用点、测试和文档。公共画布提供空间编辑机制，网站模式拥有排版与定位规则，公共画布不导入具体模式实现。

依赖方向是：产品入口装配模式，模式装配能力，能力消费所属文档与工作区契约。Creator 工作台不导入具体模式实现，能力不导入其他能力的私有 widget。跨 contrib 调用使用拥有方的公共接口；共享注册机制的契约归共享拥有方。

Sessions 窗口核心和共享服务不导入 contrib 实现。Creator 使用 Sessions 的窗口能力与 Workbench 以下的公共服务；Workbench 不反向导入 Creator。当前宿主与旧 Design 命名的相关调用点需在实现时一起整理，不扩散已有不符合分层的依赖。

模式与命令通过适当的 `sessions.*.main.ts` 入口加载。Sessions 菜单 ID 统一登记在 [`browser/menus.ts`](browser/menus.ts)。普通网站编辑 contrib 不依赖会话 provider 实现。

## 实施顺序与验收

按可完成实际工作的顺序交付，每轮使用长期所属的模型和接口。尚未实现的能力不显示为可用操作。

| 顺序 | 实现范围                                                                           | 验收结果                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 平级 contrib 装配、Editor 基座接入、按资源管理的网站文档、基础页面和选择、工作副本 | 打开两份网站分别编辑，同一网站多视图共享内容、历史和保存基准；创建页面、撤销重做、保存重开，关闭一处和切换会话不丢其他视图内容 |
| 2    | 布局与响应式、外观、网站画布计算及交互预览基础                                     | 搭出标题与文章列表；电脑和平板继承主布局，手机可覆盖；Fill/Hug、间距、定位在画布和浏览器运行中一致                             |
| 3    | 内部路由、外链与交互编辑，完整运行预览                                             | 首页跳转文章页，修改路由后链接仍有效，能返回；不同宽度下可完成相同访问任务                                                     |
| 4    | CMS 集合、字段、模板和内容绑定                                                     | 文章集合驱动列表与详情，新增条目更新页面，模板与内容分别编辑并可保存重开                                                       |
| 5    | 发布贡献与后端发布领域接入                                                         | 发布确切版本，返回可访问站点与任务结果；发布期间继续编辑不改变已启动任务的输入                                                 |

第一轮直接从网站文档与 Creator 装配开始，同时交付能保存重开的最小页面编辑流程。页面树、选区、命令、历史、文件控制器及其测试属于同一轮实现，不把 UI 接好后再补内容契约。

实现验证需要覆盖：

- 文档解析、层级及引用校验、序列化、备份恢复、保存重开、未保存状态和外部修改冲突。
- 同模式多资源独立编辑；同资源多视图共享内容、历史与保存基准，独立选区与视口，关闭最后引用及另存后的身份与引用更新。
- 七个模式使用同一套 SidebarPart、EditorPart、AuxiliaryBarPart；切换文档更新左右面板，显示或隐藏 Agent 对话保留编辑内容、选区和视口。
- 页面与元素身份、断点继承和覆盖、主版本变更、尺寸求值及跨面板统一撤销。
- 实际预览的路由、定位、不同宽度布局及交互行为；发布输入版本、失败结果和任务生命周期。
- 使用 Playwright 驱动 Browser、Electron UI 与 Electron 的真实流程，通过 DOM、焦点、可访问属性和计算样式定位问题。
- 键盘选择与编辑、逻辑焦点顺序、菜单关闭后的焦点恢复；新增区域提供无障碍帮助、提示播报设置，网站画布提供可访问文本视图。
- 文案、错误与可访问名称接入所属 NLS；至少验证一种非默认语言，以及窄窗口、主题和本轮受影响的界面状态。
- 执行受影响模块测试、分层检查及正常构建，检查本轮引入的 warning；只记录实际运行的验证结果。

界面遵守 [Sessions 设计规范](../../../../.agents/skills/sessions-design-philosophy/SKILL.md)，无障碍实现遵守 [accessibility skill](../../../../.agents/skills/accessibility/SKILL.md)。窗口职责与依赖约束分别见 [Sessions README](README.md) 与 [LAYERS.md](LAYERS.md)。
