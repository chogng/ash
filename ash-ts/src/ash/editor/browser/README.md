# Stanza Editor browser layer

> 行式文本编辑器的 canonical 设计规范见 [`text-engine.md`](../text-engine.md)，文本几何与浏览器渲染后端的长期目标见 [`text-engine-geometry.md`](../text-engine-geometry.md)（中文翻译见 [`text-engine-geometry.zh-CN.md`](../text-engine-geometry.zh-CN.md)），结构化文档规范见 [`document-engine.md`](../document-engine.md)。本文只拥有 browser implementation contracts、DOM lifecycle、input projection 和修改影响。

This directory owns Stanza's native browser projection of contracts from `../common/`. It may import `base/common`, `base/browser`, and editor common contracts. Neither `editor/common` nor `base` may import this layer.

Language presentation is an optional consumer of this layer and lives in `./view`, `./controller`, and feature-owned `../contrib/*/browser` directories. `CodeEditorWidget` installs the selected contributions through separate language-configuration and language-feature services. Contributions consume the relevant provider registry and own their request lifecycle and presentation; they do not require a separate model-level service. Pure helpers may remain beside browser feature orchestration. Shared provider contracts follow the ownership rules in the [Editor README](../README.md), independently of where a feature displays its results. The text model does not import language providers, grammars, diagnostics, or completion services.

Browser-owned responsibilities include:

- viewport observation and DOM virtualization;
- EditContext (native/textarea), keyboard, pointer, and composition-event adapters;
- font and glyph measurement;
- WebGPU device, DPR, glyph-atlas, and eligible visible-line rendering;
- DOM selection, focus, scrolling, and pointer projection;
- ARIA and screen-reader surfaces;
- presentation of editor-owned decorations and semantic tokens.

Glyph-margin features contribute model decorations or caller-owned `IGlyphMarginWidget` values. `GlyphMarginWidgets` owns stable widget and decoration DOM, semantic product-icon mounting, ARIA state, lane geometry, z-index conflict selection, and pointer target metadata. Folding and Debug own their decoration collections and controllers; neither provider creates browser elements or SVG markup.

`EditorTextAreaInputContext` provides the textarea implementation and `BrowserEditContext` provides the browser `EditContext` implementation when available. Both satisfy one `EditorInputContext` contract and own their concrete DOM, focus/ARIA state, composition lifecycle, screen-reader support, and platform-event routing into `ViewController`. The EditContext implementation keeps the browser edit buffer synchronized with the common model and never creates a second document authority.

Pure text, history, selection, decoration identity, composition transaction semantics, and DOM-independent layout math remain in `editor/common`. Workbench parts may host the browser editor and own its external box, but must not reach through its component internals. Visual rules follow [`docs/ui-styling-ownership.md`](../../../../../docs/ui-styling-ownership.md).

Browser implementation follows the frontend-wide [`coding-guidelines.instructions.md`](../../../../../.github/instructions/coding-guidelines.instructions.md), editor-scoped [`editor.instructions.md`](../../../../../.github/instructions/editor.instructions.md), and browser UI [`browser-ui.instructions.md`](../../../../../.github/instructions/browser-ui.instructions.md).

The structured Document Engine is a sibling domain inside Stanza. Line-editor contracts must not import or expose document node, schema, profile, or transaction types.

## Current implementation

`EditorInputContext` is the browser input boundary. The native implementation is
split by responsibility under `controller/editContext/native`: the core adapter
owns the browser `EditContext` event bridge, `nativeEditContextUtils` owns focus,
bounded-window, and offset helpers, `nativeEditContextRegistry` exposes active
contexts to host integrations, the native factory owns capability detection,
and the native CSS owns the hidden editing surface. `EditorScreenReaderSupport` and
its simple/rich content projections provide the optional screen-reader mirror;
the rich projection reuses the viewport's semantic-token and bracket boundaries
without changing the mirrored source text. Both projections use bounded,
line-oriented accessibility pages, preserve model-to-DOM UTF-16 mappings across
page separators, and follow the viewport cursor/scroll geometry. `screenReaderUtils`
owns the page windows and DOM/model coordinate mapping. `BrowserEditContext`
keeps the browser edit buffer synchronized with the common model and never
creates a second document authority. When the API is unavailable,
`EditorTextAreaInputContext` provides the textarea implementation. Each concrete edit
context owns its focus and ARIA state, `CompositionController`, and screen-reader
support; `EditorView` selects one implementation and exposes that contract, while
`ViewController` owns semantic command routing independently of the concrete DOM element.

`CodeEditorWidget` is the browser editing surface and owns a stable root DOM and editor identity. Each attached model has one disposable ViewModel, View, input controller, worker, and contribution set; switching models releases that set before attaching the next one. Cursor construction follows `CodeEditorWidget → ViewModelImpl → CursorsController → CursorCollection → Cursor`: the widget retrieves the ViewModel-owned controller for browser input and contributions instead of creating a second selection owner. Model content changes enter through the ViewModel collector; a flush rebuilds the collection and its tracked markers before publishing one cursor-state transition. Contribution context exposes that controller as `selectionController` and the full model/view state as `viewModel`. Keyboard routing calls `CursorMoveCommands`, retaining only the model state needed to preserve the expected column between consecutive vertical commands. Workbench continues to own model references, dirty/conflict state, save participants, save/revert routing, and persistence.

`View` is the first native browser projection. It consumes `EditorViewportLayoutManager`, creates one component-owned scroll surface, and renders only the overscanned line range. Overlapping lines retain their DOM identity while scrolling. A new model version updates visible row text synchronously, and a shrinking document clamps both the common viewport state and native DOM scroll coordinates.

`ViewContext → ViewPart → View` now owns browser rendering lifecycle. Every `ViewPart` registers and unregisters through the shared context; `View` owns assembly and synchronous render phases. `ContentViewOverlays` and `MarginViewOverlays` retain one visible row set each, while `DynamicViewOverlay` implementations return per-line content. Cursors and block decorations remain independent Parts because they own stable DOM beyond one overlay row.

`RestrictedRenderingContext` publishes only the viewport and vertical-layout data shared by all Parts. `RenderingContext` adds line geometry through the DOM/GPU `IViewLines` implementations. Feature state, document access, text measurement, and visual-line mapping are explicit Part dependencies rather than fields on a shared metadata object.

The widget exposes its browser `View` as `view` and derives `controller` from that View. Contributions use the same names. Model attachment stores the View once; controller access does not introduce another resource slot.

`EditorConfiguration` is the single source for font, wrapping, mouse style, minimap, and vertical padding. `View` receives that configuration directly; its construction options carry DOM ownership, measurement inputs, horizontal insets, and feature dependencies. `Minimap` reads current settings from its existing `ViewContext`, including after configuration updates. Embedded defaults are selected when the widget creates its configuration.

Folding sends hidden line ranges directly to `ViewModel.setHiddenAreas`. The folding range model merges overlapping collapsed regions; the view-model line collection consumes one range list. The widget does not scan line visibility or translate a separate visibility source.

The browser configuration seam is intentionally small. `editorConfiguration.ts` resolves the font and line-height values that affect initial geometry, `domFontInfo.ts` applies the same font vocabulary to viewport and diff roots, `elementSizeObserver.ts` coalesces initial and `ResizeObserver` dimensions, `tabFocus.ts` owns host-injectable Tab-focus state, and `fontMeasurements.ts`/`charWidthReader.ts` own font-environment reads. The `toggleTabFocusMode` contribution consumes that state for keybindings, DOM state, and announcements. `migrateOptions.ts` is the single compatibility boundary for the legacy option spellings that the public editor constructor still accepts; callers and view parts consume only the normalized options.

Standalone language-feature registration follows the public `(LanguageSelector, provider)` boundary. `standaloneLanguages.ts` translates the selector once into the internal provider registry's ownership metadata; feature providers do not carry `languageIds` as part of their public contract.

Standard model decoration options own line-side and block presentation. `LinesDecorationsOverlay` reads `linesDecorationsClassName`, `firstLineDecorationClassName`, tooltip, and z-index from `RenderingContext`; `BlockDecorations` reads `blockClassName`, after-end, collapse, and padding options from the same viewport decoration set. Folding and Symbol Icons now reach these Parts through model decorations rather than a browser decoration-source adapter.

`EditorDiffWidget` is a separate read-only review surface rather than two independently scrolling editor instances. Its caller owns a `DiffModel`, which observes caller-owned original and modified `TextModel` values and accepts only results pinned to their current versions. Workbench `IDiffService` creates `AppServerDiffComputationService` instances that adapt bounded diff results, hunk ranges, and grapheme-safe inline ranges to the editor's UTF-16 model; the Editor browser layer imports neither the transport API nor that adapter. The widget owns one virtualized scroll surface and side-by-side DOM rows, but owns neither text nor computation. Editing, selection history, syntax processing, and model persistence stay with ordinary editor parts. `nextChange`/`previousChange` and F7/Shift+F7 wrap over changed rows, add the component-owned `.active` state, and announce the original/modified location through the diff view's live region. Workbench `DiffEditorInput` gives the Workbench one synthetic tab resource while retaining two ordinary caller-owned text-resource inputs. `DiffEditorPane` acquires and releases both `TextModelReference` values, then hosts this view; it neither turns the synthetic URI into a text model nor owns either model's save/revert lifecycle.

`EditorMultiDiffWidget` composes an ordered collection of caller-owned `DiffModel` values in one virtualized outer scroll surface and reuses the same diff-row projection without importing Workbench. Workbench `MultiDiffEditorInput` owns the synthetic tab identity and ordered comparison list, while `MultiDiffEditorPane` acquires every underlying `TextModelReference`, owns their per-comparison `DiffModel` lifetime, and releases the complete session together. Product consumers such as SCM provide immutable comparison snapshots and open the Workbench input; they do not own widget internals or create a second text model authority.

Document views also own an optional minimap overlay configured through `IEditorMinimapOptions`. `EditorMinimap` consumes the common `EditorLayoutInfoComputer` geometry, projects visual rows and semantic-token colors into one canvas with `MinimapCharRenderer`, and owns its diagnostic/diff marker layer, slider, and pointer navigation. Document views use the common proportional minimap size by default while embedded views default it off; callers can select `fill` or `fit` explicitly. The minimap reads the canonical model and visual projection but owns no text, selection, scroll, or language state.

Text-bearing virtual row roots use ordinary `top` positioning rather than permanent transform promotion. With `experimentalGpuAcceleration: "on"`, `browser/gpu/viewGpuContext.ts` owns the per-window device request and the canvas, pixel-ratio, atlas, and rectangle-renderer lifecycle. `BaseRenderStrategy` owns only the standard strategy contract and view-event lifecycle; `FullFileRenderStrategy` and `ViewportRenderStrategy` each encode their own cell layout in their upstream-matching file. `GlyphRasterizer`, `TextureAtlas`, `TextureAtlasPage`, and the shelf/slab allocators keep their corresponding responsibilities while using Ash's smaller resolved-CSS implementation. `viewParts/viewLinesGpu/viewLinesGpu.ts` uploads glyph pages and hides a DOM row only after a complete GPU frame contains it. That frame retains the exact character boundaries used for drawing, so GPU rows answer `IViewLines`, line-width, and horizontal hit-test queries without reading hidden DOM. DOM rows answer the same contract for rows they actually render; right-to-left text, ligatures, unsupported token decorations, overlong rows, initialization failures, and device loss remain DOM-owned.

Diagnostics and diff features publish standard model decoration options for the overview ruler and minimap. Those Parts read only decoration color, lane, position, and model range; they do not retain diagnostic text, source text, or syntax results.

`EditorIndentGuidesOverlay` projects indentation guides only for visible first fragments of logical lines. `browser/viewParts/indentGuides/indentGuides.ts` identifies complete visual indentation units from leading tabs/spaces, while `TextMeasurer` places each guide in the same coordinate system as carets and selections. Continuation fragments never duplicate a guide, and scrolling does not retain offscreen source text.

`common/languages/LanguageBracketPairs` owns one model-wide structural bracket index shared by matching, navigation, editing, and nested colors. It consumes the current lexical/token context, invalidates when model tokens or language configuration change, and exposes only valid paired ranges to `BracketColorizationSource`; strings, comments, and unmatched brackets remain uncolored. The token renderer composes bracket level classes with existing semantic-token spans rather than making a second text DOM or mutating source content.

With `EditorLineWrapping.On`, the common `ViewModelLines` converts each logical line into measured grapheme-safe visual rows. The browser `DOMLineBreaksComputer` supplies only the font-dependent batch break calculation; its `ILineBreaksComputerContext` reads logical model lines, while the public `ICursorSimpleModel.getLineContent` reads visual rows. `ViewModelLines.createCoordinatesConverter()` uses that same version-bound mapping for model/view positions, ranges, hidden lines, and wrapped boundaries. The viewport virtualizes those rows directly: continuation rows keep a blank gutter, horizontal scroll is disabled, and text/semantic-token fragments, selection and decoration rectangles, composition anchors, pointer hit testing, reveal, vertical keyboard navigation, and column selection all use the same mapping. `TextModel` remains the only document authority; rebuilding rows never creates a shadow model or alters history.

Code folding is an editor contribution under `../contrib/folding/browser`, following VS Code's `editor/contrib/folding/browser` boundary. The common `ViewModelLines` accepts a feature-neutral `EditorLineVisibilitySource` and composes it with soft wrapping. The folding contribution owns range data, fold state, hidden-line derivation, commands, and folding presentation styles. `EditorFoldingModel` owns tracked physical-line fold regions. Stanza merges registered language-provider ranges, synchronous lexical ranges for `{}`, `[]`, cross-line block comments and named regions, and indentation-derived ranges; Workbench registers App Server parser folds through the same provider registry instead of exposing parser state as an editor capability. The deterministic merge keeps only nested or disjoint spans. User-created manual ranges persist through provider refreshes, while a refresh replaces only provider-owned ranges and never takes ownership of fold state. `EditorHiddenRangeModel` derives hidden physical lines from collapsed regions; the common view-model line collection filters wrapped rows and retains a header-row anchor for temporarily hidden selections. `FoldingController` maps Ctrl+Shift+`[` / `]` on Windows and Linux and Cmd+Option+`[` / `]` on macOS, while gutter controls use the same model. A collapse relocates active cursors hidden by that range to its header, before the viewport is reprojected. Ctrl/Cmd+K then Ctrl/Cmd+0 collapses all current regions; Ctrl/Cmd+K then Ctrl/Cmd+J expands them all; `[` / `]` recursively collapse/expand the innermost containing hierarchy; `1`–`9` select a fold level; `,` / `.` create/remove a manual range.

`TextDropController` accepts external `text/plain`, safe text reduced from `text/html`, and one bounded textual file. It inserts at the viewport's grapheme-safe hit target as one ordinary editor transaction. Paste behavior is not part of this contribution; non-text drops remain available to the hosting workbench.

`EditorInput.readOnly` flows into `CursorsController` rather than being treated as a textarea-only styling flag. The controller rejects every document command, undo/redo, and composition entry, so all browser adapters that submit through it retain selection/navigation/copy behavior without a path that can mutate the shared model.

`ViewLines` creates one text-only virtual row through `ViewLine`. `ViewLineOptions` is the shared DOM/GPU line configuration snapshot; `ViewLine` owns DOM text rendering and per-line browser geometry, `CharacterMapping` maps UTF-16 columns to rendered spans, `RangeUtil` normalizes browser ranges, and `DomReadingContext` caches their layout basis. Injected text reaches that row only through `TextModel.getLineInjectedText`, `ModelLineProjectionData`, and `ViewLineData`; its inline class and attached pointer data therefore share the same model/view mapping as wrapping and cursor movement. The separate screen-reader surfaces continue to read the source `TextModel`, so visual injection does not duplicate editable or announced document text. `ViewLayer` supplies the same visible-row reconciliation to line numbers, diagnostics, indentation guides, decorations, selections, and carets while each concrete view part owns its root and row DOM. Gutter width is derived from the current line-count digit width and participates in authoritative horizontal content measurement. `SelectionsOverlay` and `ViewCursors` consume the single `IViewModel` cursor state; they do not own a second selection model.

`ViewContentWidgets` owns document-positioned widget DOM, measurement, preferred above/below/exact placement, secondary anchors, focus-preserving offscreen layout, mouse-down suppression, and the separate editor-overflow root. `editorBrowser.ts` owns the public content-widget contract, while `View` and `CodeEditorWidget` expose add/layout/remove operations without taking ownership of caller-created widget state. `ViewOverlayWidgets` owns viewport-positioned widget DOM, and `WhitespaceOverlay` owns whitespace glyph rendering. GPU-only ruler rectangles and the GPU debug marker remain in their corresponding `rulersGpu` and `gpuMark` parts.

All editor feature presentation now enters the view through standard model decoration options. `DecorationsOverlay`, `LinesDecorationsOverlay`, `GlyphMarginWidgets`, `BlockDecorations`, `DecorationsOverviewRuler`, and `Minimap` each read only the options they own; `View` no longer accepts or aggregates browser decoration sources.

`LanguageDiagnosticDecorationBridge` converts one current-version diagnostic store into caller-owned model decorations. Error and Warning use their severity tokens; Information uses the accent token and Hint uses the hint class. Hover messages retain diagnostic source, code, and message in the model option. `DiagnosticHoverController` turns the current joined messages into a component-owned, non-modal rich hover and closes it on scroll. The viewport owns neither bridge, collection, store, nor model.

`DiagnosticNavigationController` uses F8 and Shift+F8 to select and reveal the next or previous current-version diagnostic, wrapping at either end. Every move also announces the selected severity, source/code when present, and message through the viewport live region.

`createStanzaSemanticTokenSource` adapts one caller-owned `LanguageTokenLineIndex` to Stanza's closed browser presentation vocabulary. Unknown worker token types are omitted by default; custom language resolvers may inspect token modifiers but must still return a named Stanza presentation, never an arbitrary CSS class. `getLineTokens` resolves one indexed line on demand. The viewport resolves only its target virtual range before replacing any row, so offscreen lines do not invoke the resolver and a resolver failure cannot partially update the visible window.

`projectStanzaSemanticTokenLine` validates each line snapshot before mutation, then creates text nodes and component-owned spans without parsing HTML. Joined DOM text must equal the model line exactly. Same-version token replacement rerenders visible line content without rebuilding rows; model invalidation removes stale spans before the normal model-version projection. The viewport owns only its event registration, not the source, common index, result store, or model. Semantic foregrounds come from registered `editor.token.*Foreground` theme colors owned by editor presentation. Legacy `editor.semanticToken.*Foreground` overrides are normalized only at the user-theme boundary.

`CompletionWidget` projects one caller-owned `SuggestModel` below the viewport's measured trigger position. It creates only component-owned listbox/option DOM, maps completion kinds through a closed text vocabulary, and projects `.visible` and `.focused`. Active-descendant ARIA state goes through `View.setAriaOptions` to the selected edit context instead of mutating its DOM from the contribution. `SuggestController` owns completion keydown and input interception. Mouse acceptance happens on mousedown so the synchronous focus rerender cannot detach the target before the edit is accepted.

The Suggest contribution installs one `LanguageCompletionService`, `SuggestModel` and `SuggestController` for the mounted editor model. `SuggestController` owns request cancellation, completion keyboard/input interception, and the `CompletionWidget`; Ctrl+Space sends an explicit Invoke request. Registered trigger characters send after the input transaction using the new version/caret; ordinary input refreshes an active incomplete result. Requests require one collapsed selection, and request errors do not undo a successful text edit. The session must observe the exact service-owned result store. `SuggestModel` and `SnippetSession` use `ICodeEditor` for selection events, commands and undo boundaries; model changes and editor disposal release the session and cancel pending resolution. Tabstop transitions close the current undo group. Read-only editors reject acceptance, choice edits and transform writes.

`SuggestController` owns the browser widget but not the session, service, registry, result store, editor, or model. Session disposal hides the widget; widget disposal clears its active descendant through the edit-context ARIA owner. Visual geometry and interaction state live in `../contrib/suggest/browser/media/suggest.css` and consume existing dialog, list-selection, foreground, border, and shadow theme tokens.

`EditorFindController` owns the per-session find/replace dialog and keyboard routing over `common/model/textModelSearch.ts` and `contrib/find/common/textSearchCommands.ts`. It projects matches through a caller-owned `TextDecorationCollection`; the viewport consumes that collection only through `SearchMatch`. Closing or disposing the controller clears this projection without changing the query or document. A non-empty selection at opening becomes a `NeverGrowsAtEdges` tracked scope. The Find in Selection control and Alt+L reuse that scope for both navigation and replace-all after match navigation has changed the editor selection. `media/findWidget.css` owns the dialog geometry and its `.visible` and `.checked` interaction states, while ARIA attributes expose the equivalent accessible state.

`GotoLineController` owns Stanza's Ctrl+G (Command+G on macOS) line/column dialog. Its common parser supports one-based `line[:column]`, backward negative values, and `::` UTF-16 offsets; while the dialog is open it previews by revealing the parsed position without mutating selections. Enter commits one collapsed primary selection, while Escape restores the pre-dialog scroll position. Its geometry and interaction states are owned by `media/gotoLineWidget.css`.

`LineCommentController` consumes Ctrl/Cmd+`/` only when the resolved language configuration has a line-comment token. It delegates all mutation, selection mapping, and undo grouping to `common/lineCommentCommands.ts`; the browser adapter only handles the key event and reveal. Unsupported languages keep the shortcut available to other browser or workbench handlers.

`BlockCommentController` maps Shift+Alt+A to the configured block-comment pair. Its common command handles range wrapping, pair removal, collapsed cursor placement, selection mapping, and undo; the browser adapter only filters the platform chord and reveals the resulting primary cursor.

`../contrib/linesOperations/browser/linesOperations.ts` owns Ctrl/Cmd+Enter, Ctrl/Cmd+Shift+Enter, Ctrl/Cmd+Shift+K, Shift+Alt+ArrowUp/ArrowDown, and Alt+ArrowUp/ArrowDown. Copy, move, and sort use the canonical `ICommand` files in that directory; delete and insert still form one selection-aware model transaction before revealing the primary cursor.

The same `linesOperations.ts` owner maps Ctrl+J (Command+J on macOS), reduces overlapping cursor/range targets, removes following indentation, retains one separator between non-empty fragments, and commits the resulting selections in one undo transaction.

`caretOperations/browser/transpose.ts` owns the macOS Ctrl+T `editor.action.transposeLetters` path and swaps complete graphemes in one isolated transaction. `linesOperations/browser/linesOperations.ts` separately owns `editor.action.transpose`, including its end-of-line exchange with the following line break; both paths reject range selections and resolve overlapping cursors before editing.

`WordWrapController` maps Alt+Z to a viewport-local word-wrap toggle. `View` always virtualizes through its visual-line source, so switching wrapping rebuilds row geometry, scroll limits, hit testing, selection projection, and rendering without changing the model or re-creating the editor. The `.word-wrapped` root class reflects that component-owned presentation state.

`OccurrenceSelectionController` handles Ctrl/Cmd+D and Ctrl/Cmd+Shift+L without browser-native selection logic. `ITextModel.getWordAtPosition` resolves the source word for a collapsed primary cursor, then the contribution adds the next exact match or replaces the set with every exact match; the controller only updates and reveals the live selections.

`WordHighlighterContribution` asks the first matching language document-highlight provider, falls back to `TextualDocumentHighlightProvider`, cancels stale requests, and applies read, write, or textual decorations after `occurrencesHighlightDelay`. `occurrencesHighlight` selects off, current-document, or all open editors sharing one language service; F7 and Shift+F7 move through the current ordered highlights without starting another request.

`EditorSelectionHighlighter` belongs to the multicursor contribution and handles only non-empty selections. It finds exact textual matches, excludes every active selection, rejects whitespace and disallowed multiline or over-limit text, and uses whole-word matching when the selected range equals the model-owned word at that position.

`MultiCursorController` adds one logical-line caret above or below every existing active cursor. Chords follow Windows (Ctrl+Alt), macOS (Cmd+Alt), and Linux's non-conflicting VS Code secondary binding (Ctrl+Shift+Alt); the common command clamps columns and rejects duplicate or overlapping new carets. Shift+Alt+I replaces non-empty selected rows with their VS Code-compatible line-end carets through the same DOM-free common command. Those actions and occurrence-selection changes record a bounded cursor-only history; `CursorUndoRedoController` in `cursorUndo.ts` restores or reapplies it without changing the document undo stack, with Ctrl+U on Windows/Linux or Cmd+U on macOS for undo.

`BracketMatchController` is a presentation adapter over the common `LanguageBracketPairs` index. According to `editor.matchBrackets`, it projects the current exact or enclosing collapsed-cursor pair as two `BracketMatch` decorations, reuses the viewport's normal virtual-row geometry, and owns neither the model, selection controller, index, nor decoration collection.

`BracketNavigationController` maps Ctrl/Cmd+Shift+`\\` through the same borrowed `LanguageBracketPairs`, so a go-to-bracket gesture has identical string/comment filtering to bracket highlighting. It owns only the chord, live selection update, and reveal; structural indexing remains common language state.

`BracketEditingController` maps Ctrl/Cmd+Alt+Backspace to an isolated common transaction that removes distinct valid bracket tokens. It never mutates the browser input surface directly and only consumes the chord if a bracket pair can be removed.

`browser/services/editorWorkerService.ts` owns the model-bound `VersionedEditorWorkerClient`; `EditorBrowserWorkerFactories` only composes module Worker transports. The first request sends a full immutable snapshot, later commits update the Worker mirror, and current requests reuse that version without copying the document. `EditorWorkerRequestExecutor` owns Unicode scanning, formatting-edit reduction, and numeric or well-known textual value navigation. Each browser factory result owns one Platform `BrowserWorkerClientPort`, which removes listeners and terminates its Worker on disposal. Direct `CodeEditorWidget` callers use the same client with an in-process executor; browser hosts and Standalone install the module Worker factory. All dedicated workers enter through `editor.worker.start.ts` and its single `start()` lifecycle.

The wire carries only versioned plain DTOs. Completion positions and ranges are reconstructed as realm-local common values before result application. Cancellation posts a cancel envelope, Worker errors poison the client so the coordinator can replace it, and the Platform port owns browser event listeners and Worker disposal without owning language state.

Protocol v4 retains the document-mirror contract: one full snapshot initializes the Worker Piece Tree. Subsequent model commits send ordered offset/length/text deltas, and requests reference the mirrored version without copying document text. A version gap falls back to full initialization; an invalid remote sync clears the mirror and poisons the client. Immutable Piece Tree snapshots keep cancelled old-version provider work isolated from later synchronization.

Protocol v4 additionally carries the client-confirmed per-lane result request ID. Syntax responses may use validated ordered item splices with independent line shifts; completion remains a full result codec. Result delta state belongs to the common wire client/server, not the browser port adapters.

The Worker also publishes its actual provider registry through a separate completion-catalog side channel. The browser client waits for the first validated revision, observes later registration/removal revisions, and exposes only immutable metadata to `LanguageCompletionService`. Custom Workers are prewarmed so the first typed trigger can wait for this handshake. Failure clears the old catalog; the next trigger rebuilds the Worker and waits for its new catalog instead of routing through stale renderer metadata.

A second completion-specific side-channel publishes named provider modules and accepts Active/Inactive requests. It never attempts to clone provider functions. Worker-local loading and atomic registration complete before the activation response, while the ordered port delivers the corresponding provider-catalog revision before the browser releases its first-request readiness barrier.

Deferred completion details use a third completion-specific side-channel. `resolveData` never enters browser state: the renderer sends only the list request/model/provider/item identity and receives normalized detail and documentation text. Focus changes abort the prior request. The selected option projects `.resolving` with `aria-busy`, then renders resolved documentation through text nodes; resolve failure leaves the candidate list and acceptance identity intact.

`EditorBrowserWorkerFactories` exposes general editor, syntax, and completion factories for the standalone runtime. Their clients use the Platform-owned `BrowserWorkerClientPort`, and every Worker realm enters through its dedicated common Worker main; general computations, syntax providers, and completion providers stay in independent failure domains. The syntax entry publishes `language.lexical`, owns its Worker-local language configuration registry, and updates the shared versioned line cache after each mirror sync before serving ordered token and diagnostic requests. `SyntaxModuleWorkerClient` waits for catalog publication and successful module activation before sending the first request. The Editor core owns registries, generic providers, request coordination, model mirrors, result codecs, and result application, but it does not install concrete language descriptions, editing configurations, or App Server adapters. Workbench and Standalone compose those registrations at their own startup boundaries. Workbench additionally owns parser provider registration, the TextMate grammar catalog, theme data, TextMate Worker creation, and catalog-change scheduling through `ITextMateService`.

Selection and decoration projection share `createStanzaRangeRectangles`, so end-exclusive ranges, selected line breaks, prefix measurement, and render-line clipping have one implementation. Presentation sources are resolved before the existing decoration DOM is reset; an invalid presentation therefore fails without partially replacing the current decoration layer.

`editorDom.ts` owns page, client, and editor-relative coordinate values plus the disposable mouse/pointer event factories. `MouseTargetFactory(ViewContext, IPointerHandlerHelper)` combines those coordinates with rendered view-line DOM, View Zones, widgets, scrollbars, and gutter parts, and returns the public `IMouseTarget` union directly. There is no second browser target protocol or conversion layer.

`hitTestStanzaEditorPoint` resolves horizontal text positions at adjacent caret midpoints. It uses grapheme boundaries when `Intl.Segmenter` is available and falls back to Unicode code points, so emoji and combining sequences are not split into arbitrary UTF-16 interiors. Prefix widths use the same `TextMeasurer` as rendering, including tab stops and shaped text. The grapheme implementation is owned by `editor/common/textSegmentation` and is also consumed by keyboard navigation; browser code does not define a second Unicode boundary policy.

`MouseHandler(ViewContext, ViewController, IPointerHandlerHelper)` owns the editor mouse lifecycle. It publishes context-menu, move, leave, up, wheel, drop, and drag events with one `IMouseTarget`; selection gestures are sent to `ViewController.dispatchMouse`, which owns character, word, line, extension, and additive-selection policy.

`PointerHandler` owns browser pointer capture and creates one disposable tracking session. `GlobalEditorPointerMoveMonitor` owns the window-level move/up/cancel and blur/key termination listeners; replacing, finishing, cancelling, blurring, or disposing a session releases them together. `MouseHandler` converts a captured pointer beyond the content bounds into `IMouseTargetOutsideEditor`, then selects `TopBottomDragScrolling` or `LeftRightDragScrolling`. Each operation scrolls through `ViewLayout`, renders synchronously, resolves the new viewport-edge target through `MouseTargetFactory`, and dispatches selection with no reveal feedback. Returning inside, releasing, cancelling, blurring, changing layout, or disposing stops the operation and its pending animation frame.

`KeyboardNavigationController` maps local keydown events into common character, word, line, page, and document navigation commands. Character, line, page, boundary and document moves enter `CursorMoveCommands` with the real `IViewModel`; word navigation calls the standard `WordOperations.moveWordLeft/moveWordRight` API with `CursorConfiguration`'s cached classifier. The same common owner supplies double-click/drag word selection, word-part movement, `getWordAtPosition`, and the ranges used by `deleteWordBackward/deleteWordForward`; browser code no longer parses a second set of word ranges or accepts a separate word-pattern callback. The controller uses explicit Windows/Linux or macOS routing, preserves Shift extension and multi-selection, retains preferred columns across vertical movement, and ignores composing, AltGraph, unknown, or already-handled events.

`ViewController` is the browser input owner: it selects one `EditorInputContext`, exposes focus, ARIA, screen-reader, composition and input contracts, and executes semantic commands. `View` independently owns layout and rendering, while suggest owns completion policy. The controller projects focus with `.input-focused`, requires the same `TextModel` as `View` and the cursor controller, and releases only what it owns.

Insert toggles the instance-local `.overtype` state. In that mode ordinary single-line input replaces following graphemes without crossing a physical line break; selected text and multiline input retain ordinary replacement behavior. Configured bracket pairs and IME composition keep their dedicated input paths.

Language-aware typing and Enter route from `ViewController` through `IViewModel.type` to `CursorsController` and `TypeOperations`. The common cursor layer owns auto-closing provenance, selection surrounding, indentation, language rules, and undo state. Optional bracket presentation does not participate in this editing path.

The session also derives folding from the same resolved configuration. Structural brackets and multi-line comments remain lexical folds; `foldingMarkers` adds language-owned named regions. Stanza's built-ins recognize `// #region` and `// #endregion` for ECMAScript, JSONC, and Rust. Marker patterns are common configuration, so browser code only projects and toggles the resulting folding model; a contribution must include its comment delimiter to avoid treating ordinary source text as a region.

`coreCommands.ts` registers editor-wide commands such as Select All through `editorExtensions.ts`. `LineSelectionController` owns repeated physical-line selection, while `../contrib/linesOperations/browser/linesOperations.ts` routes selected-line Tab and Shift+Tab through the canonical `ShiftCommand`. Collapsed Tab remains ordinary text input. Word-deletion `beforeinput` types build the standard `DeleteWordContext` and execute the ranges returned by `common/cursor/cursorWordOperations.ts`; there is no SelectionSet word owner. Ctrl/Cmd+L expands each selection through one more physical line using the DOM-free `../contrib/lineSelection/browser/lineSelection.ts` model; repeated use includes each non-final line break and retains the primary selection identity.

`language.lexicalContext` is provided by the language-analysis contribution for bracket matching and section headers. Its lexical index and token-aware context belong to the contribution's model lifetime. Input uses the common cursor's language configuration and model tokenization directly.

TextArea and Native EditContext own the default copy, cut, and paste event path. `editContext/clipboardUtils.ts` extracts selections, whole-line policy, syntax HTML and `vscode-editor-data`; an unhandled event writes that data or applies the matching paste through `ViewController`. `contrib/clipboard/browser/clipboard.ts` owns the standard Cut/Copy/Paste commands, menu placements and system `IClipboardService` fallback. Generic cursor deletion receives the already-decided cut ranges and has no clipboard dependency.

`DropIntoEditorController` owns text and bounded text-file drops. The standard eager `CopyPasteController` owns Ash's bounded text-file paste and non-comment `text/uri-list` paste extensions before the EditContext default handler runs. A file must have a plausibly textual MIME type or known text extension and remain within 5 MiB; neither path opens an arbitrary local path. An asynchronous file paste must still match the captured model revision and complete selection set, while a drop must still match its captured revision.

When a clipboard command cannot obtain writable browser event data, `clipboard.ts` asks platform `IClipboardService` for plain text. Browser and Electron implementations only adapt system text reads and writes; editor metadata and HTML remain in the editor layer. Permission denial, an empty result, a stale result, or a composition that takes ownership before completion leaves the model unchanged. Cut waits for a successful system write before editing the model.

Cut and paste are rejected while `CompositionController` owns a protected IME transaction; copy remains available. This prevents a browser clipboard event from invalidating or interleaving the provisional composition revision.

Empty-selection behavior comes from the standard `emptySelectionClipboard` editor option. Enabled mode copies complete lines and stores version 1 editor metadata; matching paste inserts through the same multi-selection `ViewController` path. Disabled mode leaves an empty selection empty rather than introducing a second clipboard policy owner.

`CompositionController` maps either edit-context composition stream to the standard `ViewController.compositionStart/compositionType/compositionEnd` path. The context supplies normalized provisional text and relative selection; the controller owns cancellation, `.composing`/`.ime-input` presentation, caret positioning, and one `TextDecorationCollection` for the active range. Escape, blur, disposal, and `IME.disable()` end the revision and undo provisional input; composition end commits it. Neither input implementation creates a second model or history path.

The active composition range is a standard model decoration with `edit-context-composition-primary`. `DecorationsOverlay` projects it through the ordinary decoration geometry and the collection clears it on end or cancellation. `View` and `ViewCursors` expose no composition-range setter and own no parallel tracked-range or overlay implementation.

The component reuses `base/browser/dom` for disposable events and DOM reset, `base/browser/geometry` for host measurement, and `base/common/lifecycle` for ownership. Its `.stanza-editor` root is styled by `widget/codeEditor/editor.css`, while internal line classes stay with their owning `viewParts/*/*.css` files; Workbench hosts may size the root and explicitly select `focusOutlineOwner: "host"` when their direct control owns one surrounding focus indicator, but must not override internal rows or focus state. The component projects stable `.active` state for the primary active line and `.primary` identity on the primary caret; CSS does not use ARIA attributes as visual selectors. Embedded presentations omit `.active` by default. Vertical padding participates in the viewport content height and row coordinates instead of being simulated by a host selector; left and right padding are component-owned text-measurement inputs, so wrapping, carets, placeholders, and pointer hits share one inset.

`FontMeasurements` owns normalized `FontInfo` readings, per-window caches, serialization, restoration, and invalidation. `charWidthReader.ts` fulfills regular, bold, and italic width requests in one DOM batch. The view keeps its private shaped-line measurer, while shared geometry depends only on the browser-neutral `TextMeasurer` contract.

`LineWidthIndex` takes one bounded synchronous first slice when the view is constructed, then schedules remaining non-wrapped lines through cancellable idle slices. Its current maximum is a lower bound until completion, never a claim about unmeasured lines. An edit cancels a pending generation and starts again from the current model version. After completion, transactions group edits by affected old line ranges, measure only their new line groups, and update a counted width set. Font refreshes restart this same policy because every cached width may have changed. Browser font-loading completion and explicit `refreshFontMetrics()` both trigger it.

The current renderer is fixed-line-height and mutates text only through the selected EditContext adapter, never through contenteditable DOM. Its resolved font size is explicit even when the host omits one, and font zoom scales that resolved pixel value instead of replacing it with an inherited `em` size. Focused carets blink through component-owned CSS when motion is allowed and remain visible when the user requests reduced motion. Canvas-unavailable runtimes use a font-size-derived fallback advance. For wrapped documents, `ViewModelLines` synchronously measures only a bounded first line slice, leaves later logical lines as one-row placeholders, and finishes their wrap measurement through cancellable idle slices before atomically publishing the complete projection. IME clause segmentation and mobile composition variants, semantic-token delta presentation beyond Stanza's closed modifier vocabulary, browser-driven wrapping, and empirical cross-platform screen-reader acceptance remain future work. Mixed-run BiDi asks `ViewLine` for browser `Range` rectangles and caret positions; its `CharacterMapping` selects the rendered child spans, `RangeUtil` reads their browser rectangles, and `DomReadingContext` supplies one cached coordinate basis for visible selection/caret, decorations, composition anchors, pointer hits, and vertical navigation. The textarea edit context provides the accessible IME/VoiceOver surface when the browser has no EditContext API, while the native implementation uses the browser editing surface; both share the explicit `dir` with the rendered line configuration. `SemanticTokenModifier` maps only standard declaration/readonly/static/deprecated/abstract/async names to component-owned classes; unknown provider strings are intentionally excluded from DOM projection. Syntax result deltas and relative token-line payload reuse are common-layer capabilities; this browser layer consumes only the current visible-line query and does not own their persistence policy. `DecorationsOverlay` renders standard model decorations from the current `RenderingContext`; there is no second browser-source projection in the production View assembly.
