# PDF 阅读、批注与 AI 内容接入

本方案供 PDF Viewer 后续单独实施。范围是查看 PDF、管理批注，以及让 AI 按用户请求读取 PDF 文字或图像；不引入通用文档编辑、排版或 Academy 文档模型。本轮只准备方案，不新增 SDK 接口、工具注册、Skill 或 Plugin manifest。

## 当前实现与待补范围

现有 PDF Viewer 已有 PDF.js 渲染、文本提取，以及高亮、墨迹和便签批注。批注由扩展自己的模型与历史管理，通过窗口获授权的文件服务保存到 `<file>.pdf.ash-annotations.json`，不改写原 PDF。Chat 附件预览是只读输入，不读取批注 sidecar。实现和已有验证范围见 [README](../README.md)。

这些客户端能力不等于 AI 已有可调用的 PDF 工具。尚需核对现有附件、文件工具与图像输入链路，确认哪些读取能力已经可复用、哪些确有缺口。仓库外导入和开发宿主的问题属于维护工具接线，不能替代 PDF 用户功能需求进入 SDK 实施队列。

## 功能边界与所有权

| 部分             | 负责内容                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| PDF Viewer 扩展  | 页面渲染、缩放与定位、文本选择、批注交互、批注模型与撤销历史；PDF 内容的解析与页码／区域映射。              |
| 现有宿主机制     | 文件与附件访问、资源引用、只读限制、保存冲突和取消／撤权；复用已有生命周期机制，不另建文档状态 owner。      |
| PDF 内容读取能力 | 将用户指定资源的文字或页面图像交给现有 AI 工具／附件链路；实现位置按现有解析能力和实际消费者确定。          |
| Skill            | 组织阅读、摘要、问答、页码引用和图文交叉核对流程，调用实际可用的能力；不承担 PDF 解析、文件存储或权限裁决。 |
| Plugin bundle    | 组织查看器、必要读取能力与 Skill 的分发和发现；安装、更新、授权继续由现有包管理拥有。                       |

Viewer 不需要 Academy 的结构化编辑、排版或文档事务 API。当前 `editor.resource.v1` 是页签／资源视图的内部承载契约，不能据此推导 PDF 需要文档编辑能力。

## 查看与批注

批注继续直接集成在 PDF Viewer 内，与其页面坐标、选区和定位保持一致；不为同一份批注建立独立业务扩展或第二份状态。保留现有 sidecar 格式、源 PDF 不变和条件写入机制。

后续围绕实际操作检查：添加／删除／撤销批注、保存与重开恢复、原 PDF 变化后的定位、并发保存冲突、只读文件与附件、关闭时未保存批注的处理，以及停用／撤权后保留草稿并冻结旧视图。未保存批注当前属于 pane；不得把“保存前关闭”直接宣称为已有恢复保证。

将批注嵌入 PDF 或导出带批注 PDF 暂不纳入；等到具体使用需求成立再选择实现，不以此扩展成 PDF 内容编辑器。

## AI 读取 PDF

先以“用户指定 PDF 和页范围 → 读取内容 → 回答并引用页码”作为一个完整切片：

1. 优先读取已有文本层，支持整份文件的有界读取、指定页范围和用户选中区域。保留页码、区域定位与源文件版本，避免回答引用另一版文件。
2. 图表、复杂版式或无文本层页面按需提供指定页面／区域的渲染图，复用已有模型图像输入。页面渲染图与原始嵌入图片是不同能力；先满足页面／区域阅读，不预建任意图片提取接口。
3. 扫描件可先交由具备图像理解能力的模型阅读；只有真实任务需要可检索文本时再接可选 OCR。没有 OCR 时明确说明，不把空文本当成无内容。
4. 批注可作为用户明确选择的辅助上下文。区分已保存批注与当前视图草稿，不自动把未保存批注同步成后端状态，也不让 AI 默认改写或删除批注。

读取应覆盖未在 Viewer 打开的文件；不能要求 Agent 借用 Renderer、DOM 或活动编辑器才能读取 PDF。Viewer 的选区可作为显式阅读上下文，但文件解析与 AI 调用的可用性不能依赖视图常驻。无界全文、整份高分辨率页面图和重复附件上传都不作为默认方式；按任务分批，并为页数、输出字节和图像尺寸设实际预算。

AI 调用沿用现有文件／附件授权和工具取消机制。Skill、安装或打开 Viewer 都不授予额外目录权限，也不自动将文件发送给远端服务；发送内容遵循现有模型调用与数据策略。PDF 正文、图片文字和批注都是待分析数据，不作为执行指令。

## Skill 与 Plugin 组合

适合以面向“PDF 阅读与批注”的 Plugin bundle 提供：Viewer 负责用户界面，读取能力供 AI 使用，Skill 描述阅读方法。具体包布局和声明沿用 [Plugin 包与来源授权](../../../docs/plugins.md)；只有实际能力和调用链确定后才增加包声明与 `SKILL.md`，不先注册空工具或编造工具名。

Skill 的初始流程可以是：确认文件和问题 → 按页读取文字 → 必要时查看页面图 → 对照批注与原文 → 用页码引用回答。文献检索、参考文献入库和引用插入由相应独立扩展提供，不成为阅读任意 PDF 的依赖。

复用唯一包管理 authority 和各能力的启用、授权与撤权路径，不创建第二份安装记录。Skill 可用不表示 Viewer 已获执行许可；查看器缺失时，已获授权的 AI 文件读取也不应依赖它启动。现有原生客户端仍受签名发布者、资源摘要和 Renderer 准入限制，不能仅靠 Plugin manifest 获得执行权限。普通第三方 Plugin 的可用范围需按实际支持验证，不将本方案写成现有分发能力。

## 单独实施的准备顺序

- 核对真实 PDF 和现有读取链：选择文本 PDF、含图表 PDF、扫描件，记录当前文字读取、页面图像输入和页码引用各自能否完成；先复用已有工具。
- 验证现有批注闭环与生命周期，区分已实现行为、缺陷和新增需求；只围绕复现的阻碍修复，不新增通用文档模型。
- 选择一个最小 AI 阅读场景。若现有能力已够，只补 Skill 或接线；确需宿主支持时，再按 [SDK 能力开放原则](../../../docs/editor-extensions.md#sdk-能力开放原则)确定最小领域契约，不开放原始后端连接。
- 用真实文件验证文字／页面图及页码对应、取消、撤权、资源版本变化、配额与失败反馈；保留源 PDF 字节和批注保存／冲突回归。再验证 Plugin 安装／启用／授权／卸载及 Skill 缺少可选能力时的行为。

F5、`.ashx` 和通用仓库外开发工具继续按原暂停状态处理，不作为本功能的前置。当前没有新增 AI 读取工具、OCR、实际 Skill 或 Plugin 发布，以上场景也尚未因本方案而通过验收。
