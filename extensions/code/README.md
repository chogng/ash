# Code editor capability

`ash.code` is a built-in independent Rust extension. Its executable is `ash-code-editor`; it is separate from the `ash code` CLI/TUI product host.

The Rust SDK registers the typed `editor.contributions.v1` DataChannel. A `describe` request carries the client's language; its version-1 response identifies `browser/editor.ts` and the SHA-256 of the package's TypeScript/CSS sources. The shared client-editor bridge checks the admitted package, version and source digest before loading that product-compiled module. It does not evaluate downloaded source or hand an extension the backend connection.

`browser/registration.ts` collects existing contribution, action, command and registration declarations. Importing the client module does not activate those declarations. The bridge owns their live leases, including menus, keybindings, command implementations and inline-edit metadata. Editors created before admission can receive the batch without replacing their model. Retirement disposes pending/controllers, scoped services, requests and model analysis; reenabling creates a fresh lifetime.

TextModel owns the only text buffer, versions and undo history. The package supplies optional tokenization, semantic tokens, bracket analysis, guides, diagnostics and synchronous language editing policies through the text-model feature contract. Pair insertion/deletion, composition interception and language indentation stop when their model policy retires. Minimap and indentation-guide overlays use leased view factories; the base renderer and its single viewport/layout remain shared. Stable event and token-source identities let existing views observe arrival and retirement. Host syntax services provide sessions and theme metadata; the package creates its renderer analysis cache. File models, dirty state, backups and save/reopen remain with the host.

Chat supplies its completion providers and widget container through editor options. The package owns the completion service, session and UI. Restricted embedded editors select contribution IDs and follow the same provider lifetime. Shared text utilities, the input adapter, dependency injection and the base SelectBox stay with their common owners.

Validation includes the real Rust stdio executable, the shared bridge, repeated enable/disable cycles, text/history preservation, Chromium editor assembly and existing feature regressions. Browser use requires an authorized backend capable of hosting the Rust process. Third-party execution/isolation and platform-specific physical IME, screen-reader and remote-environment acceptance retain their existing product constraints.
