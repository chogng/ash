# Sessions 设计理念

Sessions 让用户发起工作、跟进 Agent、处理需要自己决定的事项，并查看结果。界面围绕正在进行的工作组织，让用户随时知道：我在哪个会话里、工作进行到哪里、接下来能做什么。

本 Skill 是 Sessions 的完整设计规范，适用于 `app-ts/src/ash/sessions/**`，以及其他目录中明确为 Sessions 提供的产品界面。它独立维护，不继承 `design-philosophy` 或 Workbench 的视觉规则；规则相同也在这里完整定义。图标库、控件和主题服务是实现工具，其默认外观不决定 Sessions 的设计。

以下是设计要求，不能据此宣称现有界面已经符合规范。修改 UI 时落实受影响的要求；本 Skill 的创建不自动授权改造其他界面。产品状态、权限和生命周期仍遵守仓库及所属模块的契约。

## 1. 工作是界面的中心

- 当前会话的内容与下一步操作占据主要注意力。导航、设置、模型信息和执行细节按其用途分配位置与强调程度。
- 用户需要回应的请求持续可见，并说明要决定什么。运行中的后台工作使用克制的状态反馈；完成与失败有明确结果，不能只留下停止的动画。
- 控件是否常驻取决于用户是否需要随时发现或使用它。新建会话、发送和当前状态有稳定位置；条目整理动作可以在悬停或键盘聚焦时出现。
- 等待、无内容、无搜索结果、加载失败分别说明原因与可执行的下一步。未提供的能力不占据可点击入口，不用空页面表达可用功能。

## 2. Session 与 Chat 的层级

Session 是一项工作的上下文，Chat 是其中一段对话。标题、导航和关闭动作必须让用户看出自己正在操作哪一层。

- 侧栏以 Session 为选择单位，主区域呈现当前 Chat。Session 名称只在需要识别工作上下文的位置强调。
- 单个 Chat 可见时，避免两个相邻标题重复同一个名称。多个 Chat 可见时，各自保留可区分的标题及关闭入口，Session 标题承担共同上下文。
- Chat 数量仅在帮助理解或切换多段对话时显示。创建时间、模型和目录等信息不得与标题争夺第一层注意力。
- 关闭可见 Chat、归档 Session、停止执行是不同操作。分别命名和反馈，不能用一个关闭图标承载多个含义。
- 选中会话、键盘焦点、正在执行、需要回应分别表达，不能共用一个高亮来让用户猜测。

## 3. 导航与 Activity Bar

Activity Bar 是 Sessions 的产品页面导航。页面之间保持稳定顺序与入口位置；页面内工具放在对应内容附近。

| 项目 | 普通模式 | 紧凑模式 |
| --- | --- | --- |
| 导航图标 | 24px | 16px |
| 按钮点击区域 | 36 × 36px | 28 × 28px |
| 相邻按钮间距 | 8px | 4px |
| 高亮区域 | 与点击区域一致，8px 圆角 | 与点击区域一致，6px 圆角 |

- 上表适用于纵向导航和放在侧栏顶部、底部的横向导航。窄窗口通过布局调整分配空间，不能随意缩小单个图标。
- 未选中入口背景透明；悬停有轻量背景反馈；选中入口有持续高亮。选中与悬停必须可区分。
- 有匹配的线框与实心图形时，未选中用线框，选中用实心；没有对应实心图形时保持同一图形，用高亮表达选中。语义相同的入口在所有位置使用同一图形。
- 图标按钮必须有可翻译的名称、悬停提示和可访问名称。可见页面选择使用 `aria-current="page"`；账户入口表达菜单展开状态。
- 账户等窗口操作与页面导航分组，保持稳定位置。状态徽标表示真实待处理事项，避免装饰性圆点和持续闪烁。

导航图标较大，是为了在独立入口中提供识别度。12px 图标属于行内辅助信息，不能用于主要页面导航。

## 4. 会话列表与密度

会话列表帮助用户找到工作、判断状态和继续处理。它应支持扫描名称与状态，同时保留足够大的选择区域。

- 普通列表中，单行条目至少 48px 高；有第二行摘要或状态时至少 64px 高。紧凑模式分别至少 36px、48px。内容增长时允许条目增高，不能裁掉关键信息。
- 标题是首要信息，第二行只放有助于识别工作的摘要、来源或状态。时间与计数降低强调程度。
- 头像用于识别人、Agent 或工作来源；没有识别用途时省略。不要给每个普通会话放相同的醒目圆形图标。
- 搜索与新建会话位于列表入口，普通模式控件至少 36px 高，紧凑模式至少 28px 高。搜索框可伸缩，新建入口保持可发现。
- 选中条目使用连续的轻量背景；错误与待回应状态有文字或形状辅助，不能只依赖颜色。
- 悬停动作不得挤动标题。键盘聚焦时同样可操作；触屏通过条目菜单提供这些动作。
- 保留用户的选择和滚动位置。后台状态更新不能自动重排用户正在操作的条目。

紧凑模式减少留白和辅助信息，不减少状态含义、可操作性或文字可读性。

## 5. 对话、输入区与结果

- Sessions 与常规 Workbench 的输入框分别定义悬停、聚焦、阴影和过渡。共享输入操作时，Sessions 通过显式的外观变体启用卡片反馈，保持 Workbench 默认输入框的交互与外观独立。
- 对话内容按消息、执行进展、需要决定的事项和结果组织。长工具输出默认提供摘要与展开入口，失败原因和需回应内容直接可见。
- 消息正文保持适合阅读的行宽；宽窗口不把普通文字无限拉长。代码、表格和差异可使用更宽的内容区域，并各自处理溢出。
- 输入区是继续工作的稳定入口，使用独立表面、12px 圆角、浅灰边框和浅阴影，呈现轻盈的卡片感。焦点强调这个输入区，不让整个页面一起高亮。
- Chat 与 Code 输入卡片的悬停和聚焦使用同一套浮起效果：边框变为灰色，阴影加深并柔和展开。输入区内仍有焦点时，鼠标移开也保持浮起；只有焦点和悬停都结束后才回落。输入光标与按钮的键盘焦点保持清晰，卡片不叠加蓝色边框与外圈。
- 输入区随内容增长，达到可用空间限制后内部滚动。不要用固定的大块空白替代输入容量；空会话与已有对话保留一致的输入控件关系。
- 附件和上下文位于编辑内容附近；模型、模式等设置降为辅助操作。发送动作明确可见，执行中提供明确的停止动作；保留用户未发送的草稿。
- 自动滚动只跟随正在查看末尾的用户。用户向上阅读时保留阅读位置，以明确入口提示有新内容。
- 权限请求紧邻对应操作，写清操作对象、影响和选项。不能把待确认事项埋入工具日志。
- 窄窗口优先保留当前对话和输入区，侧栏通过明确入口收起或打开。多 Chat 布局必须保留活动上下文和切换方式。

## 6. Sessions 的视觉尺度

尺度按这里的角色选择。使用已注册且数值符合要求的 token；缺少适当 token 时在所属位置注册，不把其他产品的默认值当作设计依据。

### 图标与点击区域

| 角色 | 图形尺寸 | 使用要求 |
| --- | --- | --- |
| 普通页面导航 | 24px | 与普通工具动作区分 |
| 工具动作、紧凑导航 | 16px | 默认操作图标 |
| 行内元数据、辅助标识 | 12px | 有 Compact 图形时使用对应版本 |

图形尺寸与点击区域分别确定。普通工具动作点击区域至少 28 × 28px，紧凑工具动作至少 24 × 24px；触屏操作至少 44 × 44px，包含留白。不能用放大图形代替增大点击区域。头像和内容插图按内容角色设计，不套用操作图标尺寸。

### 字体与留白

| 角色 | 字号／字重 |
| --- | --- |
| 页面标题 | 18px／600 |
| 空状态主标题 | 26px／600，仅在需要独立引导时使用 |
| 会话标题、正文、输入文字 | 13px／400；需要强调的标题用 600 |
| 控件标签 | 12px／400 |
| 元数据 | 11px／400 |
| 徽标计数 | 10px／400 |

以上是界面文字的默认尺度；消息富文本和代码遵守所属内容的字号设置。放大与缩放不能丢失内容或操作。正文行高至少 1.4，较长段落使用 1.5；紧凑模式不缩小正文和输入字号。

间距使用 0、2、4、6、8、10、12、16、20、24、28、32、36、40px。控件内部常用 4–8px，相关内容之间 8–12px，区块之间 16–24px。通过分组留白表达关系；窗口布局和内容测量得到的尺寸按实际约束计算。

### 圆角与边界

| 表面角色 | 圆角 |
| --- | --- |
| 小型工具按钮、标签 | 4px |
| 紧凑导航、紧凑输入控件 | 6px |
| 标题栏工具按钮、普通导航、搜索框、普通会话条目 | 8px |
| 对话输入区、独立浮层 | 12px |
| 有实际身份含义的头像、胶囊 | 全圆 |

圆角表达组件角色与大小；不要依据“浮得越高就越圆”推导所有表面。同类组件保持一致。普通边框和分隔线为 1px，焦点与状态标记按可识别性设计。内部区块优先用留白分组，需要明确区分可独立滚动或调整大小的区域时再使用边界。

### 呼吸感

呼吸感来自舒展的留白、轻盈的表面和自然的交互节奏，让用户在阅读与操作之间平顺地切换。

- 相关内容靠近，独立区块之间留出空间。边框和阴影保持克制，让内容与下一步操作占据主要注意力。
- 卡片静置时轻，用户接近或开始操作时柔和浮起，持续操作时保持稳定，离开后自然回落。通过边框与阴影表达层次，保持卡片尺寸、内容位置和点击区域稳定。
- 进入和退出都使用短暂、连续的缓动，快速来回交互时从当前外观继续过渡，避免闪烁和突变。动效随真实交互发生，不使用持续循环的明暗、缩放或位移动画模拟“呼吸”。

### 悬停提示（Tooltip）

- Sessions Agent Window 的悬停提示使用 12px 大圆角，不显示指向控件的三角形箭头。`sessions.tooltip.background` 与 `sessions.tooltip.foreground` 的默认配色在浅色、深色和高对比度主题下均为黑底白字；`sessions.tooltip.border` 在高对比度下使用白色边框。Sessions 在窗口内将这些 token 映射给 tooltip，不能修改共享 Workbench tooltip token 的注册值。普通边框、阴影、字号、行高和内边距与共享 Workbench tooltip 保持一致。
- Sessions 专属的 tooltip 外观集中在 `app-ts/src/ash/sessions/browser/media/workbench.css`，以 `.ash-sessions-window` 限定作用范围。Tooltip 挂在窗口根节点下，不在触发按钮或标题栏内部；样式不能依赖这些控件的后代关系。

### 颜色、状态与动效

- 颜色来自主题变量，分别表达页面、辅助区域、输入表面、选中、悬停和语义状态。选中状态不能直接套用强调按钮的强背景。
- 错误、成功、等待与需回应状态同时有可读名称或可识别标记。深色、浅色和高对比度主题都必须清楚；高对比度下使用明确轮廓，不依赖浅色背景差异或阴影。
- 动效只用于说明变化或维持位置感，短暂且可中断，尊重减少动态效果设置。进度动效结束后保留可识别的最终状态。
- 选中、禁用和执行状态分别设计。悬停与聚焦表达同一操作区域时，共用表面反馈，键盘焦点仍须清晰可辨。禁用控件说明不可用原因，不能让透明度承担全部表达。

## 7. 文案与可访问性

- 使用用户能理解的动作与状态名称。英文界面用 sentence case，保留专有名称；文案、提示、错误和可访问名称接入所属端 NLS。
- 页面图标配名称提示；有空间的业务动作优先显示文字。删除、归档、关闭与停止用明确动词。
- 所有操作可通过键盘完成。列表与导航按控件语义支持方向键，Tab 按逻辑顺序进入区域，弹出菜单和浮层关闭后恢复焦点。
- 键盘焦点始终可见，鼠标交互不留下无意义的焦点装饰。选中和焦点的表现保持可区分。
- 标题截断使用省略号，并提供完整名称的悬停提示和可访问名称；正文、权限请求和错误原因不能只提供截断文本。
- 状态变化按紧急程度播报，流式输出不能逐字打断用户。新交互区域提供无障碍帮助；有复杂内容时提供可访问文本视图，并允许控制帮助提示的播报。

## 8. 评审与验证

评审时先说明用户正在完成什么，再说明具体阻碍和相关规则。例如：“单 Chat 页面重复显示相同标题，用户难以理解层级；应保留工作上下文，去掉重复的 Chat 标题。”

实现验证使用 Playwright 驱动 Browser 与 Electron 的实际交互，检查普通与紧凑模式、窄窗口、键盘操作、主题、长标题，以及本次涉及的任务状态。通过 DOM、焦点、可访问属性和计算样式定位问题，不以截图代替调试或行为验证。只报告实际运行且成功的检查。

输入卡片的反馈验证覆盖静置、仅悬停、仅聚焦、悬停与聚焦同时存在，以及两者都结束后的回落。验证输入时移开鼠标仍保持浮起，边框与阴影不会跳变或挤动内容；同时检查高对比度下的清晰边界，以及减少动态效果设置下的静态状态。

修改本 Skill 应源于明确的产品设计决定。发现代码偏离规则时修正代码；不能为了让现有实现通过评审而反向调整规则。涉及界面行为的要求由相应行为测试验证，Skill 不保存逐次问题处理记录。
