# Code 对齐

仅在目标位于 `app-ts/src/ash/code` 时读取。共同的对比规则、单一实现、删除确认和验证规则由主 `SKILL.md` 负责。

## 对应范围

- 本地根目录：`app-ts/src/ash/code`
- 上游根目录：`../vscode/src/vs/code`
- `code` 是桌面和浏览器产品入口，负责选择模式、装配低层服务、创建窗口并启动对应工作台，不拥有可下沉到 `platform`、`editor` 或 `workbench` 的领域实现。

## 对齐边界

- 按具体入口与运行环境完成整批对比。VS Code 已有而 Ash 缺失的启动、窗口或装配职责直接补齐；尚无决定的仅 Ash 产品标识、模式选择和后端装配入口请求用户决定，已有决定的入口可以继续承接确认范围内的产品职责。
- 入口文件的 import 集合和执行顺序决定实际装载内容；名称对齐必须同时核对启动顺序、窗口生命周期、失败语义和退出释放，不能只重命名类或函数。
- 对应实现已经存在时直接迁移该入口和调用方，不新增第二个应用对象、启动函数、窗口注册表或转调层。
- 可复用服务和状态回到正确的低层 owner，`code` 只保留产品装配与进程入口职责。

## 验证

- 比较目标入口的完整 imports、直接调用方、启动参数、窗口创建与释放顺序。
- 检查浏览器和 Electron 入口是否各自只装载对应环境代码，并确认没有旧启动入口或重复注册继续生效。
- 运行相关 `code/test` 测试和覆盖入口的最小 TypeScript 检查；涉及窗口流程时验证实际启动与关闭行为。
