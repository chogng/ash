# Platform 对齐

仅在目标位于 `app-ts/src/ash/platform` 时读取。共同的对比规则、单一实现、删除确认和验证规则由主 `SKILL.md` 负责。

## 对应范围

- 本地根目录：`app-ts/src/ash/platform`
- 上游根目录：`../vscode/src/vs/platform`
- `platform` 拥有跨层共享的服务契约、服务注册和基础设施，不拥有编辑器行为、工作台组合、应用启动或 Sessions 产品 UI。

## 对齐边界

- 先按服务或能力目录完成整批对比。VS Code 已有而 Ash 缺失的服务进入待补队列；尚无决定的仅 Ash 服务必须连同职责、注册和调用方清单请求用户决定。
- 对应服务必须对齐公开接口、服务标识、注册位置、生命周期、错误语义和生产调用路径。调用方使用完整且规范的服务契约，不为生产代码新增局部子集接口。
- 服务的环境无关契约放在 `common`，具体实现放在对应运行环境目录。不得让 `platform` 导入 `editor`、`workbench`、`code` 或 `sessions`。
- 用户确认的 Ash 产品服务使用自己的准确名称和文件图，可以继续承接确认范围内的 Ash 专属职责，但不能占用职责不同的 VS Code 路径，也不能作为对应职责的桥接层。

## 验证

- 对目标服务目录批量比较文件、imports、exports、服务注册、实现和全部生产调用方。
- 证明服务只有一个标识、一个有效注册路径和一个状态 owner；检查旧接口、重复注册与聚合入口已经退出生产调用链。
- 运行服务自己的定向测试和覆盖调用层的最小 TypeScript 检查；涉及释放时同步验证注册对象和资源的生命周期。
