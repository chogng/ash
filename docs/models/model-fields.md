# Ash 模型字段

Ash 接入多个 provider，通过适配器把不同来源的模型资料和调用协议转换为自己的领域契约。模型目录、`ModelInfo`、`ModelRequest`、`ModelResponse` 以及客户端模型中的字段，其名称、类型和语义由 Ash 定义与维护；它们不是某一家 provider 的原生 `models` 响应，也不是厂商共同制定的标准。

字段属于 Ash 契约，不意味着字段值都由 Ash 自行决定。模型容量、模态和参数支持范围需要厂商资料或所选接入的实际证据；用途推荐、基础指导和执行策略则可以由 Ash 赋予。两种来源必须分清。

## 字段的来源与用途

| 类别                     | 当前例子                                                                      | 数据来源与负责方                                                                    | 与厂商请求的关系                                                                    |
| ------------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 厂商事实的规范化表达     | 已确认的容量、输入模态和推理参数支持范围，例如 `settings.input_modalities`    | 静态声明依据厂商资料维护，动态观察由目录适配器转换，`models-manager` 合并和解析     | 用于选模、能力检查和请求准备；字段名不因此直接进入上游报文                          |
| Ash 赋予模型的内部元数据 | `recommended_for`、`model_messages`、`default_reasoning_effort`               | Ash 模型目录维护用途推荐、基础指导和请求默认值；`models-manager` 负责指导选择与冻结 | 用途标记只供 Ash 选择；默认值和指导正文经调用方组装后可以影响请求，元数据容器不透传 |
| Ash 用户偏好与执行策略   | 默认执行预算、`long_context` 偏好、自动压缩阈值、Advisor 的模型选择和调用预算 | 静态声明维护预算策略，配置负责方保存偏好，模型管理与执行负责方解释并应用            | 可以影响模型选择、预算或最终调用参数；不是厂商天然提供的模型属性                    |
| Ash 运行时派生值         | `usable_context_window`、`available_context_window`                           | App Server 的 `ModelContext` 根据有效模型资料、配置和 Core 预算计算                 | 供 Ash 展示和执行消费，不作为同名厂商请求字段发送                                   |
| Ash 单次调用意图         | `ModelRequest.max_output_tokens`、`ModelRequest.reasoning`                    | 调用方经过模型与接入约束检查后构造                                                  | 经对应协议编码器转换为厂商接受的字段、位置和取值                                    |

这是一种语义分类，不要求把所有相关数据放进模型目录。用户偏好、账户权益、运行时预算和调用记录继续由各自负责方维护，不能因为界面把它们显示在同一模型下就另存一份。

同名字段在不同契约中也可能表示不同阶段的值；不能仅凭字段名判断其来源。字段说明应区分原始容量证据、Ash 选定的默认预算、配置覆盖和最终生效结果。

Ash 的内部标记不能反过来作为厂商能力的证据。例如，推荐用于 Advisor 不证明模型拥有某种额外推理能力；Ash 选定的默认档位也不能自动称为厂商默认值。未知、明确不支持和 Ash 尚未实现分别表达，不用型号名称、空值或统一标签猜测支持范围。

## 适配边界

| 边界                    | 职责                                                                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 厂商目录 → Ash 模型资料 | `model-provider/src/catalog/` 的来源适配器读取厂商响应，转换身份、容量、能力和默认值等已知信息，保留来源与接入范围；`models-manager` 管理规范化观察的合并、缓存和快照 |
| Ash 调用 → 厂商请求     | `model-provider` 选择适配器、接入协议、上游模型 ID 和认证目标；`ash-api` 按具体协议编码字段与枚举值                                                                   |
| 厂商返回 → Ash 调用结果 | 协议解码器把返回值与流事件转换为 Ash 的响应、用量、错误和事件契约                                                                                                     |
| Ash 后端 → 客户端       | App Server DTO 是 Ash 的传输投影，客户端适配器再转换为客户端领域类型；生成的传输 DTO 仍不是厂商模型对象                                                               |

同一 provider 可以提供不同协议，不同 provider 也可以共用兼容协议。字段是否可映射，要按具体模型、协议和接入约束判断；名字相同不证明语义相同，名字不同也不妨碍表达相同的 Ash 语义。无法保留差异时应明确建模或拒绝该组合，不能静默伪造能力或丢掉请求意图。

仅供 Ash 内部消费的字段必须留在内部。新增一个模型属性不会自动增加厂商请求参数，也不会自动取得对应账户权限。基础指导和执行策略可以影响发送内容，但应先由负责方组装成既有调用意图，再交给编码器；不得把整个模型条目、内部元数据对象或 App Server DTO 序列化进厂商报文。

厂商原生字段名和枚举值由其协议约束，在对应编解码边界保持准确；Core、UI 和通用模型服务通过 Ash 领域契约消费这些能力，不自行拼接各家的报文字段。

## 当前实现的例子

### 输出预算与推理档位

Ash 的 [`ModelRequest.max_output_tokens`](../../crates/protocol/src/model/invocation.rs) 表达一次调用的输出预算。仓库中的公开 [Responses 编码器](../../crates/ash-api/src/endpoint/responses.rs) 使用 `max_output_tokens`；[Chat Completions](../../crates/ash-api/src/endpoint/chat_completions.rs) 和 [Messages](../../crates/ash-api/src/endpoint/anthropic.rs) 编码器使用 `max_tokens`。具体接入仍各自检查参数支持与默认行为。

同样，Ash 的推理枚举 `ExtraHigh` 与 JSON 值 `extraHigh`，在现有 Responses 编码路径中映射为 `xhigh`。这是明确的协议转换，不表示所有 provider、型号或接入都支持该档位，更不表示可以把 Ash 的枚举值原样发送给所有厂商。

### 内部推荐与指导

`recommended_for` 由 Ash 维护，供 Advisor、Review、Commit 等用途的选择器筛选；它不授予执行权限，也不作为厂商请求参数。`model_messages` 保存 Ash 为模型配置的基础指导，选择后的正文可以进入最终模型指令；厂商收到的是协议编码后的指令内容，不是这个本地字段结构。

`default_reasoning_effort` 是 Ash 选择的请求默认档位，必须来自已声明的可选集合；它不自动代表厂商省略参数时采用的默认值。其他 `settings.default_*` 字段同样按各自的 Ash 定义解释。

### 派生输入预算

静态 `StaticModelSpec.context_window` 表达 Ash 的默认执行预算；`models-manager` 根据容量证据和偏好解析最终的 `ModelInfo.context_window`。两者都不能仅因字段名相同就当作厂商 `models` 响应中的原始值。

`usable_context_window` 表达 Ash 扣除输出预留、安全余量并应用自身预算策略后的硬输入容量；`available_context_window` 表达进一步受自动压缩阈值约束的输入预算。这些是 Ash 的运行时计算结果，不能标注成厂商直接返回的容量字段。计算由同一个 [`ModelContext`](../../crates/app-server/src/local/model_context.rs) 负责，客户端读取结果，不另算一套。

## 字段文档与维护要求

新增或调整字段时，字段定义与对应说明应回答：

- **Ash 语义**：类型、单位、允许值、默认值，以及省略、`null`、`false` 等值各表示什么。
- **来源与负责方**：是规范化的外部事实、Ash 内部赋值、用户偏好还是派生值；谁保存、验证、合并或计算，适用于哪个模型、接入和作用域。
- **消费与发送**：哪些 Ash 调用方实际使用；是否只在内部通行，是否影响指令或预算；需要对外编码时，说明协议字段、位置、取值映射和适用条件。
- **依据与实现状态**：厂商事实附具体型号与接口依据，区分已实现映射、尚未接入的声明和设计建议；Ash 自有策略说明设计理由，不能伪装成厂商要求。
- **同步与验证**：按影响更新解析、映射、持久配置、客户端和测试；内部字段不应出现在上游报文，协议映射应验证实际编码结果。

字段和接口的准确集合以 Rust 定义及其生成 Schema 为准，不在本文另建完整字段副本。[静态模型声明](../../crates/model-provider-info/README.md#统一静态模型清单)说明当前可解析格式；[通用模型声明规范](../../crates/model-provider-info/docs/model-template.md)提供厂商接口对照与字段提案，其中的提案不自动成为已实现契约。
