# Agent Window 文档工作区与 Code IDE 边界

> 状态：产品范围已确定，Academy 的独立入口仍是候选方案。先完善 Stanza 基础；Academy 从插件侧载入，仅在 Agent Window 中使用。已有独立包与共享编辑器桥不等于宿主范围已经收敛，本文不宣称独立界面或 IDE 旧接线退出已经完成。当前实现见 [Stanza](../../src/ash/editor/README.md)、[Academy](../../extensions/academic/README.md) 与 [Workbench](../workbench.md)；具体剩余动作见[根 TODO](../../TODO.md#work--通用文档--todo)。

## 产品范围

Stanza 是共享编辑器基础。Code IDE 面向代码；Agent Window 组织 Agent 对话与插件提供的工作流。Academy 拥有普通富文档、Academic 论文和频道笔记，由 Agent Window 消费已注册能力，不扩展为 IDE 的另一套文档工作台。

| 层级或宿主          | 负责的能力                                        | 装配边界                                                             |
| ------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| Stanza              | 文本、坐标、事务、版本、历史、基础输入与视图机制  | 不识别 Academy 或产品窗口类型                                        |
| Code IDE            | 代码编辑、工程、终端、测试、调试与编码对话        | 不新增 Academy 入口、菜单或专用布局；既有文档接线需按生命周期收敛    |
| Agent Window        | 对话、资源与插件工作流的呈现和恢复                | 按可用能力消费 Academy；独立图标与界面尚未选定                       |
| Academy 插件        | 富文档 Schema、结构编辑、视图、排版、引用与 codec | 经公开 SDK、扩展宿主与通用编辑器桥接入；缺失或停用不影响基础编辑     |
| 共享 Workbench 服务 | 编辑器引用、工作副本、文件、保存、备份与冲突      | 可由两个产品宿主复用；服务位于 Workbench 不代表 IDE 必须装配 Academy |

这取代旧设计中“Code 与 Work 都在启动时装配代码和文档编辑器”的目标。IDE 中已有文档贡献的退出属于后续实现，不把现有静态接线描述为新的产品要求，也不在本轮直接移除恢复路径。

## 先完善 Stanza 基础

Stanza 的完成标准按真实编辑行为判断，不以 Academy 的界面、论文功能或上游 API 数量判断：

- 文本、版本、事务和历史由同一权威模型维护；编辑、撤销和重做保持一致，结构扩展通过公开快照／版本边界提交。
- 每个编辑器实例独立拥有选区、光标、组合输入与视图状态；多个视图共享同一资源模型，关闭一个视图不销毁其他引用。
- 键盘、指针、输入法、剪贴板、文本几何与命中测试使用一致坐标和事务契约；输入热路径不等待后台分析。
- 保存、回退、外部冲突、备份和重启恢复沿共享工作副本与文件服务闭合；视图切换不能丢失未保存内容。
- 可选贡献停用、后台断连及旧异步结果失效不破坏基础编辑；大文件策略保留基础编辑、查找和保存。
- 键盘导航、无障碍帮助与文本视图沿既有客户端机制接入；相关产品文案使用 NLS，并验证非默认语言。

内核机制见[文本引擎](../../src/ash/editor/text-engine.md)，跨宿主链路见[编辑器架构](../editor-architecture.md)。已有验证范围与环境缺口由该架构文档及根 TODO 维护；本设计不将源码存在当作行为通过。

## Academy 入口候选

在 Agent Window 的 Activity Bar 增加 Academy 图标，并打开独立工作界面，是可选的产品入口。该方案便于用户回到文档与研究上下文，但入口形态仍待选定，当前不据此注册图标、命令或模式。

若采用，该界面使用现有 Sessions 布局契约：侧栏承载文档导航与大纲，EditorPart 承载文档 EditorPane，AuxiliaryBarPart 按需承载资料或属性，SessionsPart 承载关联 Agent 对话。具体内容取决于插件已有能力；文献库和 PDF 阅读仍由各自可选插件提供。

Sessions 的入口贡献只消费共享宿主已注册的 Academy 能力，沿既有菜单、布局描述和编辑器生命周期打开界面。它不静态导入 Academy 实现，不接管安装或授权，也不在通用布局服务中增加 Academy 专用判断。独立工作界面复用现有 Parts，不新建窗口 Grid、文档模型、撤销栈或会话服务。共享机制见 [Agents Window layout](../../src/ash/sessions/LAYOUT.md)。

## 所有权与生命周期

Stanza 保持每个 Renderer realm 内同一文档的一份权威 TextModel。Academy 的 DocumentTextModel 扩展该模型，持有富文档语义与结构事务；共享文档模型服务持有资源引用和工作副本。视图借用模型，后台只消费版本化快照或分析镜像。

插件的发现、安装、精确包授权、版本准入和资源加载由既有扩展体系负责。停用或撤权移除新路由并冻结已有视图，保留工作副本与未保存内容；重新启用后通过显式重开取得替代能力，不热切换编辑中的 Schema。文档格式和旧资源身份保持包契约中的兼容要求，不能因为改变产品入口就改写文件类型。

入口切换只改变现有 Parts 的内容、可见性与焦点。文档编辑和会话选择分别留在原 owner；不能因进入或离开 Academy 而丢失草稿、关闭脏文档、取消正在运行的 Turn 或复制聊天内容。实际关闭与退出继续遵循保存、放弃和取消流程。

收敛 IDE 旧接线前，须明确已有结构化资源、dirty 工作副本与备份的保留和恢复路径，并验证缺少 Academy 时的行为。目标宿主范围必须落实到产品装配及能力消费入口，不能只隐藏图标。通用桥、文件服务与 Code 的其他真实消费者继续保留。

## Agent 结构化文档编辑

Agent 结构化编辑是独立的后续能力，不作为本轮 Stanza 基础或 Activity Bar 入口的替代完成条件。请求经统一文档服务校验文档身份、模型版本／文件修订、权限与 Schema，再由 Academy 向同一模型提交一次可撤销事务。

当前普通文本快照和 WorkspaceEdit 链路不等于结构化编辑已经实现。须先闭合真实 producer、领域端口、打开／未打开资源的路由及审阅行为，拒绝过期请求；不能把已打开的结构化资源再次解析为第二份可写普通文本模型。

## 验证边界

Stanza 的基础改动先运行受影响模型、输入和宿主回归，并通过 Ash 自身验证实际编辑、保存与恢复。Academy 的能力加载另验收精确包、停用、重开、资源释放和 dirty 恢复，实际支持范围见[包说明](../../extensions/academic/README.md)。

后续宿主范围改动须证明：Agent Window 可消费已授权插件；IDE 不创建 Academy 产品入口或自动装配其能力；已有资源与备份有安全退出和恢复路径。入口方案选定后再验证选中状态、焦点、文档／会话保留及窄窗口行为。物理输入法、屏幕阅读器、多窗口／远端组合与目标 Word 往返不能由普通单测或静态文档替代。
