# Stanza 编辑器分部实施路线图

Stanza 底层保留**通用文本编辑内核**，Code 编辑器与 Academy 富文档编辑器通过扩展注入，其中 Academy 由独立 Rust 扩展提供。本文维护目标边界、迁移顺序、contrib 归属及历史行为验收范围。M0 静态边界审计已完成，见[审计清单](editor-boundary-audit.md)；2026-10-19 已迁出既有能力并完成基础入口收敛，Academy 继续改为已安装包的 Rust 进程与独立客户端资源，Code 保持产品预装扩展。Academy 的分发与授权边界见 [6.7](#67-贡献装配与市场扩展)，真实平台验收与 M6 新功能单独跟踪。不继续向默认 Schema、Widget 或 Editor bundle 添加 Code／Academy 业务能力。

当前待办及迁移交接见 [Stanza 编辑器 TODO](../../TODO.md#stanza-编辑器--todo)。已有实现见 [Editor 目录说明](../../src/ash/editor/README.md)、[文本内核](../../src/ash/editor/text-engine.md)、[现有富文档实现](../../src/ash/editor/document-engine.md)和[跨系统边界](../editor-architecture.md)；公开契约与既有路径记录见 [API 对齐台账](../../src/ash/editor/api-alignment-status.md)。当前迁移结果与平台验收范围如下；历史基线不替代实际运行证据。

[Work / Code 设计](work-code-workbench.md)记录现有工作台与普通文档流程：共享模型、共同编辑器注册、普通 `.ash-doc` 文档流程及旧 Academic 工作台模式退场已接入，Work 界面组合与 Agent 结构化文档修改仍未实施。本路线图在该基线上重新划分编辑能力的所有权，不改变已保存文件的身份或恢复规则。Academy 的能力接入从外置 Rust 扩展经共享扩展宿主注册开始，Sessions 消费已注册的能力；旧 Work／IDE 文档流程是迁移基线，不是要求新增 IDE Academy 适配的依据。

## 目标边界与依赖方向

文本内核提供内容、位置、事务、输入与视图的通用机制。Code 是在内核上装配代码编辑能力的一种组合，Academy 是装配富文档能力的另一种组合；两者都通过宿主装载的扩展接入。默认安装或默认启用不改变扩展的能力归属。

| 所有者              | 保留或提供的职责                                                                                                    | 接入边界                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 通用文本编辑内核    | 文本存储、稳定位置与范围、原子事务、版本、undo/redo、光标／选区、平台输入事件、基础文本视图及通用映射／生命周期机制 | 不认识具体语言、段落样式、表格、论文或 Word 页面；核心入口可以在未装载 Code 和 Academy 时独立编辑纯文本。          |
| Code 扩展           | 语法分词与高亮、语言配置、补全、悬停、诊断、折叠、导航、重命名、代码操作及代码编辑策略                              | 使用内核公开契约与宿主提供的语言服务；具体交互和业务规则由扩展内部 contrib 拥有。                                  |
| Academy 扩展        | 富文档 Schema、样式与结构语义、命令、输入策略、富文档视图、工具栏、表格／图片、分页、审阅及格式 codec               | 整条能力链由扩展提供；页面片段及其到模型位置的映射由扩展计算，通过通用契约接入。                                   |
| Sessions 产品消费层 | 产品入口、编辑器选择、菜单投影、布局／恢复及会话关联                                                                | 消费共享宿主已注册的编辑能力；不拥有 Academy 注册、装载或能力实现，也不预设专用 contrib；不新增 IDE Academy 接线。 |
| 共享宿主基础设施    | 扩展目录与启停、DI、EditorPart／Pane、资源引用、工作副本、保存、备份、恢复、冲突与协作连接                          | Sessions 复用现有 Workbench 下层领域服务；格式语义由能力包提供，不复制服务或反向依赖 Sessions。                    |
| Academic 论文配置   | Academy 内的论文结构、引用、文献、模板与投稿规则                                                                    | 复用 Academy 的富文档、样式、分页和输出，不在内核维护论文特判。                                                    |

能力接入方向为：**Academy 独立 Rust 扩展 → 公共 Rust SDK／Host RPC → 共享扩展宿主与通用编辑器桥 → Stanza 公开契约**。Sessions 经共享宿主服务消费注册结果，源码依赖仍遵守 **Sessions → Workbench → Editor**；Rust Provider 不链接进 App Server，通用桥不反向导入 Sessions。宿主装载已启用包并交付能力，内核只消费注册结果；内核及其基础 bundle 不导入具体扩展实现，也不通过全局服务定位器寻找指定扩展。Workbench 不反向导入 Sessions，Sessions core／services 不导入 Academy 实现；产品装配可以选择默认能力，通用承载层不根据包名硬编码功能。

Academy 不交付 IDE 模式下的新入口、菜单、布局或专门适配。Sessions 已复用的 Workbench 编辑器／文件／工作副本等服务继续由原 owner 提供，涉及格式语义时拆出后复用。Code 能力与 IDE 模式分别看待：Sessions 的 Chat／Cowork 输入、代码文件和 Changes 仍有真实消费者，不能因排除 IDE Academy 适配而整体移除这些依赖。既有 IDE 文档入口按消费者与持久恢复依赖有序退出，不在本轮删除。

扩展声明具体语义与校验规则，内核提供将扩展数据随内容原子提交、映射、快照和撤销的通用机制。同一资源保持唯一内容、版本、历史和工作副本；扩展不能再持有一份可独立保存的正文。现有 mark／atom／facet／region／relation store、结构事务与兼容树应按实际消费者逐项审计：真正通用的机制可保留，段落、表格、引用等具体解释与默认值归扩展，不能把整套富文档实现预先认定为内核。

基础文本视图负责通用文本几何。扩展可以提供自己的视图、布局和编辑策略，不必复用代码编辑器 DOM；例如 Enter 分段、Tab 切换单元格、分页与跨页选区规则属于 Academy，平台 IME 事件与通用事务提交仍沿内核／宿主机制。富文档布局计算出的几何、命中和选区映射须保持一致，但其算法不进入基础文本视图。

Academy 的运行边界如下：独立 Rust Provider 通过[公共 Rust SDK](../../sdk/rust/README.md)与 Host RPC 注册能力，拥有格式解释、转换及其他适合后端执行的领域计算；包同时提供与精确版本绑定的客户端视图资源和同步编辑策略。DOM、平台输入、即时选区、唯一正文、dirty、版本及撤销仍由 TS 客户端拥有，Rust 只接收契约允许的版本化快照／ID，返回带版本的结果或编辑提案，由客户端校验并原子提交。扩展拥有 Schema 等业务规则及其客户端实现，不能把它们改为 Sessions 内置实现，也不能在 Rust 保留第二份可写文档。同步输入和布局不强制每次跨进程往返。

共享宿主负责发现、授权、激活、注册投影和客户端资源装载；Sessions 通过同一注册结果选择编辑器和组织产品界面。现有 Markdown Rust 扩展提供了独立 Provider、静态客户端资源与通用自定义编辑器宿主的[可复用参照](../../extensions/markdown-language-features/README.md)，但其文本编辑契约不证明 Academy 的结构事务、分页或视图接入已经具备。M1／M2 须验证实际支持范围，客户端装载、版本匹配和隔离缺口沿[现有扩展体系](../editor-extensions.md)补齐；Web 运行 Rust Provider 需要授权后端。执行许可、权限和进程监管复用现有体系，不另建 Academy 专用安装器、协议或进程体系。

## 扩展与 contrib 归属

**扩展包拥有能力、版本和装载生命周期；contrib 是包内的功能组织单元。** 一个 Academy 包可以包含多个 contrib，不要求每个按钮或样式成为独立安装包。共享模块的提取由真实消费者决定，不提前建立没有调用方的 SDK、registry 或空适配层。

| 内容                             | 当前实现线索                                                                                 | 目标归属与处理                                                                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通用文本机制                     | `src/ash/editor/common`、`browser` 中的文本、输入与基础视图 owner                            | 保留实际共享机制；从默认 Schema、模型和 Widget 中移出具体语言／富文档规则。                                                                                          |
| 通用可选文本交互                 | 查找替换、多光标操作、Diff 等现有模块                                                        | 按真实复用关系形成可选贡献，由 Code／Academy 按需装配；纯算法与基础机制仍按其 owner 判断，不因多个产品使用就全部成为默认内核。                                       |
| Code 功能 contrib                | `src/ash/editor/contrib` 中的语言、补全、悬停、折叠、重命名等                                | 实现由 Code 能力扩展拥有，依行为链逐项迁移；保留必要的公开兼容契约，不把整个目录继续视作核心默认功能。                                                               |
| Academy 写作与结构 contrib       | `formatting`、`paragraphStyle`、`paragraphFormatting`、`academic`、`citation` 及现有文档命令 | 迁入 Academy 包内部，分别拥有字符格式、段落／样式、列表、表格、图片、引用等完整功能；Schema、命令和呈现一起迁移。                                                    |
| Academy 视图与输出 contrib       | `RichTextEditorWidget`、富文档样式、文档转换与后续布局                                       | 富文档视图、连续／分页布局、审阅、DOCX/PDF 实现由 Academy 拥有；宿主只提供通用挂载、资源与保存／导出调度。                                                           |
| Sessions／现有 Workbench contrib | Sessions 产品消费者；现有 `workbench/contrib/codeEditor`、`documentEditor`、`academic`       | 能力注册和注入迁向共享扩展宿主及通用编辑器桥；Sessions 消费产品入口，通用服务留原 owner，业务实现迁入包，保留 Code／共享消费者；不新增 IDE Academy 适配。            |
| 扩展包入口                       | 现有 `extensions/academic` 及 Code 相关包                                                    | Academy 包提供独立 Rust executable 和版本绑定的客户端资源，共享扩展宿主按启用／授权状态装载注册；文件关联是包声明的一部分，绑定硬编码内置 factory 不算实现已经外置。 |

注释应解释扩展与宿主的责任、状态与 DOM owner、事务和位置映射、版本／代次失效及释放边界。每个 contrib 保持功能内聚，底层公共契约不反向导入 contrib；不按文件行数拆分，不保留新旧两个功能 owner。目标目录和包拆分在真实调用链确定后落定，本文不预建新路径或承诺新的稳定 API。

## 当前基线与待迁移状态

Academy 的 [`ash-academy`](../../extensions/academic/README.md) 经公共 Rust SDK／Host RPC 注册 Academic、普通 `.ash-doc` 和频道笔记三种编辑器。[共享桥](../../src/ash/workbench/api/browser/mainThreadClientEditors.ts)按精确安装包、授权和运行代次投影注册；[装载器](../../src/ash/workbench/services/extensions/browser/extensionEditorModules.ts)读取同代资源、校验客户端与样式摘要及宿主 API 版本后装载独立模块。Academy 不再进入产品静态包目录、原生可执行文件清单或 Renderer 的模块 glob。旧的 Academic／普通文档／频道笔记静态 Schema factory 和默认文档贡献已退出。

富文档 Schema、结构事务／历史、命令、行投影、协作算法、codec、富文本 Widget 与段落贡献由 `extensions/academic/common`、`browser` 唯一拥有。Academy 的 `DocumentTextModel` 使用基础 `TextModel` 的通用扩展快照提交边界；基础模型不导入富文档结构或包实现。宿主保留文件、资源引用、dirty、备份和网络连接，使用 profile 提供的 codec／Widget／导入导出端口。停用冻结旧视图并保留工作副本；显式重开复用模型与历史。声明路由在停用时仍保护结构化文件，缺少运行能力时拒绝自动回退普通文本。

- Code 的既有 contrib、控件、命令与模型分析已迁入 `extensions/code`；独立 `ash-code-editor` Rust Provider 经 `editor.contributions.v1` 和共享桥提供客户端模块。`editor.all.ts` 保留基础文本命令，Provider 租约装配与退出可选行为。输入配对／缩进、Minimap 与缩进引导同样由包内策略／视图租约安装。基础入口的静态依赖闭包、真实 Rust 注入及 Chromium 组合回归已通过；Electron／远端与物理输入验收单独记录。
- Academy 现有连续正文、段落样式、基本格式、表格、图片、论文引用与保存／协作路径已经迁移。M6 的首版写作与样式现已补齐自定义段落／标题样式、局部覆盖、缩进、列表编号和富文档查找替换，并已闭合单栏正文分页；复杂页面结构、页眉页脚、脚注、打印／PDF 与 DOCX 往返仍单独推进。
- 旧的段落属性、命令和控件已随同迁入包内；各 profile 为自己的视图安装和释放控件。共享 SelectBox 的 active descendant 已修复，迁移验证以根 TODO 的实际运行日志为准。历史基线不替代新边界与平台验收。

Academy 仍以 Word 的文档工作流为目标：新建、写作、样式、对象、页面设置、审阅与输出，普通文章和论文使用同一扩展的富文档能力。现有 `academic`／`Academic` 名称继续标识已实现的论文配置；迁移须保留扩展 ID、内容类型、协作身份与旧文件兼容，确需更改时单独设计迁移，不恢复已退场的顶层工作台模式。

## 迁移顺序与阶段门禁

先迁移已有能力并证明外部注入，再恢复新功能开发。以下是实施依赖，后面的九部分用于定位职责，不是要求完成全部 Code 功能后才处理 Academy。

| 阶段                          | 迁移内容                                                                                                                                                       | 完成门禁                                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M0 边界与清单（静态审计完成） | [完整清单](editor-boundary-audit.md)覆盖 649 个 Editor 生产 TS／CSS 文件、全部 62 个 contrib 子项及 Sessions／Workbench／包／测试消费者；列出 A01–A22 混合职责 | 已明确目标 owner、迁移顺序、退出条件、Rust 扩展注入方向与 IDE 排除范围；客户端包运行等缺口留给 M1／M2，未宣称实现或运行时验收完成。                              |
| M1 最小内核与接入契约         | 从独立 Rust 扩展的实际注册／调用及基础文本行为确定必要端口；明确通用编辑器桥、包绑定的客户端资源、原子提交、codec、恢复与释放                                  | 明确基础文本行为与目标依赖闭包；端口由 M2 的真实 Code／Academy 消费者驱动，契约不包含具体业务字段。实现随切片闭合，整体验收在 M5 完成，不预建空 API 或重复内核。 |
| M2 两类外部注入切片           | 先选一个现有 Code 交互，再从 Academy Rust executable 经共享宿主注入编辑器，以段落能力验证 Schema → 命令 → 客户端视图 → 保存重开；Sessions 消费注册结果         | 启用后能力出现，停用／退出后注册及在途请求按契约退出；正文和未保存内容保持安全；无硬编码内置实现回退，无第二份模型或撤销历史。                                   |

| M4 Code contrib 逐项迁出      | 按补全／悬停、导航／引用、重命名／代码操作、格式化及其他交互分别迁移实现、资源和装配依赖                                                                       | 每个功能从扩展包走到可观察结果，并覆盖取消、旧版本结果、模型切换、错误与释放；共享可选文本贡献按真实调用复用。                                                   |
| M5 收敛内核与组合入口         | 在调用方、包注册、持久读取和测试转移后退出旧实现与默认导入；同步源码说明、台账、构建与打包依赖                                                                 | 基础文本、Code、Academy 注入三种编辑器组合及 Sessions 消费路径独立验收；基础入口不加载后两者的功能模块／资源，所有组合只有一个有效能力 owner。                   |
| M6 扩展内功能演进             | 迁移闭环验收后，继续 Academy 写作、分页、输出与审阅，以及各自 Code 功能                                                                                        | 新能力由所属扩展内部 contrib 实现，核心只补实际需要且语义通用的机制；不把业务重新写回内核。                                                                      |

## API 名称与契约怎么对齐

[API 对齐台账](../../src/ash/editor/api-alignment-status.md)仍有待处理项。同名声明、路径一致或类型检查通过都不等于行为对齐。VS Code 提供公开契约与可观察行为参照，不能据其内置 bundle 组织方式决定 Ash 的核心边界。迁移需核对名称、大小写、参数、返回类型、事件、取消、释放及真实消费者；不复制上游私有结构，也不创建无调用方的兼容转发层。

## 一次只做一个迁移切片

每项工作先写出：**用户动作 → 包装载／激活入口 → 宿主适配 → 内核公开契约 → 唯一状态与 DOM owner → 可观察结果 → 测试**。先读 Ash 的生产调用方和行为测试，再读对应的上游公开契约。对需要迁出的文件同时记录当前位置、目标 owner 和旧入口退出条件；按已经验证的切片迁移实现，保留无关的既有未提交改动。

一个切片完成须同时满足：

1. 功能实现、Schema／资源、注册、恢复读取和消费者已迁到唯一 owner；核心没有反向导入，也没有隐藏的旧内置回退。必要的公开兼容契约与行为得到保留。
2. 通过实际扩展包入口验证装载、启用／停用、失败、版本／代次切换、取消和释放。移动目录、静态 import 或声明式文件关联不能单独作为扩展化证据。
3. 内容、扩展语义、选区映射、版本、事务与 undo/redo 保持一致；同一资源的多视图共享一个工作副本。缺失扩展、格式不兼容及停用不能丢失持久内容或未保存修改。
4. owner 级单测和必要的真实浏览器／Electron 场景通过；涉及 UI 时覆盖键盘、焦点、无障碍帮助／文本视图、本地化、主题和高对比度。物理 IME 与屏幕阅读器结果按实际范围报告。
5. 受影响类型检查、正常构建、架构及依赖检查通过，并核对三种组合的装载集合。准确记录未解决失败，更新路线图、台账与 TODO，不削弱断言。

### 0. 入口与装配

建立不装载 Code／Academy 的基础文本入口，并通过宿主公开装载链组合两类扩展。分别核对调用方提供的模型与编辑器创建的模型由谁释放，注册与实例各由谁持有。`editor.all.ts` 现仅注册基础文本命令，具体 factory 从扩展注册；包的静态构建可以保留，但启用目录必须决定能力注册与激活，基础入口不直接 import 具体实现。

### 1. 通用文本内核

保留原子文本编辑、UTF-16 坐标、版本／快照、undo/redo、稳定位置与大文件预算，提供真实扩展所需的通用事务与数据映射。具体段落、样式、表格和论文 Schema／命令由 Academy 迁入包内；通用扩展数据参与同一次提交、版本和历史，验证失败不能留下半次提交。多个视图共享同一模型时保持各自视图状态隔离。

### 2. 选区与输入

内核归一平台键盘、指针、textarea／EditContext、IME 与剪贴板事件；Code／Academy 提供具体编辑意图与命令。分清通用输入处理和补全接受、代码缩进、段落拆分、列表退出、单元格导航等策略，验证组合取消、焦点切换、旧事件与扩展停用不会双写或写回旧模型。

### 3. 视图与几何

基础文本视图保留行布局、软换行、滚动、光标和通用挂载／映射机制。Code 的特定覆盖层、Minimap 等可选视图贡献由其组合装配；Academy 的富文档 DOM、段落／表格布局、连续或分页视图归 Academy。分别验证布局结果到内容位置的映射、命中、选区、IME 候选位置及释放，不把 Word 排版规则写入基础 `View`／ViewPart。

### 4. Code 语言与异步结果

将语言配置、分词、高亮、补全、诊断、折叠与符号沿现有调用链接入 Code 扩展，宿主继续提供实际语言服务和后端访问。统一核对 Provider 注册、文档版本、取消与过期结果拒绝。Worker、Rust 或 App Server 返回带身份和版本的结果，不拥有同步文本状态；语言算法和语法资源也按所属能力装载。

### 5. Code 与共享可选贡献

每个 contrib 以完整用户行为迁移：命令、交互、资源、状态、注册和释放一起转移。按补全／悬停、导航／引用、重命名／代码操作、格式化及其他功能推进；查找替换、多光标、Diff 等按真实消费者确定复用。依赖 Workbench 文件、账号或工作流的部分留在宿主适配，功能实现由扩展拥有。迁移不需要一次补齐所有 VS Code 文件或成员。

### 6. Academy：外部注入的 Word 式富文档编辑

#### 6.2 可编辑分页的最小闭环

Academy 的布局 contrib 提供 A4／Letter、页边距、单栏正文、缩放与自动分页。一个模型段落可对应多个页面片段，扩展提供片段到内容位置的双向映射，跨页拖选、方向键、删除、IME、剪贴板与撤销使用一致结果。纸张宽度决定正文换行，窗口宽度与缩放只改变显示比例或滚动。

自动页界、页数与几何属于扩展视图的派生状态；用户指定的纸张设置、手动分页和分节属于扩展的持久语义，通过事务保存。不能每页建立一个内容模型。布局绑定内容版本、样式、页面设置及字体／图片度量，迟到结果不能覆盖新版；增量重排、可见区域渲染和组合输入节点的维护由 Academy 视图负责。

第一条验收链为：**从 Academy 扩展入口新建多页正文 → 在跨页长段落的页边界输入中文 → 跨页选择并删除 → 撤销／重做 → 保存并重开**。检查正文、样式、模型位置、光标几何与页界，重排本身不增加内容版本或撤销记录；同时验证包退出／不兼容时的数据保留与恢复，平台 IME 和 Electron 按实际运行验收。

2026-10-19 正文分页实现位于 Academy 包内的 `pageLayout` 贡献。现以纵向页面堆叠显示 A4／Letter 单栏正文，统一页边距保存在根属性 `pageMargin`（18–144 磅，缺省 72），`pageSize` 为 `continuous`／`a4`／`letter`，旧文档缺省连续布局；Schema 在持久读取及事务提交时校验。纸张和页边距沿唯一模型保存、协作及撤销，50%–200% 缩放仅属于当前视图。

页面由包内视图测量浏览器实际行框，在页界插入不含文本且不可编辑的 DOM 空白；纸张、正文列与页间距均沿纵向排列。一个段落继续使用同一个编辑 DOM、文本 ID、字符格式与事件 owner，UTF-16 位置会遍历页界拆分后的 Text 节点，原生命中、正反向选区、剪贴板及事务恢复使用同一映射，没有每页正文副本或独立历史。字体／图片度量变化在当前 DOM 重排并恢复活动选区，重排不提交模型事务；组合输入期间不拆分／合并文本节点，提交或取消后再布局。纸张正文宽度固定，窗口和缩放不改变断行。

本轮验证和边界：macOS arm64 上经真实外置 Rust Provider、安装目录资源校验及客户端装载回归英中纵向页界点击、方向键、中文组合事件、复制／删除／粘贴、撤销重做、保存重开和停用恢复；高对比度验证真实鼠标跨页拖选、Letter／页边距、连续模式撤销、跨页查找滚动、段落字体与空段落逐字输入。几何断言检查页面纵向对齐、正文处于页边距内，度量变化不产生内容版本；反向选区、字体重排、组合取消及页内链接 owner 另有回归。38 条 Academy Chromium 场景、5 个模型／Pane／架构文件共 86 项、独立客户端包 3 项及正常 Renderer 构建通过。日志位于 `.build/academy-vertical-*.log`，截图与 trace 位于日志指向的 Playwright 结果目录。纵向堆叠已从本切片待办中移除；可见区域虚拟化及 6.3 的表格跨页／孤行等规则另推进。自动化组合事件不替代物理 IME、完整 Electron 或屏幕阅读器验收，根 TODO 的平台项继续保留。

#### 6.3 页面结构与复杂排版

在 6.2 的映射成立后，由 Academy 内部贡献依次提供：

1. 手动分页、分节、纸张方向与节级页边距，持久意图与自动页界分开。
2. 页眉页脚、页码、首页不同与奇偶页规则，重复显示引用所属节的内容，页码由布局派生。
3. 与下段同页、段中不分页、孤行控制、表格跨页、重复表头和行拆分；正文／表格稳定后再实现浮动对象、文字环绕与多栏。
4. 脚注／尾注、题注、编号、目录和交叉引用，注释及关系进入扩展语义，页码与脚注区域参与其布局。

#### 6.4 打印与 PDF

#### 6.5 DOCX 导入、导出与往返

#### 6.6 审阅与 Academic 论文工作流

批注、修订追踪、接受／拒绝及协作审阅由 Academy 的审阅 contrib 拥有，使用稳定内容位置与页面映射，明确持久语义、撤销与协作规则。现有协作连接及成员 UI 只是基线，不能作为 Word 式审阅已完成的证据；连接、凭证、房间和网络权限由宿主服务管理。

Academic 配置持续回归现有论文结构、引用和文献；公式、文献样式、模板与投稿规则复用 Academy 的样式、编号、布局和输出。普通文档保留自由正文入口，论文约束不进入内核或另造分页实现。

#### 6.7 贡献装配与市场扩展

Academy 的正式交付目标是从 Ash 扩展市场下载安装并按包装载、更新和卸载。源码位置不决定安装方式；默认推荐或默认安装也使用同一包管理生命周期。开发和离线场景可接入本地包，但不能另建 Academy 安装器或绕过来源、摘要、启用与执行授权检查。Rust Provider 与客户端资源属于同一精确版本，声明所需宿主契约及平台；升级扩展不要求重编 Ash，宿主不兼容时明确拒绝装载并保留文档。

源码仓库尚未决定迁移。目前建议继续在 Ash 的 `extensions/academic` 维护，便于在接入契约仍变化时同步实现和验证；契约稳定、确有独立发布需要后再迁到单独仓库。`extensions` 市场仓库按其现有职责维护目录、不可变版本产物、签名和撤销，不承接 Academy 日常源码开发或 Ash 安装器。是否迁仓不作为外置安装的前置条件，也不在多个仓库维护同一实现的可写副本。

Academy 包内部 contrib 负责功能分工，独立 Rust Provider 经共享宿主和通用编辑器桥提供能力。Sessions 只负责能力消费及产品入口、布局和会话关联，Workbench 下层继续提供已有共享基础设施；IDE 不新增 Academy 适配。Sessions 静态 contrib 不能成为能力注册或注入入口，也不预设需要新建 Academy 专用 contrib；内部 `registerEditorContribution` 不能直接当作市场作者接口。

### 8. 宿主与持久化

Sessions 产品适配与 Standalone 等宿主通过同一能力契约创建视图，宿主继续拥有 pane/input、资源引用、dirty/save/revert、冲突、备份与恢复；具体文档 codec 由扩展提供。扩展语义变化同批接入保存、恢复和兼容检查，多视图始终引用同一模型与工作副本。旧 `ash.document` 包络、内容类型、协作身份及文档资源的更名不得隐含在目录迁移中。

## 0.2 Workbench pane 切换文件（已验收）

用户在同一 pane 打开另一文件时，`CodeEditorPane.setInput` 获取新模型并创建新 part，随后释放旧 part 和旧模型引用。切换前焦点若仍在 pane 内，新 part 布局后恢复编辑焦点；焦点已移到外部时不抢回。`codeEditorPane.test.ts` 和 `textModel.integration.spec.ts` 验证旧模型、DOM、编辑器服务登记退出，新文件可直接接收键盘输入。此项验收的是 Workbench 输入切换，不代表同一 `CodeEditorWidget` 实例已支持 `setModel`。

## 0.3 Code/Academic bundle 与贡献释放（已验收）

Code 工作台入口共同装配行式与文档贡献，Academic 配置添加论文结构和引用能力。浏览器用例从真实 pane 验证按资源选择视图、贡献激活及销毁后 DOM 退出。Academic 工具栏的监听随贡献释放；协作成员列表重绘时旧按钮监听立即释放，销毁后的异步结果不能再写回 DOM。`collaborationContribution.test.ts`、`formattingContribution.test.ts` 与 Code/Academic 浏览器用例覆盖这些行为。

## 0.4 同一 Widget 切换模型（行为已验收）

调用 `setModel` 时，`CodeEditorWidget` 保持对象、注册表身份和根 DOM，按模型释放旧 worker、ViewModel、View、输入与贡献，再装配新模型。切换前聚焦的编辑器在新模型挂接后恢复焦点；内容、光标、模型和装饰事件只读取当前模型。外部 Widget 与装饰集合句柄保留，旧模型上的装饰清除；空模型与外部销毁模型都释放旧视图并允许再次挂接。Standalone 在切走隐式模型时释放它，外部传入的模型始终由调用方持有。`CodeEditorWidget`、Standalone、Observable owner 级测试及 Chromium 公开入口用例覆盖输入、共享模型隔离、事件顺序、失败后的空状态、资源与销毁。Widget 的其余公开 API 差异仍按各自用户行为分部留在对齐台账，不计作本项完成。

## 1.1 原子编辑与 UTF-16 坐标（已验收）

调用公开编辑器的 `executeEdits` 时，`TextModel` 先把编辑范围约束到文档和完整的 UTF-16 字符边界，再检查整批范围是否重叠。两个各占半个代理对的相邻编辑会被判为重叠，整批拒绝且文本、版本、历史和内容事件保持不变；单个跨行编辑则扩展到完整字符后一次提交。公开 offset/position 转换保留 UTF-16 码元位置，并约束越界输入。模型、Piece Tree 测试和真实 Chromium 用例覆盖这些边界；两个编辑器共享同一模型时，拒绝和提交的结果在两个视图中一致。

## 1.2 版本与快照（已验收）

调用公开编辑器或模型的 `setValue`，即使写入内容相同，也会清空旧历史、推进模型版本并发布一次重置事件。旧版本的异步语言请求因此失效；已经创建的顺序快照和版本化快照仍可在后续编辑、重置或模型释放后读取原内容。已释放模型拒绝写入时不会消费传入的快照。模型测试覆盖版本、事件、请求失效、BOM 和快照生命周期；真实 Chromium 用例确认共享模型的两个编辑器保持相同内容，且公开入口产生新版本。

## 1.3 Undo/redo 与选区映射（已验收）

一个模型事务保存编辑前后的选区，键盘撤销与重做分别恢复原选区和结果选区，包括多光标及反向选择。空编辑或校验失败不关闭正在合并的撤销组，随后连续输入仍一次撤销。两个 Standalone 编辑器共享模型时，发起编辑者保持焦点并恢复自己的选区，另一编辑器保留独立选区；Code Action 菜单仅在自身拥有焦点时把焦点还给所属输入节点。模型历史测试和真实 Chromium 用例覆盖文本、版本、DOM、焦点、Escape 与菜单因内容变化关闭。

## 1.4 稳定行身份与文档语义（已验收）

行点转换以行 ID 找到对应的物理行，再按该行长度校验 UTF-16 offset；负数和非整数行索引直接拒绝。拆行或重置先在 `TextModel` 中计算并校验全部新行 ID，生成器失败时不修改文本、版本、历史或事件，也不占用已预留的 ID。成功提交后，未受影响行的 ID 保持不变，撤销和重做恢复对应身份。结构文档仍由同一个模型提交事务，其代码行 ID、区域和语言属性随事务保持对应；模型测试与两个共享模型的 Chromium 编辑器用例验证这些行为。

## 1.5 超大文件预算（已验收）

`ModelService` 从现有 `editor.largeFileOptimizations` 设置取得创建选项，`TextModel` 只在创建时按文本长度和行数决定分词、同步与整份读取预算；改设置不会中途重建已打开模型的策略。关闭优化只移除分词和堆操作门槛，同步上限始终生效。超出堆预算时 `getValue`、`getText` 和 `getLinesContent` 拒绝整份物化，顺序快照仍可分块读取。模型服务、预算边界和堆读取测试，以及真实 Chromium 中两个编辑器共享约 20 MiB 模型的用例覆盖这条链。第 1 部分的逐项行为已验收，整个 Editor 仍按后续分部继续验收。

## 2.1 键盘导航与编辑（已验收）

键盘事件先交给补全等输入消费者决定是否处理，再发布公共按键事件；已处理事件不再进入光标导航。补全打开时，方向键只切换建议项和 ARIA 活动项，编辑器光标保持不变，Enter 只提交选中的补全。普通输入下，Shift 扩选、Backspace、撤销、方向键与字符输入依次由当前编辑器选区和模型事务处理，不发生双写。Widget owner 测试与真实 Chromium 用例覆盖这两条链；下一项是指针与拖动。

2026-09-15 补全会话与片段导航已迁入浏览器层并通过 `ICodeEditor` 操作。Tab/Shift+Tab 切换占位符结束当前输入的撤销组，真实 Chromium 验证两个占位符编辑、离开片段及撤销。只读接受、选项修改与模型切换后迟到结果由真实 Widget 单测覆盖；完整 Suggest/Snippet API 仍在对齐台账中待验收。

片段选项切换将所有镜像和转换结果作为一次编辑提交，撤销、重做后按当前文本继续切换。真实 Chromium 覆盖转换结果位于两个镜像之间及位于源占位符之前的键盘操作。首次展开在声明解析完成后计算镜像、转换文本和最终范围，覆盖后置默认值、选项和嵌套转换；嵌套片段保留选项列表，前置镜像同样参与选项切换。

## 2.2 指针与拖动（已验收）

鼠标手势由 `pointerdown` 保留 pointer ID，再用 `mousedown.detail` 判断单击、双击和三击；触控与笔仍从 `pointerdown` 进入同一选择链。真实双击选中完整单词，跨行拖动只改变当前编辑器选区，不修改共享模型或另一个编辑器的选区。`pointerup` 结束指针会话后，兼容 `mouseup` 不再重复发布公开事件；若缺少 `pointerup`，`mouseup` 仍结束手势。松开后移动指针不会继续扩选。PointerHandler、Widget owner 测试和 Chromium 用例覆盖这些行为。

## 2.3 多光标（已验收）

在真实编辑器中用 Alt 点选添加第二光标，再点同一位置会移除它；重新加入后一次键入在两行各插入一个字符，只产生一个模型版本和一次可撤销事务。光标集合属于当前编辑器，另一个共享模型的编辑器保持自己的单光标。`CursorsController` owner 测试覆盖事务、结果选区和撤销，Chromium 用例覆盖点选、切换、输入与共享模型隔离。

## 2.4 Textarea 与 EditContext（已验收）

同一 Standalone 用户动作分别经 textarea 和 EditContext 输入节点：在行中按 Enter 只提交一个模型版本，撤销恢复文本和选区。焦点转移到另一个编辑器后，旧节点迟到的文本更新、不可取消的 textarea 输入与撤销键均不能写回旧模型或抢回焦点；EditContext 会把浏览器文本窗口恢复到模型状态。Widget owner 测试和两组独立 Chromium 用例覆盖正常输入与失焦边界。下一项是 IME。

## 2.5 IME 浏览器事件链（已验收）

Textarea 和 EditContext 的候选文本连续改写各提交可观察的临时版本，结束组合后只占一个撤销步骤；撤销恢复初始文本和选区。组合期间按 Escape 或把焦点移到另一个编辑器时，临时文本和选区回到组合前，装饰与组合态清除；旧输入节点迟到的 `compositionstart/update/end` 不会重启组合、写入旧模型或抢回焦点。输入 owner 测试与六个 Chromium 用例覆盖提交、取消和失焦边界。这些用例在浏览器中合成组合事件；系统输入法候选窗口和 Electron 行为仍需平台验收。下一项是剪贴板。

## 2.6 剪贴板（已验收）

Textarea 与 EditContext 都由当前输入节点处理复制、剪切和粘贴：复制保留选区文本与编辑器元数据，剪切和粘贴各提交一次可撤销事务；焦点移走后旧节点的剪贴板事件不再读取旧选区或改写旧模型。Web EditContext 不会由浏览器默认发出键盘复制事件，因此同路径 `clipboard.ts` 的标准贡献把该节点的复制、剪切和粘贴快捷键送入现有剪贴板操作；旧 capability 注册不再进入 Code bundle。浏览器报告 `execCommand('cut')` 成功却未发出事件时，命令仍会写入系统剪贴板后删除选区。命令式粘贴等待读取、剪切等待写入时，会在提交前重新核对焦点、模型身份、版本和选区；任何一项变化就放弃该次编辑。命令 owner 测试、四个 DOM 事件用例和两个真实键盘/浏览器剪贴板 Chromium 用例覆盖这些行为；第 2 部分仍保留 2.5 所述系统输入法平台验收。

## 3.1 行布局与软换行（已验收）

同一 Standalone 模型行在窄视口中投影成多个视图行；调整宽度或增量修改文本后，可见行数、内容高度和 DOM 行一起更新，点击续行仍回到正确的模型列，模型行数与版本不会因布局改变。非等宽字体的 DOM 测量现在优先在正文后的空格处断行，`wordBreak: keepAll` 尽量把连续 CJK 文本移到下一行；一整段放不下时仍在字素边界强制断行。投影 owner 测试与两个 Chromium 用例覆盖这些行为。下一项是可见行复用。

## 3.2 可见行复用（已验收）

滚动时 `ViewLayer` 只移除离开视口的文本行与覆盖行，并插入新进入的行；重叠行保持同一个 DOM 节点且整个过程中不脱离文档。增量修改可见文本会更新该行内容而保留行根，旧行离开视口后断开，编辑器释放时当前可见行也全部断开。80 行模型、80px 视口的 Chromium 用例通过 DOM 身份、`MutationObserver`、内容、版本和释放状态验证这条链。下一项是光标和 gutter。

## 3.3 光标与 gutter（已验收）

一个模型行折成多条视图行时，行号只在首行出现，glyph marker 固定于对应模型行的起点，光标按当前模型列落在正确续行。相对行号以模型行而非视图行计算；光标移到下一模型行或首行内容缩短后，光标、行号和 marker 沿同一纵向布局更新，单纯移动光标不改变模型版本。Chromium 用例与既有光标、行号、glyph owner 测试覆盖这条链，本项不需要修改三个 Part 的生产实现。下一项是装饰与 View Zone。

## 3.4 装饰与 View Zone（已验收）

2026-09-15 修复 View Zone 拒绝零高度的问题：`heightInPx: 0` 和 `heightInLines: 0` 都允许创建收起的区域，并通过 `layoutZone` 展开、移动和再次收起。区域沿用同一 DOM 节点，margin 同步隐藏与展开；空白区变化不修改文本版本。块装饰包含相邻区域的空白，区域展开时块装饰增高、文本光标下移，区域移到当前行之后时光标回到原位置。两个 Standalone 回归用例覆盖这条链及删除后的节点退出。

同日补充修复折叠行坐标转换：隐藏行的列号不再用于折叠标题的换行计算，而是定位到已保留的标题末尾。此前 `showInHiddenAreas: true` 的区域在三条显示行的标题折叠后会错误插在第一条之后（20px），现在位于标题末尾（60px）。两条坐标回归测试覆盖短、长隐藏行以及换行开启与未发生换行的情况；Standalone 用例覆盖真实折叠按钮、滚动、展开、文本版本不变和节点释放。

同日补充修复区域回调丢失 `this`：`onComputedHeight` 和 `onDomNodeTop` 都绑定到传入的区域对象。Standalone 用对象方法读写区域 DOM，验证零高度展开、折叠隐藏、展开恢复、滚动后的高度与位置通知、模型版本不变及节点释放。

2026-10-18 补齐交叉场景，生产实现未改动。`standalone.integration.spec.ts` 新增两例，分别验证隐藏行中的区域保留与隐藏：标题由三条软换行改成五条时，行内装饰仍对应原模型列；折叠体装饰退出，块装饰高度包含当前可见文本与区域空白。滚动后块装饰与 body／margin 区域使用同一几何，滚出视口后装饰退出，返回时区域保留原 DOM；折叠期间收起／展开区域、再展开折叠和恢复换行列数后，高度与位置恢复，文本版本不变，移除与销毁释放节点并保留输入焦点。
