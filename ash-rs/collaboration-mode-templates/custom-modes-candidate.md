# 自定义模式候选

状态：候选，暂不实现，也未安排实施。当前产品仍只支持 Agent、Plan、Debug、Multitask、Ask 五种内置模式，使用 `CollaborationMode` 强类型表示。本文用于评估自定义模式是否值得加入；不表示已有模式目录接口或自定义模式配置。

## 候选目标

让用户保存可重复使用的任务处理方式，例如代码审查、故障调查或文档整理。桌面端和 TUI 使用同一份模式定义，命令、请求和历史通过稳定 ID 标识模式；改名、翻译或更换颜色不改变模式身份。

自定义模式与 Role、模型、推理强度、权限策略分别选择。模式定义任务的处理方式，Role 定义 Agent 的职责和能力上限，权限策略决定具体动作能否执行。

## 身份与定义

候选设计采用 `ModeId` 与模式定义目录。内置模式保留 `agent`、`plan`、`debug`、`multitask`、`ask` 五个 ID；自定义 ID 带来源命名空间，创建后保持不变，避免不同来源覆盖同一个模式。显示名称可以修改，也可以本地化。

| 内容 | 候选职责 |
| --- | --- |
| `ModeId` | 命令、请求、队列和历史中的稳定身份 |
| 模式定义 | ID、名称、说明、明确的内置行为类型、指令正文和修订版本 |
| 内置行为类型 | 保留五种模式的强类型执行规则，供自定义模式明确选择 |
| 模式目录 | 由后端解析、校验并提供可用定义，供各客户端读取 |
| 内置名称的本地化、颜色、显示顺序、快捷键 | 由各端的本地化、主题和 UX 设置负责；使用 ID 关联 |

内置模式通过 ID 使用各端的语言词条；自定义模式显示定义中的用户名称。颜色由各端主题按 ID 关联，不把终端或桌面端的颜色值写入共享执行定义。

模式 ID 与提示词资产 ID 分别记录。模式 ID 表示用户选择了哪种处理方式；资产的 owner、ID 和 revision 表示这次实际使用了哪份指令。

## 行为与权限

自定义模式选择一种内置行为类型，再提供该模式的任务指令。只读要求、工作流入口、Goal 续接和子任务继承等执行规则，由后端根据明确的行为类型处理。指令正文不能自行声明新的执行类型，也不能扩大 Role 或权限策略授予的能力。

例如，“代码审查”可以选择 Ask 行为并附加审查重点；“故障调查”可以选择 Debug 行为并附加证据要求。名称和正文不会成为判断是否允许修改、是否自动续接或如何委托的依据。

本 crate 继续负责内置模式指令资产。用户定义的读取、校验和保存归共享后端的模式领域所有；App Server 提供访问入口。协议定义身份和请求结构，客户端负责选择与显示。具体文件归属需要在实施时按真实调用方确定，不提前创建模块或接口。

## 接受、恢复与修改

接受一条消息时，后端解析模式 ID，并保存 ID、定义修订版本、已解析的行为类型和完整指令。持久队列也在接受时保存这些内容，交付时使用已接受的定义。

更改或删除模式只影响后续提交；已经接受的 Turn、排队消息、恢复和重试沿用保存的定义。同一命令的重试仍需检查已接受内容是否一致。新的请求引用不存在或不可用的 ID 时返回明确错误，界面让用户重新选择。

子任务的行为继承继续由后端决定。自定义模式还需要明确哪些附加指令适用于子执行者，避免把协调者要求直接带给每个子任务。

## 采用前需要决定与验证

- 定义的保存范围：用户、项目或共享来源；不同来源的访问、重名和删除规则。
- 自定义模式附加指令如何继承到子任务，以及协调模式如何指定子执行者的模式。
- 内置名称的本地化、自定义名称的显示、模式颜色和用户排序如何与各端设置结合。
- 模式目录、错误与更新通知的正式协议，以及已有五种模式记录的读取约定。
- 普通发送、排队、跨模式追加、恢复、重试、分支、委托和 Goal 的端到端覆盖。

现有行为约定见 [五种模式](../docs/collaboration-modes.md)。只有自定义模式进入明确的产品需求后，才实现本文涉及的目录、保存和协议能力。
