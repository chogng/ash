# Ash 受管网络代理规划

本文规划沙箱内命令的出站网络能力，所有者是 `ash-rs/network-proxy`。参考的是本机 `../codex` 仓库提交 `872fc22f9c41c3ba7f9fcc5dd8630b880ee713b8` 中的 `codex-rs/network-proxy`，按 Ash 已有的执行、审批和沙箱边界选择能力，不逐文件移植。

产品模型 API key 由受信任的 App Server 通过 `ash-model-provider` 和 profile SecretStore 管理，模型 HTTP 与 WebSocket 请求由模型调用链发送；[凭据边界](../../docs/secrets.md#12-模型-api-key-的进程边界)记录了这项选择。网络代理只处理沙箱内命令的流量。代理支持 WebSocket 不能算作 Responses WebSocket、Realtime 或 Live 模型调用的验收。

## 现状与参考边界

| 能力 | Ash 当前状态 | Codex 参考实现 | 本方案的判断 |
| --- | --- | --- | --- |
| 命令网络出口 | 每次受管执行创建 HTTP/CONNECT、SOCKS5 TCP 代理；审批前不连接目标；检查并固定 DNS 结果；命令结束即关闭代理 | HTTP、SOCKS5、执行范围和目标策略 | 保留 `ash-network-proxy` 为唯一命令代理实现 |
| 代理入口归属 | 本次命令有独立回环端口，但端口本身不能证明连接来自该命令 | Linux 的受信任桥接有归属标记；Windows 根据连接进程的限制 SID 选择路由 | 先证明并实施 Ash 的执行归属，再扩大代理可获得的权限 |
| 审批 | `app-server` 把执行、目标、协议和策略版本交给现有动作审批 | 代理调用宿主策略决策器 | 规则、批准记录和用户交互仍由 `action-policy`、Core 与 `app-server` 持有 |
| WebSocket | `wss://` 可通过已批准的 CONNECT 作为不透明字节流；HTTP 正向代理拒绝 Upgrade | 对已配置的可检查隧道保留 HTTP Upgrade，升级后转发字节 | 先补命令流量的 `ws://` Upgrade；不把目标级 CONNECT 审批描述成路径级检查 |
| HTTPS 方法和路径 | CONNECT 只看目标，不能判断隧道内的方法或路径 | 按需要终止 TLS，执行受限模式和凭据替换 | 只有产品确实需要方法或路径规则时才加入 TLS 检查；未检查的隧道不能满足这类规则 |
| 命令凭据 | 不替换子进程环境或请求中的密钥 | 凭据代理把子进程环境中的真实值换为占位值，再按目标绑定注入请求 | 作为独立需求设计；代理只持有执行期间的受限绑定，不持久保存凭据，也不自动取得模型 API key |
| 平台 | macOS 与 Linux 有受管执行路径；Windows 严格受管网络明确拒绝 | 有远端执行配置及 Windows 代理入口处理 | 本轮只规划并验证 macOS；Linux、Windows 保留单独的实机门槛 |

Ash 当前行为以[代理 README](../network-proxy/README.md)和实现为准。Codex 的凭据代理从受信任的父进程环境发现凭据，在子进程环境中放入占位值；Ash 若加入工具凭据替换，也必须由凭据所属领域批准具体用途，不能让命令代理读取产品模型 key。

## 职责与依赖方向

| 所有者 | 职责 |
| --- | --- |
| `exec-server` | 为一次命令创建并持有代理，准备子进程代理环境，命令结束或取消时结束代理 |
| `network-proxy` | 解析 HTTP、CONNECT、SOCKS5 和将来明确支持的 Upgrade；取得真实目标、检查解析地址、请求审批、连接上游并管理连接生命周期 |
| `action-policy`、Core、`app-server` | 规则优先级、执行身份、单次审批、审查交互和策略版本；代理不得自行保存长期批准 |
| `sandboxing`、`mxc-sandbox` | 禁止命令直连网络，仅开放本次代理端点；不能实施该限制时拒绝受管执行 |
| 凭据所属领域 | 按各领域契约持久保存、录入、轮换和删除；产品模型 API key 由 App Server 与 `model-provider` 管理 |
| `model-provider`、`ash-api` | 产品模型协议、模型 API key 鉴权与请求；不经由命令代理来取得工具网络审批 |

`ash-network-proxy` 已用 `server` feature 隔离监听依赖。本方案不为代理再建同义 crate。将来加入 TLS 检查时，若会让只使用授权接口的 crate 编译 TLS 和证书栈，再按能力与依赖隔离拆出具体实现；先有调用契约，再决定 crate 边界。

## 实施顺序

### 1. 代理入口归属

现有审批把执行 ID 写入请求摘要，但代理尚不能由回环 TCP 连接证明发起者属于该执行。同一系统用户的其他进程若能访问端口，可能借用该执行的审批。先核对 MXC 能否提供受保护的代理入口或经过系统核实的连接发起进程身份；若仍只能使用普通 TCP 回环端口，不能把端口号或子进程可读的令牌当成进程身份。以同用户其他进程尝试连接并触发审批作为验收用例。解决入口归属之前，不向命令代理交付真实凭据。

Codex 的 Linux 归属标记由受信任的桥接写入，Windows 使用系统令牌中的限制 SID；这两条路径都不能直接证明 Ash 当前 macOS 回环端口已具备身份边界。

### 2. 命令 WebSocket 传输

在 macOS 的受管命令路径补 `ws://` HTTP/1 Upgrade：代理先按真实主机、端口和握手方法取得本次执行的决定；只接受合法的 Upgrade 握手，转发上游确认的 `101` 与选定协议，随后双向转发字节。断开、取消、执行结束均关闭两端。`wss://` 继续按 CONNECT 目标批准；除非启用明确的 TLS 检查，不声称代理看见其中的 URL 路径、握手标头或消息。

此步不改变产品模型的 Responses、Realtime、Live 协议实现，也不把 API key 放入命令环境。普通 HTTP、CONNECT、SOCKS5 的既有授权和 DNS 固定规则仍适用。

### 3. 需要内容规则时建立可检查的 HTTPS 路径

若需要像 Codex 的受限模式那样根据 HTTPS 方法、路径或握手标头决定，必须由代理终止本次 TLS、校验目标与上游证书，并向命令提供仅本次执行有效的信任材料。代理在读取请求内容后再次按真实目标及方法求授权；无法检查的加密或其他不透明隧道直接拒绝该类请求。证书私钥只属于代理的执行生命周期，不进入命令、配置、日志或持久文件。

这项能力必须先证明沙箱禁止直连、代理入口可核实本次执行，并覆盖同用户其他进程试图调用代理的场景。没有这些证据，不开启内容检查或凭据替换。

### 4. 确有工具凭据需求时加入受限替换

凭据所属领域批准具体执行、目标、可用协议和版本后，向代理交付短期绑定；子进程只看到占位值。代理在目标与请求路径均匹配、上游 TLS 已验证、且本次执行仍有效时加入鉴权。重定向、目标变化、凭据轮换和执行取消都重新检查或终止请求。代理不扫描旧 profile key，不自行发起系统身份确认，也不将产品模型 API key 自动提供给工具。

Codex 的环境变量发现与替换可作为机制参考，不能直接作为 Ash 的凭据授权。Ash 先定义实际工具凭据来源及使用场景；在此之前不增加凭据注册表、持久存储或新的公共接口。

### 5. 平台验收

macOS 先验证命令网络出口与新增协议。Linux GNU/musl 的沙箱网络隔离、共享端口、DNS、取消及代理入口在测试机实测后才能标为完成。Windows x64/ARM64 需要先解决 PSEC 的代理身份和入站约束，再验证受管流量；当前明确拒绝保持为真实状态。任何平台都不能通过开放直连来换取代理测试成功。

## 验收门槛

1. 受管命令无法绕过代理直连；代理拒绝其他执行或进程冒用本次端点。记录入口归属的系统依据，不能以端口唯一或执行 ID 写入日志替代身份检查。规则拒绝时，DNS 与上游连接均不发生；解析后的地址不能跳过原目标授权。
2. `ws://` 的成功、拒绝、无效 Upgrade、上游 `101`、双向数据、断线和取消都在真实受管命令中验证；`wss://` 的 CONNECT 只按目标授权，不宣称已检查内部路径。
3. 若实现 TLS 内容检查，验证未受信任证书、目标变化、不可检查隧道、证书材料回收、并发执行隔离和日志脱敏；任何不能执行方法规则的路径明确拒绝。
4. 若实现工具凭据替换，验证子进程与普通代理响应不含真实值，非目标站点与其他执行无法取得鉴权，轮换或删除使旧连接失效。产品模型 key 的验收另见[凭据边界](../../docs/secrets.md#12-模型-api-key-的进程边界)。
5. 分别记录 macOS、Linux、Windows 的构建目标、系统版本、真实沙箱结果和未通过项。编译、单测和普通回环代理测试不能代替平台隔离验收。
